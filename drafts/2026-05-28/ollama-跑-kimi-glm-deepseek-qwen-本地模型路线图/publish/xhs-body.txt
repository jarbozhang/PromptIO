Ollama 在 GitHub Trending 上的价值，不是又一个开源项目冲上榜。它更像是把本地模型这件事从“配环境”拉回到“选模型”。

仓库描述直接写着，可以跑 Kimi-K2.5、GLM-5、MiniMax、DeepSeek、gpt-oss、Qwen、Gemma 等模型。当前来源记录里，它是 Go 项目，172464 stars，16309 forks，创建于 2023-06-26，最近一次 push 是 2026-05-27。

但新手最容易误会的是，Ollama 不是把所有大模型都塞进你电脑里。Ollama Library 里有本地可拉取的尺寸，也有带 `cloud` 标签的模型。这个区别决定了你该从哪条路开始。

本文为 AI 辅助整理，关键事实已按 Ollama GitHub 仓库和 Ollama Library 页面核对。

## 先别追模型名，先看标签

看到 Kimi、GLM、DeepSeek、Qwen 放在一起，第一反应可能是“那我是不是都能本地跑”。更稳的看法是，Ollama 给了统一入口，但不同模型的运行方式不一样。

Kimi-K2.5 页面给出的命令是 `ollama run kimi-k2.5:cloud`，页面标了 vision、tools、thinking、cloud，context 是 256K tokens，size 是 1.04T parameters。

GLM-5 页面给出的命令是 `ollama run glm-5:cloud`，标签是 tools、thinking、cloud，context 是 198K tokens，页面说明它来自 Z.ai，用于复杂推理、代码和 agentic tasks。

这两类模型适合理解为“通过 Ollama 接入的大模型能力”。如果你的目标是离线、数据不出本机、在低配置机器上自己折腾，它们不是第一站。

第一站更该放在 DeepSeek-R1 和 Qwen3 这类有明确本地尺寸梯度的模型上。

## 一条命令，只解决启动问题

Ollama README 给的安装路径很直接。macOS 和 Linux 示例是 `curl -fsSL https://ollama.com/install.sh | sh`，Windows 示例是 `irm https://ollama.com/install.ps1 | iex`。装好后，仓库 README 里的基础动作是运行 `ollama`，再跑模型，例如 `ollama run gemma3`。

放到这篇的主题里，新手可以从两条命令试起。

`ollama run qwen3`

`ollama run deepseek-r1`

这不是“性能路线图”，只是启动路线图。真正影响体验的是你选哪个 tag。

## 低配置机器，别从旗舰开始

Qwen3 的模型页把尺寸列得很清楚。`qwen3:0.6b` 是 523MB，`qwen3:1.7b` 是 1.4GB，`qwen3:4b` 是 2.5GB，`qwen3:8b` 是 5.2GB，后面还有 14B、30B、32B、235B。

DeepSeek-R1 也有类似梯度。`deepseek-r1:1.5b` 是 1.1GB，`deepseek-r1:7b` 是 4.7GB，`deepseek-r1:8b` 是 5.2GB，`deepseek-r1:14b` 是 9.0GB，32B 是 20GB，70B 是 43GB，671B 是 404GB。

这组数字给新手的真正提示不是“越大越好”，而是先把任务缩小。低配机器可以先跑 Qwen3 0.6B 或 DeepSeek-R1 1.5B，确认流程、提示词和文件输入方式。能接受更慢、更重，再升到 4B、7B、8B。

如果你的目标是中文问答、轻量改写、代码片段解释，Qwen3 4B 或 8B 是更稳的起点。如果目标是推理类问题，可以试 DeepSeek-R1 的小尺寸蒸馏模型。需要长上下文和复杂工程任务时，再考虑 14B、30B 以上，或者承认这类任务更吃机器。

这里不要把模型页面的 context window 当成“低配也能顺滑跑满”。上下文越长，显存、内存、等待时间都会变成实际约束。页面大小也不是最终运行成本，只能当选择入口。

## 哪些事值得放本地做

本地模型最适合三类任务。

一类是隐私敏感但难度不高的文本活。比如会议纪要改写、内部文档摘要、提示词初稿、代码片段解释。它们不一定需要最强模型，但需要你愿意把材料放进模型上下文。

第二类是高频小任务。每天都要问、反复改、格式固定的东西，放本地可以减少工具切换，也方便接到脚本、编辑器和个人工作流里。Ollama README 里也列了 REST API、Python、JavaScript 用法，这说明它不只是聊天窗口，能被应用调用。

第三类是学习和评估。新手真正要学的不是“哪个模型最强”，而是同一个提示词在 Qwen3、DeepSeek-R1、Gemma 上会怎么变。Ollama 的好处是把换模型的摩擦降到很低。

不适合本地模型的任务也要说清楚。最新事实核查、高风险决策、长篇复杂代码修改、需要稳定工具调用的 agent 流程，都不该只靠小模型闭门完成。可以本地起草，本地拆解，但最终结果要有人工核对或更强模型复核。

## 我的判断

Ollama 这次值得中国 AI 用户关注，不是因为它让所有模型都“本地化”了，而是它把模型选择变成了一个可操作的菜单。

Kimi-K2.5 和 GLM-5 这类 `cloud` 模型，像是把高端能力接进 Ollama 的统一入口。Qwen3 和 DeepSeek-R1 这类有小尺寸、本地 tag 的模型，才是低配置用户开始搭工作流的入口。

所以新手路线可以很朴素。先用 `qwen3:0.6b` 或 `deepseek-r1:1.5b` 确认机器和流程，再用 4B 到 8B 做日常文本和代码辅助，等任务真的需要复杂推理，再评估 14B 以上或者 `cloud` 模型。

不要一上来追旗舰。能长期留在桌面上的本地模型，往往不是参数最大的那个，而是你愿意每天打开的那个。
