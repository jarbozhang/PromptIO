# 100 万美元 Token 实验后的反常识结论：AI 用得越多，团队未必越快

一个 20 多人的团队拿到 100 万美元预算，开始了一场 Token 近乎不限量的激进实验。管理者原本想验证 AI 能把交付速度推到多高，最后看到的却是另一幅画面，成员更累、审查堆积、项目细节失焦。

这件事对团队负责人最有价值的提醒，不是应该少用 AI，而是不能再用 Token 消耗量和任务数量判断提效。真正该核算的，是一项需求从提出到可信交付，究竟占用了多少人类注意力。

如果团队已经同时运行多个 Agent，会频繁切换会话，或者发现产出明显增加但交付没有同步加快，可以沿着这次实验暴露的链条重新检查指标。

## 当五个并行会话占满一个人的注意力

实验中，成员等待推理时通常会同时打开多个会话，中位数约为 5 个。并行看起来消除了等待，实际上把等待时间改造成了上下文切换。

每个会话都有自己的目标、假设、历史信息和待决问题。人需要不断记住刚才批准了什么、哪条结论还没验证、哪个 Agent 已经偏离任务。机器吞吐量提高后，人类注意力反而成了串行资源。

成员普遍反馈比以前更累，也不难理解。过去一小时思考架构，后面可能有数小时相对明确的编码工作。代码生成被压缩后，高强度判断会连续出现，人的大脑没有恢复区间。

因此，并行会话数不该只被当成效率指标。它同时是一项负债，超过团队可管理的范围，新增会话只会制造更多待复核状态。

## 看见交付物如何变成审查队列

Token 放开后，产出量会快速上升，但生成不等于交付。代码、调研结论、方案和回复都要经过人工审查，生成端越快，审查端越容易形成队列。

这次实验里，最多的成员单日 Token 花费达到 7000 美元，团队中位数为 2000 美元。原帖作者据此判断，这种消耗超过许多成员的月工资水平，难以持续。

更关键的是，成本没有停在模型账单上。人还要阅读长输出、核对依据、处理冲突结果，并承担错误进入项目后的返工。若只计算调用费用，相当于把最稀缺的人工审查时间记成了零。

评论中有人建议让 AI 审查 AI，并要求输出可核验的证据。这能过滤一部分低级错误，却不能取消最终责任。多一次审查会话还会增加新的上下文和判断任务，只有验收标准足够明确时，它才可能真正减负。

## 便宜模型为何可能形成更贵的路径

团队会把快问快答和前期调研交给更快、更便宜的模型。单次调用成本下降了，但原帖记录到另一个现象，便宜模型往往需要更多轮反复，一次没有完成的任务会跨会话补充、纠偏和重做。

模型路由因此不能只比较单次价格。更实用的核算单位是一次合格交付，包括模型调用、迭代轮数、人工复核、上下文恢复和返工。

一个贵模型若能一次产出接近验收标准的结果，可能比多轮便宜调用更省。反过来，边界清楚、容易自动验证的任务，也没有必要全部交给最高成本模型。路由策略需要跟着任务风险和验收难度走，而不是跟着模型价目表走。

## 当会议减少八成，团队却更难实时回答

实验期间，团队会议数环比减少近 80%。这个数字乍看像是协作效率的大幅提升，但成员对项目细节的掌握度也出现下降。

收到问题后，有人需要先询问 AI，再组织回答，于是沟通逐渐转向非实时方式。更极端的情况是，双方把 AI 生成的内容直接发给对方，对面的 AI 再继续回答，两条错误路径可能在缺少人工理解的情况下越走越远。

这里损失的是团队的共享认知。会议减少本身不是问题，问题在于原本通过讨论形成的背景、判断依据和责任关系，没有被新的工作机制接住。

AI 可以压缩信息交换，却不能自动生成信任。一个成员若无法解释自己交付物的关键决策，任务即使完成，也没有真正进入团队能力。

## 用四个指标重算一次真实效率

团队负责人可以选取一个已经完成的需求，回看完整记录，并计算四项数据。

**交付周期**，从需求确认到通过验收的总时间，而不是模型首次生成结果的时间。

**人工占用**，包括提示设计、会话切换、阅读、复核、解释和返工所花的时间。

**一次通过率**，首次提交达到验收标准的比例，用来识别低价模型造成的隐性迭代。

**知识留存率**，随机询问负责人关键取舍、风险和验证依据，看结论是否留在团队里，而不只留在会话记录里。

这四项数据应和 Token 成本放在同一张复盘表中。若调用量上升，而交付周期、人工占用和一次通过率没有改善，增加预算只是在扩大在制品。

更稳妥的改法，是限制每个人同时承担的活跃任务，为不同风险等级设定验收方式，把长输出压缩成结论与证据，并要求交付负责人能够脱离会话解释关键决策。

100 万美元买到的最重要经验，不是某个模型该多用还是少用，而是 AI 提高了生产速度后，组织必须重新设计审查、路由和知识留存。下一次复盘，不妨先挑一个最近完成的需求，把它的首次生成时间改成可信交付时间，再看团队究竟快了多少。
