# Hermes Studio v0.6.32：群聊、记忆和任务路由终于能连成一条线

如果你正在用 Agent 处理群聊协作、长会话或后台任务，Hermes Studio v0.6.32 值得看。它没有把重点押在某个醒目的新按钮上，而是处理了四类很容易让工作流失控的问题，中文 @mention 失效、长对话压缩错位、后台结果找不到原任务，以及不同 Profile 之间记忆串档。

我把这次合并的 14 个改动放在一起看，最明显的感受是，Hermes Studio 正在补齐一条完整链路。消息从哪里来，应该交给谁，执行过程如何保留，结果送回哪里，记忆又归哪个身份，这几件事终于开始互相对得上。

对读者最实际的价值，是可以据此判断要不要升级，并从群聊、Skill Bundle 或 Profile 隔离记忆中选一个入口验证，不必一次搬动整套工作流。

## 对照旧问题判断升级价值

这次更新覆盖群聊、Workflow、会话压缩、Skill Bundle、Ekko 记忆、Hermes 0.19 和桌面 Runtime。单看功能名有些零散，放回真实任务就清楚了。

| 旧问题 | v0.6.32 的处理 | 直接影响 |
| --- | --- | --- |
| 中文、Emoji 或标点后面的 @mention 可能失效 | 扩展群聊 mention 识别 | 中文群聊中的任务指派更可靠 |
| handoff 或重连后难以追踪任务来源 | 保留每次 Hermes Bridge 运行的来源 | Workflow 结果更容易回到原始上下文 |
| 长会话编辑、分支或并发运行后压缩错位 | 改进游标压缩并限制历史范围 | 长任务不容易带错上下文 |
| 后台委派完成后结果无法稳定返回 | 单聊支持异步投递并持久化结果 | 离开当前会话后仍能接住任务结果 |
| 多个身份共用记忆时可能互相污染 | Ekko 改为 Profile 隔离的规范模型 | 不同角色的长期记忆边界更清楚 |

我认为，真正值得升级的并不是功能数量，而是这些修复同时落在任务链的不同节点。只修 @mention，任务仍可能在重连后失去来源。只修路由，记忆串档又会让正确任务拿到错误背景。v0.6.32 的价值来自组合，而不是某个孤立能力。

## 把群聊指派接到后台结果

群聊修复最直接。@mention 现在可以在 CJK 文本、Emoji 和标点后触发，房主也能在房间设置中查看、生成和轮换邀请码。

这解决的是中文协作里的小故障。类似“资料整理好了，@研究助手继续核对”这样的句子，不该因为 mention 前面是中文标点就漏掉指派。对于多 Agent 房间，这不是输入体验问题，而是路由入口是否可信的问题。

Hermes 0.19 又补上了另一端。助手的中间消息会作为独立气泡实时显示并保存，普通单聊也可以接收持久化的后台委派结果。一个任务从群聊被点名、进入后台执行，再把结果送回来，链路因此更完整。

这里对 Agent 应用的启发很明确。任务路由不能只记录“交给了哪个 Agent”，还要保留来源、运行过程和回传位置。否则异步能力越强，丢结果时越难追。

## 让长会话压缩不再偷换上下文

长会话最麻烦的地方不是消息多，而是编辑、分支和并发运行会改变历史结构。若压缩游标仍按旧位置工作，就可能重复压缩、漏掉关键消息，或者把不属于当前分支的内容带进摘要。

v0.6.32 对游标压缩做了三层修正，保持编辑后的正确位置，适配分支与并发运行，并限制参与压缩的历史范围。完整压缩方案也已经写入文档。

会话搜索同时增加全局分类，并改进 Markdown 感知排序。对经常在代码块、任务记录和普通对话之间检索的人来说，搜索结果不再只依赖表面文本匹配。

我的判断是，这组改动比单纯提高上下文上限更重要。上下文窗口再大，也不能替代正确的历史边界。长任务要稳定，关键是知道哪些信息属于当前分支，哪些已经压缩，哪些仍然可以追溯。

## 用 Profile 管住技能和记忆

新版允许直接在聊天中创建、浏览、运行和删除 Profile 级 Skill Bundle，并查看 Bundle 内包含的 Skill。技能组合由此从文件层面的配置，进入了可以在会话中管理和调用的对象。

Ekko 记忆也统一为按 Profile 隔离的单一规范模型。精确修改会校验 revision，来源审计更完整，相关性过滤也更严格。

这几项放在一起，Profile 不再只是一个角色名称。它开始同时约束技能集合、记忆归属和修改历史。个人助手、项目助手与团队助手可以拥有不同 Skill Bundle，也能保持各自的长期记忆边界。

revision 校验尤其关键。多个运行同时修改同一条记忆时，直接覆盖很容易丢掉较新的内容。先确认 revision，再执行精确修改，至少能让冲突暴露出来，而不是悄悄写坏长期状态。

## 选一个入口完成首次验证

已经使用群聊的团队，可以优先验证中文句子中的 @mention，再观察任务经过 handoff 或重连后是否仍保留来源，并确认后台结果能回到对应会话。

技能较多的个人开发者，可以建立一个 Profile 级 Skill Bundle，只放入两三个职责明确的 Skill，在聊天中完成浏览、运行和删除，确认 Bundle 的可见内容与实际调用一致。

同时维护多个助手身份的人，更适合从 Ekko 开始。准备两个 Profile，分别写入容易区分的项目事实，再检查检索结果、来源审计和 revision 修改是否保持隔离。

桌面端用户还可以留意 Runtime 变化。新的构建、后备路径和 Windows CLI shim 已默认使用 Hermes Agent 0.19.0，macOS、Windows 与 Linux 的窗口控件也分别适配了各自框架。开发文档则支持直接使用当前 checkout，也可按需采用隔离的 Git worktree。

我会把第一次验证压到一个闭环任务里。发出一条带中文标点的群聊指派，让它进入后台运行，完成后检查结果是否返回原会话，再确认写入的记忆只出现在指定 Profile。这个闭环通过，再考虑迁移更长的 Workflow。
