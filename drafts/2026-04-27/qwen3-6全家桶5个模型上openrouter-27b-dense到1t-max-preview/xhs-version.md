# 通义今天一口气铺了 5 个新模型，从 27B 到接近 1T 全段位卡好

今天早上刷模型聚合平台的新上线列表，我数了三遍才确认。

阿里通义千问一口气上了 5 个新条目，覆盖从 27B Dense 一直到接近 1T 参数的 Max Preview，全部带价格、全部能直接调。这是我跟踪这个聚合平台半年以来，单家厂商单日上线模型数量的新纪录。

## 5 个模型先把图谱画清楚

按规模从小到大排一遍。

**Qwen3.6 27B**，Dense 架构，262K 上下文，文本+图像+视频输入。Dense 的好处是单卡能塞下，私有部署首选。

**Qwen3.6 35B A3B**，35B 总参 / 3B 激活的混合 MoE，262K 上下文，多模态。比 27B Dense 还便宜一点，给"想要 MoE 吞吐效率但没必要上千亿"的场景准备。

**Qwen3.6 Flash**，1M 上下文，多模态。对标高吞吐快响应，1M 窗口塞整本书、塞整个项目代码库都没问题。

**Qwen3.5 Plus 2026-04-20**，1M 上下文，多模态。是 3.5 系列的小更新，给存量用户的平滑升级。

**Qwen3.6 Max Preview**，Sparse MoE 约 1 万亿总参，262K 上下文，明确为 agentic coding 和 tool use 优化。

5 个排在一起看，是一张非常清晰的产品矩阵图。

## 为什么"集体发"比单个新模型更值得关注

我看新模型有个习惯，先不看 benchmark，先看价格表。价格表能告诉你一家厂商对自家模型的真实定位。

前几天国产同梯队另一家也是双发把价格底部压了一截，今天通义这 5 个一字铺开，每个价位段都精准卡位。35B A3B 卡"批量任务、要便宜"，27B Dense 卡"本地能跑、私有部署"，Flash 卡"超长上下文、快响应"，Max Preview 卡"agentic coding、复杂工具调用"。

这种铺法不是临时拼凑，是产品经理坐下来画好矩阵的结果。国产模型的发布节奏，从"一次一个旗舰"变成"一次铺一个段位"。

## 我自己最关心的 3 个点

**第一，视频输入。** 5 个里面有 4 个支持 video 输入。会议录屏自动出纪要、教程视频转文字步骤、产品演示抓 bug，之前主流路径要么靠国际旗舰多模态，要么自己拼"视频抽帧 + 多帧图像理解"的土法。现在国产模型原生支持，价格也很友好。我准备把内部"会议录屏纪要"那条管线切到 35B A3B 上跑一周看看。

**第二，Max Preview 的 agentic coding 定位。** 我之前用 Qwen 3 系列做 multi-turn tool use 有个老坑，前几轮调用得很好，第 5、6 轮开始忘记 schema。Max Preview 这次重点优化工具调用，能不能把这个坑填上，我会专门拉个 benchmark 测一下。

**第三，27B Dense 的延续。** 海外开发者社区前几天写过实测，27B Dense 在高端笔记本上跑 4-bit 量化能到 30+ tokens/s，开发机完全可承受。今天云端上的这一版本和开源权重是同一套。本地开发、云端生产，一套权重一套 prompt 无缝切换。

## 我的判断

这次发布的真正信号，不是某一个模型有多强，而是国产模型厂商从"追赶 SOTA"切换到了"全段位铺货"。

之前的发布逻辑是憋大招、对标国际旗舰、跑分超过对手就算赢。天花板是"我们也能做到 SOTA"，赢一次就被下一个版本盖过去，没有复利。

全段位铺货完全不一样。它不追求每一个段位都是 SOTA，但要求每一个段位都"够用 + 比国际同档便宜"。开发者做选型时，国产模型变成那个"先看一眼有没有合适的"的默认选项。

但我也得说一句不那么乐观的，**这种铺货策略对模型质量的稀释风险是存在的**。同时维护 5 条产品线对厂商工程能力是巨大考验。Max Preview 标的是 Preview，3.5 Plus 是小更新，27B Dense 已经是 4 月初的版本，真正的 3.6 旗舰其实只有 35B A3B 和 Flash 两个。铺得开是一回事，每一条都打磨好是另一回事。

## 你下一步可以做什么

把这 5 个 model_id 加到对照测试清单，同样的 prompt 同样的 task，跑一遍延迟、质量、成本三个指标。先试 35B A3B，价格便宜到几乎可以无脑调用。做 agentic coding 产品的，Max Preview 值得专门留一两个小时测 multi-turn tool use 的稳定性。

国内用户可以通过通义官方 API、阿里云百炼平台或 ModelScope 直接获取。

最后留个问题，你觉得国产模型这种"全段位铺货"的打法能持续多久。评论区聊。
