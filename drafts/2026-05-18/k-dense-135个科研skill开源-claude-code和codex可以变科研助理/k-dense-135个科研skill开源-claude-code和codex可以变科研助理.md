# K-Dense 135 个科研 Skill 开源 Claude Code 和 Codex 可以变科研助理

我今天最想保存的 GitHub 项目，不是一个新模型，而是一包 Skills。

K-Dense-AI/scientific-agent-skills 把 135 个科研和分析 Skill 开源出来，仓库现在有 2.3 万多 stars、2500 多 forks，MIT License。它覆盖的不是单一领域，而是生物信息、药物发现、临床研究、材料科学、金融数据、科研写作和一批常用工具包。

它支持 Cursor、Claude Code、Codex 这类 agent 工具。安装入口也很直接，README 给的是 npx skills add K-Dense-AI/scientific-agent-skills。

我觉得它的价值不在“多了 135 个提示词”，而在于它把科研任务拆成了 agent 可以接管的工作单元。

## Skill 比 prompt 更接近工作台

普通 prompt 很容易变成一句愿望。比如“帮我读论文”“帮我分析数据”“帮我写实验计划”。这类请求太大，模型只能给一段看似合理的文字。

Skill 不一样。一个好的 Skill 会把任务边界、输入材料、工具调用、输出格式和检查项写清楚。它更像给 agent 装一个可复用的小工作台。

科研场景尤其需要这个东西。因为科研工作不是聊天，很多任务都有固定流程。查数据库、读论文、整理证据、跑包、写报告、检查引用，这些都可以拆成步骤。

K-Dense 的方向就是把这些步骤预先打包。你不需要每次从零告诉 Codex 或 Claude Code 怎么处理一个生信数据集、怎么查一个药物靶点、怎么整理一篇论文的贡献和局限。

## 它适合谁

第一类是研究生和科研助理。不是让 AI 替你做结论，而是帮你把重复性工作标准化。比如文献卡片、方法对比、实验记录清洗、图表说明初稿。

第二类是跨学科开发者。很多开发者会写代码，但不熟悉临床、生物、材料这些领域的流程。Skill 至少能提供一个起步模板，避免一上来就问错问题。

第三类是数据分析团队。金融数据、科研数据库、Python 包、R 包都有固定套路。把这些套路变成 Skills，比把它们塞进一份巨大 system prompt 更好维护。

## 我会怎么用

如果我今天要把它放进工作流，不会一次装完就全信。

我会先挑 3 个低风险任务。

第一，论文速读。让 agent 输出研究问题、方法、数据、结论、局限和可复现实验。

第二，数据库检索计划。让 agent 列出需要查哪些源、用什么关键词、结果如何记录。

第三，代码审阅。让 agent 对已有分析脚本检查输入输出、随机种子、缺失值处理和图表生成。

这些任务都有一个共同点，它们辅助人做判断，不直接替人下科学结论。

## 需要保守的地方

科研 agent 最大的问题不是会不会写，而是会不会编。

K-Dense 这种 Skill 仓库能降低流程混乱，但不能自动保证事实正确。尤其是临床、生物、材料和金融数据，引用、版本、样本量、统计方法都需要人复核。

last30days 里直接讨论 K-Dense 的社区证据不多，但相关 issue 和评论里反复出现一个要求，让 agent 在数学、论文和 workflow 上做一致性检查。这其实很符合科研场景的真实需求。大家不是只想要漂亮摘要，而是想知道哪里不一致、哪里缺证据、哪里需要补实验。

## 我的判断

Claude Code、Codex、Cursor 这类工具正在从“会写代码”变成“能在本地项目里工作”。科研 Skill 的出现，说明同一套 agent 形态也在进入科研桌面。

它不会把研究者替掉。更现实的变化是，研究者把一部分固定动作交给 agent，自己专注在问题选择、实验设计和结果判断上。

如果你已经在用 Codex 或 Claude Code，K-Dense 值得试一次。不要先问它一个宏大问题，先拿一篇论文、一份小数据、一个脚本，让它按 Skill 给你做结构化处理。能把小任务做稳，才有资格进入真正的科研流程。
