# Karpathy 让 AI 用 HTML 回答 17k 赞爆款 输出格式正在变天

我昨晚做的第一件事，是打开 Claude，问了一个我每周都要问几遍的问题，"帮我对比一下 vLLM、SGLang、TensorRT-LLM 这三个推理框架在 A100 上的取舍"。

不同的是，我在末尾加了一句，"structure your response as HTML"。

它没像往常那样吐一堆 markdown 标题加 bullet，而是给了我一段完整的 HTML，三列卡片布局，每列顶部一个框架名，下面是吞吐、延迟、易用性、坑点四行小标签。我把它存成 .html 双击打开，浏览器里是一张可以直接截屏发群的对比图。

这条 prompt 技巧不是我想出来的，是 Karpathy 上周发的一条推。17426 个赞，1822 转发，913 条回复。

## 一条推为什么能爆到 17k

Karpathy 的粉丝量已经够大了，但他大多数推也就稳定在三五千赞这一档。能冲到 17k 的，往往是他亲自下场写一段判断，而不是转发别人。

这条推恰好就是这种类型。前半截给了一个所有人都能立刻动手试的小技巧，后半截抛出了他对 AI 输入输出未来形态的演进判断。两段都能独立传播，叠在一起就成了爆款。

小技巧那一段只有一句话，"在你的 query 末尾加上 structure your response as HTML，然后把生成的文件用浏览器打开"。

他还顺便提了一句，让 LLM 输出 slideshow 也行。

## 这个小技巧具体怎么用

我自己实测下来，HTML 这种输出对三类问题特别有效。

第一类是解释概念。任何"X 是什么、X 和 Y 区别在哪"的查询，让模型用 HTML 回答，它会自然地给你卡片、对比表、配色块，比 markdown 表格密度高得多。

第二类是做汇总 dashboard。比如"帮我把这周 AI 圈发生的事情按主题归类"，HTML 输出会给你一个仪表盘，每个主题一个卡片，卡片里有事件标题、关键人、一句话总结。我已经把它当周报模板在用。

第三类是生成可视化的方法论清单。例如"我要做 RAG 系统选型，列出我该问自己的 10 个问题"，HTML 版本会自动分组、加序号、配视觉权重，看完就知道哪几个问题最关键。

不适合的场景也很明显。要让模型给你写代码、写引用列表、做严格的结构化数据，HTML 反而是噪声，markdown 或纯 json 更好。纯创意写作也别用 HTML，文字本身就是产品，不需要包装。

我那条 prompt 的实际输出大概长这样（截取一小段）。

```
<div class="card">
  <h3>vLLM</h3>
  <p class="tag">吞吐优先</p>
  <ul>
    <li>PagedAttention 是杀手锏</li>
    <li>动态 batching 默认开</li>
    <li>坑：长上下文调度抖动</li>
  </ul>
</div>
```

浏览器里渲染出来就是一张干净的卡片，比 markdown 表格读起来轻松太多。

## Karpathy 的更大判断

技巧背后他说了一段更值得思考的话。

他认为，对人类而言，audio 是最方便的输入方式（说话就行），但 vision 是最高效的输出方式。理由是人脑里大约三分之一的皮层是为视觉处理服务的大规模并行计算单元，他原话是"10 车道的信息高速公路"。

所以 LLM 的输出格式会顺着视觉带宽往上走，他给了一条进化路径，

1）raw text，硬读、累
2）markdown，加粗、表格，眼睛轻松一点，当前默认
3）HTML，有底层代码但有更多布局和交互空间，正在成为新默认
...
n）交互式神经视频/模拟，由 diffusion 网络直接生成

中间那几步什么样他没写死，但他指了一个方向，最近爆火的某些 demo 已经在拼凑 Software 1.0（确定性代码）和神经网络生成内容这两类产物。

他也提到输入端要升级。光有 audio 和 text 不够，他会忍不住想去屏幕上指、想用手势比划，"就像你和一个真人站在电脑前一起干活"。

整段话连起来看，Karpathy 在说一件事，人和 AI 的输入输出还非常原始，距离 neuralink 那种脑机接口还早，但中间这段进化才是大头。

## 评论区有人捅破了一层

913 条回复里我刷到一条点赞最高的回应，大意是，"这才是为什么 Claude 的 Artifacts 那么好用，它把 HTML 渲染做成了产品内置功能，你不用自己存文件再开浏览器"。

这条回复其实把 Karpathy 没说透的那层捅破了。

HTML 输出之所以现在还只是个"小技巧"，是因为大多数对话界面默认不渲染 HTML。你得自己复制、自己存文件、自己打开浏览器，才能看到真正的输出。这个摩擦把 90% 的用户挡在了门外。

谁先把 HTML 渲染做成 app 内置 view，谁就能把这个技巧变成默认体验。

## 我的判断

我认为 Karpathy 这条推被严重低估了。它表面是个 prompt 小技巧，骨子里是 LLM 产品交互的下一站路标。

每个用 ChatGPT、Claude、Gemini 做日常工作的人都该立刻试一次。每个做 AI 产品的人都该在自己的对话界面里加一个"HTML view"开关。每个做内容的人都该考虑用 HTML 输出代替截图。

但我也得泼一桶冷水。

HTML 输出只对"信息密集型查询"有效。日常的闲聊、单点问答、代码生成，HTML 反而是负担。把它当成万能 prompt 包装会很快失望。

另一个现实问题，国内能用得顺手的 LLM 产品里，目前只有 Claude 的 Artifacts 和少数海外产品把 HTML 渲染做成了原生 view。豆包、元宝、Kimi、DeepSeek 的官方 app 里，HTML 还是要复制出来自己开浏览器。

国产 AI 产品如果要追上这一波，应该把 HTML 渲染当成下一个版本的标配，而不是一个隐藏技巧。Artifacts 这种形态没有什么技术壁垒，难的是产品决心。

更长期看，Karpathy 那条进化路径里 HTML 也只是中间态。再往下，AI 的输出会越来越像一个临时生成的迷你 app，每次回答都是一个为你这个问题专门搭出来的交互界面。文本框、回车、滚动列表这套用了二十年的交互，可能真的快到头了。

## 你今晚可以做什么

第一步，打开你手边任何一个 LLM 产品，复制一句你这周问过的问题，末尾加上 "structure your response as HTML"，看一下输出。

第二步，把生成的 HTML 存成文件，用浏览器打开。建议第一次试就拿"对比型查询"试，差异最明显。

第三步，把这个习惯固化下来。任何"对比、汇总、分类、清单"型的问题都用 HTML 输出，普通对话仍然用默认格式。

进阶玩法，试一下 Karpathy 提到的 slideshow 变体。让模型给你输出一份"用 HTML 写的 slides"，每张 slide 用一个 section 标签，再加点 CSS。出来的东西可以直接当汇报材料。

我这周的 AI 周报已经全部改成 HTML 输出了。下周如果你还在用 markdown 列表写汇总，我会觉得你亏了。
