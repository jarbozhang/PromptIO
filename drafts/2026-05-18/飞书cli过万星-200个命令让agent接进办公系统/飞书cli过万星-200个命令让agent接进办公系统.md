# 飞书 CLI 过万星 200 个命令让 Agent 接进办公系统

今天国内办公 agent 最值得看的入口，不是聊天机器人，而是 CLI。

阮一峰在 X 上提到，多家国产办公平台开始开放 agent 可调用的命令行工具，其中飞书最完整。官方 larksuite/cli 仓库现在已经过万星，补充源显示它覆盖 17 个业务域、200 多个命令、24 个 Agent Skills，安装入口是 npx @larksuite/cli@latest install。

这个方向很关键。因为企业办公里真正有价值的数据，不在一个“智能助手欢迎页”里，而在 Docs、Sheets、Base、Calendar、Mail、Drive 和审批流里。

## Agent 需要手脚

很多办公 AI 产品的问题，是它只能回答。

你问它“这个项目进度怎么样”，它可以写一段漂亮总结。但如果它不能读取项目表、查日历、更新任务、创建文档、发消息、生成会议纪要，再聪明也只是聊天窗口。

CLI 给 agent 提供了手脚。命令行天然适合被 Claude Code、Codex、Cursor 这类工具调用。只要权限和参数设计清楚，agent 就能把办公系统里的动作串成流程。

比如读取飞书多维表格里的销售线索，按条件生成跟进文档，检查日历空档，草拟邮件，再把结果写回任务表。这不是“会聊天”，这是“能干活”。

## 200 个命令的价值

200 多个命令听起来像数量宣传，但它真正说明的是覆盖面。

办公自动化最怕只接一个点。只会读文档，不能写表格；只会发消息，不能查权限；只会查日历，不能改任务。流程一旦跨系统，agent 就断手。

飞书 CLI 如果真的覆盖 17 个业务域，就能把很多内部流程接起来。市场、销售、运营、产品、研发都可能受益。

对中文团队尤其重要。国外工具生态里，Notion、Google Workspace、Slack、Linear、Jira 有很多 agent 接口。国内团队大量数据在飞书、钉钉、企业微信和本地表格里。没有这些入口，办公 agent 很难落地。

## 最值得先做的三个流程

第一，会议后自动整理。

读取会议纪要，抽取行动项，写入任务表，按负责人和截止日期分发。

第二，销售线索清洗。

从表格读取新线索，补全公司信息，按地区、规模、预算打标签，再生成跟进建议。

第三，知识库维护。

扫描一批文档，找出过期页面、重复标题、缺失 owner 的资料，生成清理清单。

这些流程都有共同点，输入结构清楚，输出可检查，风险可控。它们比“让 AI 管理整个公司”更适合第一批试点。

## 权限会成为核心问题

办公系统接进 agent 以后，权限不是附属问题，而是产品核心。

谁能让 agent 读工资表。谁能让 agent 发全员消息。谁能让 agent 修改客户数据。每一次命令调用都应该有审计日志、授权边界和回滚方案。

所以 CLI 生态越完整，越要重视最小权限。企业不要一上来给 agent 超级管理员权限。先给它一个测试空间、几张测试表、几篇测试文档，把流程跑稳后再扩大。

## 我的判断

飞书 CLI 过万星不是一个单纯开发者新闻。它代表国内办公 agent 正在从“对话层”往“执行层”走。

过去大家做办公 AI，常常停在总结、润色、翻译、问答。接下来有价值的是把 agent 接进真实工作流，让它读写企业已有数据，完成可审计的动作。

如果你在飞书里有大量重复流程，今天就可以从一个很小的任务开始。不要先做全公司智能体。先让 agent 处理一个多维表格、一类会议纪要、一批过期文档。跑通一个闭环，比做一个漂亮的聊天入口更重要。
