# OpenRouter 给 7 个主流模型加了 latest 别名，再也不用追版本号了

我前两天刚把生产环境一个 Agent 的模型 ID 从一个长串日期版本换成了另一个长串日期版本，刚换完三天，OpenRouter 一口气放出 7 个 `~latest` 别名。

我盯着控制台看了两秒，骂了一句脏话。

这 7 个别名覆盖了主流模型厂商最常用的几档，国内开发者天天打交道的那几家全在里面。规则只有一条，调用 `~厂商名/模型名-latest` 这种 ID，OpenRouter 帮你自动指向各家当前最新版本。

有人会撇嘴，"不就是个别名吗，我自己 if-else 也能搞定"。等会再聊，先把事情讲清楚。

## 模型版本号是国内开发者最隐形的成本

我做过一段时间国内中型团队咨询，发现一个反常识的现象，**真正拖慢国内 AI 产品迭代的不是算力也不是 API 价格，而是模型版本号**。

听起来很扯。但你想想看一个普通场景。

你在 prod 跑了个带日期后缀的模型 ID，老板某天开会说"听说 X 又升级了，我们的客服效果是不是落后了"。你回去查文档，发现已经有三四个新版本。每个都得跑一遍 eval，最后大概率发现升不升级差别不大，那一周白搭进去了。

更难受的是有家厂商版本号像考古学，一长串日期数字。我自己有一次记错了一位，整个 Agent 跑了半天才发现走的是老模型，回答质量下降一个档。

国产模型也类似。各家都有版本快照机制，每次升级一个新 ID，要么写 model registry 维护，要么硬编码定期手动同步。

这就是 `~latest` 别名想解决的事。

## 7 个别名都覆盖了哪些档位

按能力档位分大致是这样。

**轻量档**两个，国产代表和海外代表各一个，上下文几十万 token，价格每 M tokens 一块钱人民币左右，做批量任务和简单对话足够。

**主力档**三个，覆盖三家不同厂商，上下文已经卷到 100 万 token，价格每 M tokens 在十几块钱区间。这次有一家直接把上下文给到了百万级，做长文档分析的同学可以省掉一层切片逻辑了。

**旗舰档**两个，价格高一档，做复杂推理任务用。

把这七个并排放在一起，**便宜档的能力已经追上去年的旗舰档了**。我自己跑过几个长文档摘要任务，便宜档跑出来的质量在我偏宽松的评测标准下其实够用。

不是说便宜档一定好，是说价格和能力的等高线已经被拉得很奇怪。OpenRouter 把几家放在统一命名空间里，恰好把这种"奇怪"摊在你面前。

## 我的判断，价值不在省事

我自己写过 model registry，一个 yaml 加加载脚本就能跑，从工程讲没什么了不起。

但 `~latest` 别名的真正价值，**是把"跟进最新模型"这件事的心智成本降到了零**。

我观察身边做 AI 应用的朋友有个分化。有的团队每周扫一遍各家更新，永远跑在最前沿。有的团队半年都不换一次模型，因为"上次升级踩了坑，老板说稳定优先"。后者更常见，至少七成是这种状态。

不是他们懒，是切换成本太高。每次切换都要重新 eval、重新调 prompt、重新做回归测试，一旦有人请假就拖一个月。

`~latest` 别名给"稳定优先"派一条妥协路径，你可以选择信任 OpenRouter 替你做版本跟随。代价是某次厂商偷偷改了 API 行为，你的 prod 也跟着抖一下。我认为这个 trade-off 对大部分中小团队是划算的。

唯一要小心的是 prompt 鲁棒性。如果你的 prompt 高度依赖某个特定版本的输出格式，latest 别名可能让你某天突然破防，这种情况还是老老实实锁版本号。

## 实际接入

OpenRouter 接入和主流 SDK 完全兼容，model 字段直接写 `厂商名/模型名-latest` 就行。国内用户可以通过 OpenRouter 官方 API 直连使用，本文不展开。

行动建议很简单，把现有项目里最不重要的一条调用链（比如内部测试用的 chatbot），把模型 ID 改成 `~latest` 版本，跑一周看看。**一周内没踩坑，再决定要不要推到主链路**。

回到开头那条骂街。我那个刚换完版本号的 Agent，今晚下班前会改成 latest。下次厂商再升级，希望我能装作什么都没发生。
