# openclaw 36 万星跨平台个人 AI 助手，使用前需要注意几个安全细节

365389 颗星，74847 个 fork，去年 11 月才建仓的项目。

openclaw/openclaw 这个 TypeScript 项目，今天又一次冲上 GitHub trending。半年时间堆出 36 万星，已经是这个语言生态里最大的开源个人助手项目之一。我盯着这个数字看了三秒，然后想把一些细节给国内开发者朋友讲清楚。

这不是一篇"快上车"的安利。

## openclaw 是个什么定位

最朴素的问题先回答，它是干嘛用的。

它的定位是"你自己设备上跑的私人 AI 助手"。你日常用什么聊天工具，它就在哪个工具里回复你。WhatsApp、Telegram、Slack、Discord、Google Chat、Signal、iMessage，官方列了 20 多个。macOS / iOS / Android 上有语音唤醒和"对话模式"，桌面端有一个叫 Live Canvas 的可视化工作区，工具层自带浏览器和自动化能力。

我的理解是，它在 TypeScript 圈做了一件事，把"个人助手"做成跨所有 IM、跨所有 OS 的统一中枢，而不是某个 IDE 插件或网页。

安装入口很轻。`npm install -g openclaw@latest` 然后 `openclaw onboard --install-daemon`，它会注册一个常驻 daemon。Node 24 推荐，22.14+ 也能跑。Windows 走 WSL2。

## 4 月需要留意的安全细节

ArsTechnica 4 月 3 号有一篇关于 openclaw 的安全报道，提到 agentic 工具在某些条件下出现了未授权拿到 admin 权限的路径。4 月 18 号 Latent Space 那篇《The Two Sides of OpenClaw》也提到，社区收到的安全报告比 curl 多 60 倍，至少 20% 的 skill 贡献被识别为恶意。

curl 是几乎每台 Linux 服务器都装的、有 27 年历史的核心工具。一个半岁大的项目收到的安全报告比它多 60 倍，主要是因为它增长太快、暴露面太大、生态门槛太低。

我的建议很直接。如果你 4 月 3 号之前装过 openclaw 或它的任何 skill，把版本升级到官方公告之后的修复版本，并且把这段时间的可疑账号活动留意一下。重点查的是聊天工具里有没有你不记得发过的消息，浏览器里有没有不属于你的登录会话。

20% 的 skill 是恶意贡献这个数据值得记一下。意思是随手装一个第三方 skill，五分之一的可能它在做你没预期的事。

## 国内开发者怎么用更稳妥

坦率讲，我自己暂时不会把它装在主力机上。但这不代表 openclaw 没价值。

它的价值在于给你示范了一种架构，"个人 AI 助手 = 跨平台 daemon + IM 适配层 + 工具层 + skill 市场"，这套架构在国内基本是空白的。微信生态、钉钉、飞书、企微，目前都没有同等量级的开源参考实现。

我会做三件事。

第一，**用沙箱跑**。专门开一台虚拟机，或用 Docker，或在一台不放任何账号的旧机器上装。让它接副号，不要用主号，不要让它接管主浏览器 profile。

第二，**只装官方 skill**。第三方 skill 在 20% 恶意率没降下来之前，每装一个都当成你在装一个未经审计的 npm 包。看 PR 历史、看维护者、看下载量。npm install 后顺手 `npm ls openclaw` 看一眼依赖树。

第三，**学它的架构，写自己的简化版**。如果你做的是国内场景，比如把 AI 接到企微、钉钉、微信小号，你不需要 openclaw 的 20 个 IM 适配，你只需要那一层。把它当代码参考库读，比直接当生产工具用更稳。

## 一个开放问题

我自己还在摸索的一个问题是，agentic + 插件市场这套架构在治理层面有没有可能更成熟。

curl 的安全模型是它只做一件事，做了 27 年。openclaw 的安全模型是它什么都做，半年长到 36 万星。这两种模型在拉扯。如果 openclaw 想长期跑下去，要么 skill 市场收敛到"只跑官方功能"，要么搞出比 npm 更严格的签名加审计机制。

你怎么看 agentic 工具的"插件市场"这件事，留言聊聊。

回到开头那个 365389。这个数字本身没错，只是 star 是好奇心投票，不等于审计报告。装之前多看一眼，跑之前隔个沙箱。
