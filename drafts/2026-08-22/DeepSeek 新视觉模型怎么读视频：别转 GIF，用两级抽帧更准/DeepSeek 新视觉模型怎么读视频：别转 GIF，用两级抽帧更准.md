# DeepSeek 新视觉模型怎么读视频：别转 GIF，用两级抽帧更准

如果你正准备用 DeepSeek 新视觉模型分析监控片段、游戏录像或短视频，最该调整的不是提示词，而是送进模型的画面。

DeepSeek V4 Flash Vision Exp 目前不接收音频，官网和 API 也不直接接收视频。把视频转成 GIF 同样解决不了问题，原帖作者用代码验证后发现，模型只识别 GIF 的第一帧。

真正可用的办法，是把视频拆成按时间排列的 JPEG 或 PNG。遇到快速动作，再把普通的匀速抽帧升级成两级采样，先用低帧率看全片，再对关键事件加密取帧。

## 选一段能暴露差异的视频

我会避开口播和长时间静止画面，选一段同时包含场景变化与短促动作的视频。比如角色进入画面、物体突然移动、游戏里发生交火，这类片段更容易检验模型有没有漏掉关键过程。

测试片段不必很长。重点是你能人工说清事件顺序，并知道哪个瞬间最容易被低帧率采样跳过。

准备时保留原视频，再建立三个输入组。

- GIF 组，将完整片段转成 GIF
- 匀速组，按固定时间间隔抽取 JPEG 或 PNG
- 两级组，全片用约 1fps 获取宏观画面，再对事件窗口提高采样频率，并围绕动作中心裁切

这三个输入组服务同一个问题。测试时不要临时更换视频或提示词，否则很难判断差异究竟来自哪里。

## 把帧按时间轴交给模型

抽出的图片要按时间顺序作为多个 `image_url` 传入。提示词里同时写清采样率和时间轴，让模型知道每张图处于什么位置，而不是把它们当成一组无序图片。

可以把输入说明压缩成下面这种结构。

```text
这些图片来自同一段视频，并已按时间顺序排列。
全片采样率为每秒 1 帧。
事件窗口使用更高采样率。
请按时间轴描述事件，并标出动作开始、变化和结束。
```

GIF 组也使用同一任务，但不要预期它能保留完整动态信息。根据原帖的代码验证，DeepSeek V4 Flash Vision Exp 只读取了 GIF 第一帧，视频转 GIF 在这里更像是丢掉了后续画面。

匀速抽帧适合场景概览，却可能错过发生在两帧之间的快速动作。原帖作者用 CS2 录像验证后采用了另一种路径，宏观 1fps 全图，加上事件窗口的高帧率中心放大。

我的判断是，视频理解的输入不该只有一种时间尺度。全片画面负责回答发生在哪里、前后发生了什么，局部密集帧负责回答动作究竟怎样完成。

## 用同一组问题验收三种方案

不要只看模型输出长不长。真正有用的验收标准，是它有没有还原你已知的事件链。

我会固定检查下面几项。

- 是否识别出主要角色、物体和场景
- 是否按正确顺序描述动作
- 是否漏掉持续时间很短的事件
- 是否把相邻两次动作合并成一次
- 是否能指出事件发生的大致时间窗口
- 加密事件段后，动作描述是否出现可核对的新增细节

如果两级采样只让回答变长，却没有补回关键动作，就应重新选择事件窗口或裁切区域。高帧率不是越多越好，它要覆盖真正需要观察的瞬间。

## 避开四个输入坑

第一个坑是把 GIF 当作视频容器。文件能上传，不等于模型读到了完整动画。

第二个坑是全片统一加密抽帧。这样会制造大量相似图片，却未必把有限输入留给关键动作。

第三个坑是只传图片，不解释采样率和时间轴。模型看到的是离散画面，时间信息需要由输入明确补上。

第四个坑是只做中心裁切。快速动作可能发生在画面边缘，因此全图低帧率层不能省，它负责定位事件窗口和空间关系。

## 把第一次验证压到一个事件窗口

找一段你能人工复述的短视频，标出一个持续时间很短的动作。分别准备 GIF、固定间隔抽帧、全片 1fps 加事件段密集帧三组输入，再用完全相同的问题检查事件顺序和遗漏点。

这次验证的交付物不该是三段漂亮回答，而是一张简单记录，哪种输入看到了什么，漏掉了什么，事件窗口调到哪里后发生变化。

当模型不能直接读视频时，抽帧策略就是视频理解的一部分。下一次碰到动作密集的片段，别急着增加整段帧数，先把关键事件的时间窗口找准。
