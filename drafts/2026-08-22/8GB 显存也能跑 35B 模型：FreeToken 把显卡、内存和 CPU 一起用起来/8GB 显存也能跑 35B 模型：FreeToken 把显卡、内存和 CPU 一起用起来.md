# 8GB 显存也能跑 35B 模型：FreeToken 把显卡、内存和 CPU 一起用起来

如果你手里是 8GB 显存的 RTX 4060，又想在本地运行 35B 级模型，FreeToken 给出了一条值得核验的新路径。它不要求所有参数都挤进显存，而是让 GPU、CPU、系统内存和 PCIe 共同承担推理。

原帖转述的论文数据里，Qwen3.6 35B 在 8GB RTX 4060 笔记本上达到 39.3 tok/s。这个数字很吸引人，但我更关心另一件事，8GB 只是显存门槛，不是整机配置答案。

读完这份选型指南，你应该能判断自己的机器是否值得尝试，以及安装前必须补齐哪些信息，避免下载完模型才发现内存、格式或运行环境不匹配。

## 判断你是不是 FreeToken 的目标用户

FreeToken 解决的是超大混合专家模型，也就是 MoE 模型的个人电脑推理问题。

MoE 每生成一个 token，只会激活一部分专家参数。FreeToken 利用这个特点，把需要频繁计算的部分留在 GPU，把其他工作交给 CPU 和系统内存，并通过 PCIe 搬运临时需要的专家参数。

我会把适合尝试的人分成三类。

- 有 RTX 4060 这类显存有限的显卡，但系统内存仍有扩展空间
- 想运行 35B 及以上 MoE 模型，不满足于只能加载更小模型
- 目标是代码、邮件、工具调用等 Agent 任务，愿意为本地运行核验整套硬件条件

如果你只看显存数字，FreeToken 很容易被理解成低配置机器直接运行超大模型。评论里已经有人指出，运行 284B 模型还可能需要数百 GB 内存。这个提醒很关键，参数没有放进显存，不等于参数不需要存放和搬运。

## 把 8GB 显存拆成四个条件

FreeToken 的调度逻辑比单纯的显存卸载更细。

在预填充阶段，也就是 Prefill，它会提前搬运下一层可能需要的专家参数。在逐 token 解码阶段，也就是 Decode，它再根据 CPU、GPU 和 PCIe 的实际速度动态分工，决定哪些任务交给哪种硬件。

所以，选型时不能只问显卡型号，还要同时检查四项条件。

- GPU，确认显存容量、计算能力和项目支持的运行环境
- 系统内存，确认模型权重、缓存和运行开销能否容纳
- CPU，确认被分配到主机端的计算不会成为主要瓶颈
- PCIe，确认参数在内存和显卡之间搬运时不会拖慢解码

我的判断很直接。FreeToken 降低的是显存独自承担全部模型的压力，它没有消除整机资源需求。RTX 4060 用户真正获得的，是参与更大模型推理的可能性，而不是绕过容量和带宽限制。

## 按模型规模选择验证分支

原帖给出了三组数据。Qwen3.6 35B 搭配 8GB RTX 4060 笔记本，达到 39.3 tok/s。DeepSeek-V4-Flash 284B 搭配 RTX 5090 台式机，达到 22 至 25 tok/s。GLM-5.2 753B 搭配 RTX PRO 6000 工作站，约为 15 tok/s。

这三组结果不能直接横向比较，因为模型规模和硬件都不同。对大多数 RTX 4060 用户，35B 才是合理的第一条验证分支。

如果目标是 35B 模型，我会优先核对对应模型名称、权重版本、量化格式和系统内存需求。如果目标直接跳到 284B 或 753B，问题已经不再是显卡能否启动，而是机器有没有足够的内存容量、CPU 能力和数据搬运带宽。

评论中还有用户称，自己用 RTX 4060、llama.cpp 和 MTP 也能获得相近的 Qwen 速度。这条反馈缺少完整测试条件，不能拿来做性能结论，却提醒了一个选型问题，FreeToken 需要和现有推理方案在同一模型、同一量化、同一上下文长度下比较。

## 下载模型前完成这张核验卡

我不会拿 39.3 tok/s 直接当成自己的预期速度。安装前，我会要求下面这些问题都有明确答案。

- 模型是否确实采用 FreeToken 支持的 MoE 架构
- 测试使用的是哪个准确权重版本
- 权重采用什么量化格式，项目是否直接支持
- 8GB 显存之外需要多少系统内存
- 测试机器使用什么 CPU、PCIe 规格和操作系统
- 39.3 tok/s 对应怎样的上下文长度、批量大小和生成设置
- 首次 Prefill 延迟是多少，持续 Decode 是否稳定
- 模型加载后是否仍给操作系统和其他程序留有内存

目前给出的材料没有提供完整安装命令、量化格式、内存占用和测试参数，所以这些项目都应该在仓库、论文或官方文档中逐项核对。缺少其中任何一项，我都不会只凭显卡型号下载几十 GB 的权重。

## 用一个 Agent 任务验收整套机器

FreeToken 还设计了 Agent State Cache。Agent 调用工具、修改上下文并继续执行时，它可以减少重复 Prefill。原帖展示的方向包括写代码、读邮件、调用工具和游戏场景。

对我来说，这比单次聊天跑出高 token 速度更值得关注。Agent 工作流会反复修改上下文，首轮速度漂亮但每次工具调用后都要重新处理大量内容，实际体验依然可能很慢。

真正的验收任务应该固定模型、量化格式和上下文，让 Agent 连续完成一次工具调用，再记录首次响应、Prefill、Decode、系统内存峰值和后续轮次耗时。只要这组数据稳定，8GB RTX 4060 才算真正获得了运行 35B 模型的实用路径。

我的下一步动作很明确，先找到 FreeToken 的正式仓库和论文，确认 35B 示例的完整配置，再决定是否下载权重。对 4060 用户来说，最重要的数字不是 8GB，而是整机资源组合能否复现那条 39.3 tok/s 的路径。
