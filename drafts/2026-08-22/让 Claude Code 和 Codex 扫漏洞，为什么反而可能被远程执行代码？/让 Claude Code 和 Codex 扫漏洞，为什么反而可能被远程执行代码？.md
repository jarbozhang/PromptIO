# 让 Claude Code 和 Codex 扫漏洞，为什么反而可能被远程执行代码？

你把一个陌生依赖交给 Claude Code 或 Codex 扫漏洞。它读完 README，找到仓库自带的安全脚本，判断脚本可信，然后主动执行。

漏洞还没扫出来，攻击者的二进制文件已经在主机上运行。

AI Now Institute 公布的概念验证揭示了一条反直觉攻击链。用于防御的编码 Agent，会把待审计仓库里的恶意内容同时当成数据和指令。对工程团队来说，关键不是停用 Agent，而是别让不可信代码、自动命令执行和关键环境出现在同一条链上。

## 还原主机失守的现场

研究人员修改了 Python 库 `geopy` 的副本，在仓库里放入 `security.sh`、恶意二进制文件 `code_policies`，以及作为伪装的 Go 源文件 `code_policies.go`。

`security.sh` 表面上引用了 Semgrep、Black 和 mypy 等常见工具，实际会启动恶意二进制文件。伪装源码则负责制造可信外观，让 Agent 误以为二进制文件由这份正常的安全检查代码编译而来。

第二层诱导藏在 README。文档没有直接要求运行恶意载荷，只是把 `security.sh` 描述成仓库的安全检查工具，建议在提交代码前执行。

当研究人员要求 Agent 对仓库做安全测试时，Claude Code 和 Codex 都沿着这条线索展开调查。它们检查脚本、源码和二进制文件，得出可以安全运行的判断，随后执行脚本，攻击载荷因此进入主机。

整条事故链可以压缩成五步。

不可信依赖进入审计目录

→ 仓库文档把恶意脚本包装成安全流程

→ 伪装源码帮助二进制文件通过语义判断

→ Agent 认为执行命令符合审计目标

→ 自动授权放行，主机发生任意代码执行

## 找到真正失效的信任边界

根因不只是提示词注入，也不只是某个模型判断错了。更深的问题是，Agent 在同一个上下文里读取不可信内容、规划安全任务、判断命令风险并执行命令。

传统扫描器把源码当作被分析的数据。编码 Agent 却会理解 README、脚本注释和项目指令，还会把这些内容纳入行动计划。攻击者不必攻破模型，只需要让恶意动作看起来像完成任务所需的正常步骤。

研究中的攻击不依赖 hooks、skills、插件、MCP Server 或特殊配置文件。普通 README 就能承担诱导入口，因此只检查 `.mcp`、`.json`、`CLAUDE.md` 或 `AGENTS.md` 远远不够。

研究人员还分别询问模型仓库里是否存在提示词注入。在其测试中，Claude Sonnet 4.6 和 GPT-5.5 都没有识别出来。不过论文也强调，结果会受到模型、上下文、提示词和环境变化影响，这条攻击链并非每次都产生完全相同的行为。

## 解释为什么常见防线不够

把 Agent 放进沙箱是必要动作，但沙箱不是绝对边界。概念验证本身没有继续演示沙箱逃逸，不过研究指出，一旦攻击者已经取得代码执行能力，就可能继续寻找沙箱漏洞、配置文件写入点、凭据或远程服务权限。

只增加人工确认同样不完整。高频弹窗容易造成自动化偏误和确认疲劳，操作者可能在连续批准正常命令后，放过那条被包装得最像安全检查的命令。

让另一个模型检查是否存在注入，也不能构成独立控制。生成执行计划和识别恶意意图的组件如果共享相近的模型能力、上下文和判断方式，失败可能同步发生。

真正需要拆开的，是读取、判断、执行和访问关键资源这四种权限。

## 把修复落到运行边界

扫描陌生仓库时，创建一次性虚拟机或容器，不挂载个人目录、SSH 密钥、云凭据、生产配置和宿主机套接字。任务结束后直接销毁环境，不把它继续用于开发或发布。

Agent 使用无特权账号运行，只开放审计所需的只读目录。禁止写入启动项、工具配置、流水线目录和宿主机路径，也不要让扫描身份继承开发者的完整权限。

默认关闭出站网络，只按任务开放必要目标，并记录 DNS、连接和进程行为。网络限制无法替代隔离，但能压缩载荷下载、凭据回传和横向访问的空间。

把仓库自带脚本、二进制文件、安装钩子和测试命令设为高风险动作。即使 Agent 判断安全，也必须由人检查文件来源、内容、哈希、调用链和预期输出后再决定是否执行。

最后，把自动扫描分成两个阶段。第一阶段只读分析并生成报告，第二阶段在新的隔离环境里运行经过人工选定的命令。不要让读取陌生文档的同一个会话直接获得执行权。

## 留下一张事故卡片

**触发条件**　Agent 审计不可信仓库，同时拥有命令执行能力。

**危险信号**　文档推荐运行仓库自带安全脚本，二进制文件由同名源码提供可信外观，命令被描述为完成审计的必要步骤。

**首要控制**　一次性隔离环境、无凭据挂载、最小权限、默认限制网络、未知命令人工确认。

**验收标准**　即使 Agent 执行了仓库中的恶意文件，攻击者也拿不到宿主机凭据、生产权限和可持续利用的网络入口。

安全 Agent 不该因为任务叫作漏洞扫描，就自动获得更高信任。面对陌生依赖，最可靠的假设仍然是，仓库里的每个文件都可能在尝试改变审计者的行为。
