# 把 40 个营销 Skill 塞进 AI 工具，独立开发者可以少花哪些外包钱

一个独立开发者最容易卡住的地方，往往不是产品能不能做出来，而是产品做出来以后，没人知道、没人点击、没人留下来。

预算不够请完整增长团队，找 agency 又很容易变成一次昂贵的交付。AI 能写文案，但没有产品上下文时，经常写得像通用广告模板。

marketingskills 这个开源项目有意思的地方就在这里，它不是再给你一个聊天入口，而是把 40 多个营销 Skill 做成 Markdown 工作流，放进 Claude Code 或 Cursor 这类工具里，让独立开发者先跑出一版可用的增长方案。

## 从一个卖不动的产品页开始

想象一个很常见的场景，一个技术创始人已经有了产品、用户画像和一张落地页，但转化很低。

以前这件事通常会拆成几笔钱，找人看定位，找人改文案，找人做 SEO，再找人检查 onboarding 和流失。每个环节都不算神秘，但放在一起，对 solo founder 来说就很重。

marketingskills 的入口不是“让 AI 帮我做营销”这种大问题，而是先填一次 product-marketing，把产品、用户、定位这些底稿放进去。后面的定价、CRO、SEO、冷启动邮件、留存类 Skill，都可以基于这份上下文继续工作。

这一步很关键。营销不是句子写得热闹，而是上下文一致。一个定价建议如果不知道目标用户，一个冷启动邮件如果不知道购买动机，输出再漂亮也很难落地。

## 工具进入流程后，AI 不再只写一段文案

Corey Haines 把自己的增长经验整理成 40 多个 Markdown skills，覆盖 pricing、launch、SEO、AI-SEO、ad creative、CRO、onboarding、churn-prevention、AB 测试、cold-email 等环节。

对独立开发者来说，价值不在“功能很多”，而在这些 Skill 能沿着同一条增长链条接力。

比如先用 product-marketing 固定产品语境，再让 CRO Skill 审一遍落地页。接着用 SEO 或 AI-SEO Skill 补搜索入口，用 cold-email Skill 写第一批触达邮件，最后让 onboarding 和 churn-prevention 检查用户进入产品后的流失点。

这就接近一个小型增长工作台，而不是单次 prompt。它不能替代所有专业服务，但可以把“我完全不知道从哪开始”压成“我先拿一版方案去验证”。

## 交付物从灵感变成一组可检查资产

我认为 marketingskills 最适合的用法，不是让 AI 直接决定战略，而是让它产出一组可以被人检查、删改、上线测试的资产。

一轮下来，独立开发者可能拿到的不是一句口号，而是落地页审计、定价思路、增长计划、邮件草稿、入门流程建议、流失预防方向。每一项都不应该直接照抄，但每一项都能进入下一次产品会议或发布前检查。

这里的变化很实际。以前请 agency，交付物可能更完整，但沟通成本高、周期长、价格也高。用 marketingskills，更像先让一个增长顾问坐到你的编辑器旁边，帮你把混乱问题拆成可修改的稿件。

它省下来的，不一定是全部外包预算，而是最早那一轮摸方向的钱和时间。

## 哪些外包钱可以先缓一缓

如果你的产品还在早期，最值得先用它替代的，是那些“需要方向，但还没到精修阶段”的工作。

可先内部跑一版的交付物包括

- 落地页转化审计，检查首屏、价值主张、行动按钮和信任信息
- 定价初稿，整理套餐、限制条件和用户购买理由
- SEO 与 AI-SEO 方向，先确定内容入口和关键词主题
- 冷启动邮件，拿到第一版触达结构和不同用户段落
- onboarding 检查，找出新用户从注册到首次价值之间的断点
- churn-prevention 思路，把流失预防提前放进产品流程

这些东西的共同点是，它们不要求一开始就完美，但必须早出现。越早把它们放到纸面上，越容易发现产品定位哪里含糊。

## 可复用的经验是先跑一条增长链

marketingskills 的正确打开方式，不是一次把 40 多个 Skill 全部跑完。

更稳的做法是选一条链路，比如“落地页到邮件触达”，只跑 product-marketing、CRO、SEO、cold-email 这几段。等有了真实用户反馈，再补 onboarding 和 churn-prevention。

我会把它当成独立开发者的增长草稿机。它负责把空白页变成可讨论的方案，人负责判断哪些内容符合产品现实，哪些建议应该删掉。

真正要小心的是，不要把 AI 输出当成市场验证。它能帮你省掉第一轮空转，但不能替你证明用户愿意付钱。增长方案最后还是要回到页面点击、邮件回复、用户留存这些可验证信号上。
