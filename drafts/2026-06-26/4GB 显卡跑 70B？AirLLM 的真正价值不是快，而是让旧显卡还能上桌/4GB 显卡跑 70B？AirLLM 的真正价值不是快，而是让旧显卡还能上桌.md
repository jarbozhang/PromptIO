# 4GB 显卡跑 70B？AirLLM 的真正价值不是快，而是让旧显卡还能上桌

如果你手里只有一张 4GB 显卡，还想摸一下 70B 大模型，AirLLM 值得放进候选名单。但它解决的不是快，而是能不能跑起来。

这件事对本地大模型玩家很现实。很多部署方案卡住的地方，不是代码，而是显存预算。

读完这篇，你可以判断三件事，自己的机器适不适合试 AirLLM，AirLLM 适合放在哪类任务里，什么时候应该换别的部署路径。

## 判断你是不是低显存验证人群

AirLLM 的 README 写得很直，70B 大模型可以在单张 4GB GPU 上推理，Llama 3.1 405B 可以在 8GB VRAM 上跑。

关键点在后半句，它不是把模型砍小，也不是靠蒸馏、剪枝把问题糊过去。它走的是推理内存优化，把模型按层拆开，需要哪一层就加载哪一层，再配合预取和压缩，把显存压力降下来。

所以适合它的人群很明确。

- 你想验证 70B 级模型的输出风格，但手里没有大显存卡
- 你在学习本地推理，想看大模型在低显存机器上怎样被调度
- 你做低预算实验，能接受慢一点，只要流程能完整跑通
- 你不急着服务很多请求，只需要单机、单任务、小批量验证

如果你的目标是给多人同时用，或者追求稳定低延迟，AirLLM 就不该被当成主部署方案。它更像一张入场券，不像一条高速路。

## 把显存问题和速度问题分开

很多人看到 4GB 跑 70B，第一反应会自动补成 4GB 快速跑 70B。这里最容易踩坑。

按层加载的取舍很清楚。显存里不再长期塞住整套模型权重，压力小了，但加载、预取、压缩和数据移动会进入链路。你省下的是显存，不是凭空多出来的吞吐。

这也是 AirLLM 的价值边界。它把原来直接失败的任务，变成可以验证的任务。它不保证你能获得生产服务里想要的并发、响应速度和稳定吞吐。

我的判断很简单，AirLLM 不该被拿来证明小显卡已经追上大显存机器。它真正有用的地方，是让旧显卡重新具备实验资格。

## 按任务分支决定要不要上 AirLLM

选型时别先问它强不强，先问你要用它完成哪类任务。

- 如果你要做概念验证，想确认 70B 级模型能不能完成某类提示词、格式输出或推理任务，可以试 AirLLM
- 如果你要做学习项目，想理解低显存推理里分层加载、预取和压缩的取舍，可以试 AirLLM
- 如果你要做本地演示，只需要少量样例输出，可以把 AirLLM 当成低预算入口
- 如果你要做高频接口、聊天服务、批量任务或稳定交付，应该评估更小模型、常规推理框架或更合适的硬件方案
- 如果你不能接受明显等待，也不想处理缓存、磁盘和模型文件路径，AirLLM 可能会把问题从显存转移到体验上

这份清单的核心不是劝你用或不用，而是别把验证工具塞进生产位置。AirLLM 的优势越清楚，边界也越清楚。

## 用一个短输出任务验收边界

真正开始前，把验证路径压到一个小任务。

选一个你能合法获取的模型，按 GitHub README 走最小示例，不要一上来接业务流程。提示词也别复杂，选一个短输入、短输出、答案容易判断的任务。

验收时只看四个信号。

- 能不能完成一次生成
- 首次输出前等待是否能接受
- 显存是否稳定在你的机器范围内
- 模型分层、缓存和文件保存是否给磁盘带来额外压力

如果这四项都过，再增加上下文长度、输出长度和任务复杂度。只要其中一项卡住，就先别谈完整工作流。

AirLLM 最适合的姿势，是把 4GB 显卡从只能跑小模型，推进到能碰一碰大模型。这个改变已经足够有价值，但它不需要被包装成高吞吐答案。

旧显卡能上桌，不等于它坐主位。
