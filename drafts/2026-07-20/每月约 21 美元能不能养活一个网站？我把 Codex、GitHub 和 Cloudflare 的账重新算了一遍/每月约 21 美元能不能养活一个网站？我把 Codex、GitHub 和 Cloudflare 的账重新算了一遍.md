# 每月约 21 美元能不能养活一个网站？我把 Codex、GitHub 和 Cloudflare 的账重新算了一遍

每月约 21 美元，确实可能让一个网站保持在线，但这张账只对一类项目成立，也就是代码能生成静态页面、内容可以通过 GitHub 更新、暂时不需要数据库和复杂后台的网站。

如果你正在做个人主页、内容站或产品验证页，这套组合值得认真算一次。如果项目需要账号、订单、数据管理或持续运营，21 美元就不能代表完整成本。

我重新拆账后最大的判断是，低成本建站真正省下的是基础设施费用，开发返工、内容更新和日常维护仍然要有人承担。

## 判断自己是不是这张账的目标用户

原帖给出的组合很清楚。Codex 负责编码，每月 20 美元。GitHub 负责版本控制，免费。Cloudflare 提供每年 12 美元的域名，以及免费的 DNS、防火墙和静态网站托管。

按这组数字折算，域名每月约 1 美元，加上 Codex 的 20 美元，总额约 21 美元。

这张账适合以下项目。

- 个人主页、作品集和活动介绍页
- 文档站、博客和更新频率不高的内容站
- 用来验证需求的产品落地页
- 能接受通过代码仓库更新内容的小型站点

评论里有人提出，可以做几个模板，让 Codex 整合内容并生成静态页面，把网站做成一个轻量的伪 CMS。这个思路的价值不只是省服务器，而是顺手避开数据库、后台系统和对应的维护工作。

但如果你连每次改文案都不愿意碰仓库，静态方案省下的钱，很可能会变成新的操作负担。

## 按三类项目重算投入

### 静态内容站

这类项目最接近原帖的 21 美元模型。域名是持续支出，GitHub、DNS、防火墙和静态托管按原帖方案可以使用免费服务，Codex 则是可选的开发投入。

评论区也有人指出，简单静态站并不需要每个月订阅 Codex。网站完成后，如果更新只是替换文章、图片或少量页面，开发工具可以按实际需求使用，而不必机械地计入每个月。

因此，静态站更该问的不是能否压到 21 美元，而是内容更新是否足够简单，简单到你愿意长期维护。

### 带后台的小产品

一旦加入登录、用户数据、内容编辑后台或其他动态能力，原帖清单就不再完整。评论里那句“不需要部署程序的服务器吗”，问到了关键位置。

原帖没有给出服务器、数据库、存储、邮件或监控的价格，所以不能直接算出新的月费。但可以确认，21 美元只能覆盖已列出的项目，不能被当成带后台产品的完整预算。

我的选择会很直接。产品还在验证期，就尽量把公开页面静态化，把确实需要状态的部分单独列出来。不要因为基础页面免费，就误以为整个产品的运行成本已经解决。

### 需要持续运营的站点

持续运营的站点还多了一层成本。内容要更新，故障要处理，依赖要升级，表单和关键页面要检查，用户反馈也需要进入迭代。

这些工作不一定立刻产生新的服务账单，却会消耗稳定的人力。评论里有人说做了一堆网站，收益仍然是零，像是在花钱买玩具。这个反馈比 21 美元本身更值得警惕。

建站价格低，不等于获客成本低，也不等于网站会自然产生收入。对需要长期运营的项目，我会把内容来源、更新频率和目标用户一起放进预算，而不是只盯着托管账单。

## 用四个条件做分支选择

选型时，我会检查下面四件事。

- 页面能否在构建时一次生成
- 是否必须保存用户数据和业务状态
- 内容更新者是否能接受 GitHub 工作流
- Codex 是持续生产工具，还是只在搭建和改版时使用

四项里，如果只有最后一项需要付费，原帖方案就很合适。如果需要保存用户状态，应该把后端能力另列预算。如果内容团队离不开可视化后台，就要评估真正的 CMS，而不是为了守住低价硬套静态站。

Codex 也不应该被简单归类为网站运行费。它更像开发和维护工具。评论里既有人认为简单网站连这 20 美元都能省，也有人反馈生成结果不够满意。两种声音并不冲突，工具值不值这笔钱，取决于它是否减少了你的修改时间。

## 把验证压到一个真实页面

决定采用这套组合前，可以只做一个最能代表项目难度的页面。不要挑只有标题和按钮的首页，而要挑包含真实内容、导航、图片和更新需求的页面。

验收时只看四个结果。

- 页面是否能通过 GitHub 稳定更新
- Cloudflare 静态托管是否满足当前交付形态
- 修改一次内容需要多少人工操作
- 去掉 Codex 后，维护流程是否仍然能继续

如果这条路径顺畅，再扩展整个站点。如果一个页面已经频繁需要数据库、后台或人工救火，21 美元就只是入口价格，不是项目成本。

我最终会把这张账理解成一张筛选表。静态内容站可以从它开始，带后台的小产品要补齐动态服务，持续运营的站点还要把维护和内容生产算进去。

真正该验证的不是网站能不能上线，而是它上线之后，谁来更新，以及为什么值得继续更新。
