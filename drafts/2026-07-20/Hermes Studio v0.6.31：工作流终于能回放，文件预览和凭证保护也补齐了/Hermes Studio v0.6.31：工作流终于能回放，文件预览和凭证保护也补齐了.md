# Hermes Studio v0.6.31：工作流终于能回放，文件预览和凭证保护也补齐了

如果你用 Hermes Studio 搭工作流，却经常卡在三个地方，失败后找不到执行路径、查看文件要来回切应用、编辑 Provider 时担心凭证暴露，v0.6.31 值得认真看。

这次一共合并了 25 个 PR。相比增加几个醒目的新入口，我更关注它补上的工程能力，执行记录、历史回放、文件预览和凭证保护，都会直接影响 Agent 能不能从演示走向稳定使用。

读完可以先判断一件事，你现在遇到的是模型能力不足，还是调试链路和操作界面没有跟上。后者往往更隐蔽，也更浪费时间。

## 把失败工作流还原出来

以前调试工作流，最麻烦的不是看到失败，而是不知道它经过了哪条分支。条件一多，只看最终输出，很难区分是条件判断、节点输入，还是中间步骤出了偏差。

v0.6.31 给 Workflow 增加了结构化 JSON 条件、完整执行记录与历史路径回放。它们组合起来，才是这次更新里最有分量的一组变化。

| 旧问题 | v0.6.31 的变化 | 直接用途 |
| --- | --- | --- |
| 条件表达不够结构化 | 支持结构化 JSON 条件 | 更清楚地描述分支规则 |
| 只能看到执行结果 | 保留完整执行记录 | 定位具体节点与上下文 |
| 难以复原历史路线 | 支持历史路径回放 | 检查当时走过的分支 |

我认为，回放的价值不只是方便排错。只要 Agent 开始执行多步任务，团队迟早要回答三个问题，它做了什么、为什么走到这里、同样输入能否复现。完整记录和历史路径，正是在给这些问题补证据。

## 在一个界面里检查交付文件

Agent 生成文件之后，检查过程常常被切得很碎。HTML 要开浏览器，PDF 和 Office 文档要换阅读器，CSV、Markdown、源码又在不同工具里查看。

新版本支持预览 HTML、PDF、DOCX、PPTX、XLSX、CSV、图片、Markdown 和源码文件。覆盖面从普通文本扩展到了常见办公交付物，这会让文件型任务顺畅不少。

我会优先用它验证两类场景。一类是让工作流生成报告、表格或演示文稿，另一类是让 Agent 同时处理源码和说明文档。预览不等于内容已经正确，但它能缩短发现格式错乱、文件选错或交付不完整的路径。

这里的关键变化不是“多支持几种格式”，而是检查动作回到了工作区。对于需要频繁查看中间产物的任务，少一次切换，就少一次上下文丢失。

## 编辑 Provider 时少暴露一层凭证

Provider 配置是很多 Agent 工具容易被忽略的风险面。连接信息既要能编辑和测试，又不该在日常查看时完整显示，更不能改完以后没有记录可查。

v0.6.31 增加了凭证脱敏、连接测试和审计记录。三项能力分别覆盖查看、验证和追踪，形成了比单纯隐藏输入框更完整的保护链。

我会把这项升级看成团队使用的基础条件，而不是装饰性的安全选项。个人临时环境里，配置暴露可能只是一次疏忽。到了共享工作区，谁看过、谁改过、连接是否可用，都会变成交付问题。

## 判断哪些任务现在更适合验证

这次更新还加入了自定义 runtime 目录，并改善了会话与协作体验。单聊和群聊支持消息引用，Delegate Task 能在跨回合及重启后可靠返回。历史会话、Workspace Diff、模型切换和 Reasoning Effort 也得到优化。

桌面端统一了暗色视觉，更新流程进一步完善，同时修复了 macOS 麦克风权限等问题。这些改动单独看不算大，放到长时间运行的 Agent 场景里，却会影响任务能不能连续完成。

适合优先升级验证的人很明确。工作流分支已经多到难以凭记忆排错，Agent 经常产出 Office 文档或源码文件，或者团队需要共同维护 Provider 配置，都能直接用到这次更新。

如果目前只跑单步对话，也很少处理文件，这个版本带来的变化不会同样明显。我的判断是，v0.6.31 的重点不在让 Agent 显得更聪明，而在让它的执行过程更容易检查、复现和管理。

## 用一次失败任务完成升级验收

升级后，我建议不要先跑顺利的演示流程。挑一个包含 JSON 条件、至少两个分支，并且会生成 PDF、DOCX 或 CSV 的旧任务，再故意提供一个会进入失败分支的输入。

执行结束后，检查完整记录能否定位失败节点，历史回放能否还原分支路径，生成文件能否直接预览。随后打开 Provider 编辑区域，确认凭证展示、连接测试与审计记录是否符合团队的使用要求。

如果任务还包含 Delegate Task，可以跨一个回合或重启后继续检查返回结果。这样跑一遍，v0.6.31 最重要的几项能力就不再是更新列表，而会变成一条可以验收的工作链。
