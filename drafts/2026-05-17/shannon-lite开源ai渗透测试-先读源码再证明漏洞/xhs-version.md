# Shannon Lite 开源 AI 渗透测试，先读源码再证明漏洞

今天 GitHub Trending 里最值得安全团队看的项目，是 KeygraphHQ/shannon。

仓库描述很直接，Shannon Lite is an autonomous, white-box AI pentester for web applications and APIs。

它分析源代码，识别攻击向量，并执行真实利用来证明漏洞。

GitHub API 现在显示 42473 stars、4856 forks，AGPL-3.0 License。今天 trending 抓到日增 +335。

这不是普通 SAST，也不是 AI 帮你看代码的聊天工具。

它的关键词是 white-box pentester 和 prove vulnerabilities。

## 和 SAST 最大区别

传统 SAST 做静态分析。

它扫描代码，找危险函数、数据流、依赖漏洞、规则命中，然后给你一堆 findings。

问题是误报多，安全工程师要花很多时间判断哪个真的能打。

Shannon 的定位更进一步。

它先读源代码，理解应用和 API，再识别攻击路径，最后尝试执行真实利用来证明漏洞。

这里的「证明」很关键。

一个扫描器说这里可能 SQL injection，和一个工具给出可复现 PoC，证明这条路径真的能拿到不该拿的数据，优先级完全不同。

前者是提示。

后者是证据。

## 为什么 white-box 重要

黑盒扫描从外部打应用，只能看到接口行为。

它不知道代码里有哪些隐藏路由，不知道权限判断写在哪里，也不知道某个参数最后流向哪个数据库查询。

白盒扫描能读源码。

它可以从路由表开始，沿着 controller、service、repository 往下追，看到权限中间件、数据校验、ORM 查询、文件读写、外部 API 调用。

AI 的价值在这里不是懂安全术语，而是能把代码语义和攻击路径连起来。

## 适合谁用

1. Web 应用和 API 团队

如果产品有大量后台接口、用户权限、文件上传、支付回调、第三方 webhook，值得试。

2. 安全团队

它可以作为人工渗透前的预扫描，让安全工程师先拿到疑似可利用路径。

3. 开源项目维护者

如果没有专职安全团队，release 前跑一遍，至少能挡住一部分明显问题。

但不要拿它去扫别人的服务。

这类工具只能在你拥有授权的代码和环境里使用。它会尝试真实利用，越过授权边界就是安全事件。

## 风险也很明确

第一，误伤测试环境。真实利用不是读代码那么温和。

第二，PoC 泄漏。可复现利用链要按敏感信息处理。

第三，误报和漏报仍然存在。AI 读源码不等于万能。

第四，AGPL-3.0 对商业集成有要求，闭源平台接入前要看 license。

## 我的判断

AI 安全工具正在从发现问题，走向证明问题。

过去安全扫描器给开发团队带来的常见感受是噪声。

几十个 high，几百个 medium，最后大家疲劳。

如果 AI 只是把告警写得更像人话，价值有限。

但如果它能把「可能有漏洞」推进到「这里有一条可复现路径，这是请求，这是影响，这是修复建议」，安全和开发之间的协作效率会明显提高。

Shannon 的方向就是这个，先读源码，再证明漏洞。

它不会替代专业渗透测试，但可能改变第一轮筛查和验证的工作量。

## 建议怎么试

先做三层隔离，

代码隔离，只给测试仓库或脱敏仓库
环境隔离，只打 staging 或本地靶场
报告隔离，PoC 输出和漏洞链路按敏感信息管理

评估指标不要只看发现了多少漏洞。

重点看 PoC 可复现率、误报率、单次扫描时间。

AI pentester 的正确位置，是把安全工程师从海量噪声里解放出来，而不是替公司承担授权和责任。
