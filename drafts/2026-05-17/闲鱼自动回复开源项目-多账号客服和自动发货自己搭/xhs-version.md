# 闲鱼自动回复开源项目，多账号客服和自动发货自己搭

今天 GitHub Trending 里有个中文项目挺扎眼，GuDong2003/xianyu-auto-reply-fix。

仓库描述是，闲鱼智能客服系统，支持多账号管理、AI 自动回复、自动发货确认、多渠道消息通知，提供完整 Web 管理后台。

GitHub API 现在显示 1070 stars、250 forks，创建于 2026 年 1 月 24 日。今天 trending 抓到日增 +109。

## 它到底做什么

不是一个简单脚本，而是完整的闲鱼智能客服后台。

核心能力有四块，

1. 多账号管理

很多闲鱼卖家不止一个号。多个账号同时在线，用后台集中看，比每个手机盯一个号轻松很多。

2. AI 自动回复

买家常问的问题高度重复，能不能便宜、几成新、什么时候发货、有没有瑕疵、能不能包邮。真正消耗人的就是这些高频低价值来回。

3. 自动发货确认

对卖虚拟资料、模板、教程这类商品的人来说，付款后的交付流程可以规则化。

4. Web 管理后台

有后台才可能给普通卖家用。只给命令行，很多人根本跑不起来。

## 闲鱼为什么适合 AI 客服

淘宝商家已经有千牛、店小蜜和客服外包。

闲鱼更像半个人半商家的混合市场，卖家要在手机上处理所有消息，但交易又足够频繁。

AI 客服在这里不是为了显得高级，而是为了让一个人能同时管更多货。

比如每天 80 条咨询，其中 60 条都是重复问题。系统先按商品、关键词、上下文给回复草稿，复杂问题再交给人。

它不需要完全替代人，只要挡住 70% 的重复消息就有价值。

## 不要当无风险赚钱机器

这类项目边界很明显。

第一，仓库没有 license。没有明确开源许可，不等于可以随便商业化改卖。

第二，自动化操作平台账号有风险。Playwright、DrissionPage 这类技术可以接管网页行为，但平台风控不会因为项目开源就放行。

第三，AI 自动回复容易说错话。价格、成色、保修、发货时间，都可能变成交易承诺。

所以更适合把它当半自动客服后台，不是全自动老板。

## 推荐用法

先从低风险商品开始。

第一步，只开消息汇总和通知，不开自动发送。

第二步，把商品知识写成固定 FAQ。AI 回复只能引用 FAQ，不要自由发挥。

第三步，设置人工接管词。只要出现退款、投诉、平台介入、真假、保修，自动回复立刻停掉。

第四步，自动发货只用于低争议的数字资料或固定流程商品。

第五步，用测试号跑一周，不要直接上主力号。

自动化的第一目标是少盯手机，不是让账号替你承担所有风险。

## 我的判断

这是一个很典型的中文 AI 自动化项目。

它不讲 AGI，不讲 benchmark。它讲闲鱼、多账号、自动回复、自动发货、消息通知。每个词都对应真实痛点。

未来类似项目会越来越多，小红书矩阵、闲鱼客服、淘宝售前、B 站私信、微信社群、抖音评论，都是高重复、半结构化、有明确收益的场景。

但越贴近交易，越要留人工兜底。

真正能长期跑的副业自动化，不是全自动，而是关键节点有人确认。
