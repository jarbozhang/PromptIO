# 字节又开源了一个 agent 框架，普通开发者能拿来干啥

GitHub trending 5 月 6 日单日 +328 星，bytedance/deer-flow 这个仓库突然冒出来。我翻了下定位写得很直白，long-horizon SuperAgent harness，能做研究、写代码、造网页、出幻灯片、跑视频，单任务从分钟到小时级别都能扛。

不是又一个 demo 项目，是字节把内部跑过的工程结构推到了外面。我自己看完最直观的判断是，这一版本不是给"玩家"的，是给"想真用 agent 做点事"的开发者准备的。

## 我觉得真正能上手的三个点

**第一，六个 IM 渠道直接接好了。** Telegram、Slack、飞书、企业微信、个人微信、钉钉，全部开箱即用。微信走腾讯 iLink 长轮询，企业微信和钉钉走 WebSocket，飞书也是 WebSocket。

放到中国语境，这一条比另外五个组件加起来都直观。你做个客服 agent、内部知识助手、报告生成 bot，部署完直接接到企业微信群里，不用再单独搞一套前端。这是真实生产入口，不是 demo。

**第二，subagents 并行扇出 / 收束。** 主 agent 可以同时起几个子 agent 探索不同方向，每个子 agent 拿独立的 context、独立的工具子集、独立的终止条件，跑完汇总。

研究类任务最容易撞到的墙就是 context 爆炸，子 agent 各自带一份精简上下文回来，等于把"长程"拆成了"多个短程并行 + 一次汇总"。这个思路对长报告、行业研究、多源数据分析特别有用。

**第三，跨会话 memory。** 业界大部分 agent harness 把 memory 当短期上下文，deer-flow 这里做了本地存储、用户私有控制、跨会话保留偏好，去重逻辑专门防止事实重复堆积。

这是国产侧第一次有人在开源 harness 里把"长期记忆"做出来，等于 ChatGPT memory 的工程化复刻，但放在了用户自己机器上。

## 模型选择没把人锁死

默认推荐豆包 Doubao-Seed-2.0-Code，火山引擎 Coding Plan 是官方部署链路。开源端 DeepSeek v3.2 和 Qwen3 全系适配，闭源端 GPT-5 和 Kimi 2.5 也都在矩阵里，OpenRouter 通过 langchain_openai 接口直挂。

字节这次没把模型选择写死，豆包是首选但其他路都留着。这个姿态比某些"必须用我家模型"的国产框架更可信。国内用户可以直接用豆包或 DeepSeek 跑起来，不用纠结访问问题。

## 我的判断

最近一个月我写过的 agent 框架已经 36 篇，openclaw 是工程师工厂，hermes-agent 是策略闭环，Manus 是商业化样本，LangGraph 是底座框架。deer-flow 走的是另一条产线，企业内部研究助手、长程报告生成、私域客服增强，这一条线值得单独跟。

如果你做的是代码生成或自主迭代，老路线还是更合适。但如果你的场景是"接到企业微信里跑一个长任务报告"，deer-flow 就是目前国产开源里最对口的一个。

字节肯出这种级别的工程开源，本身是个信号，国产 agent 框架的开源密度已经追上来了。

## 怎么上手

仓库地址 https://github.com/bytedance/deer-flow，docs 目录里有 DeepSeek v3.2 和 Qwen3 的 vLLM 适配文档。本地起 LocalSandboxProvider 就能跑通最小例子，IM 渠道接入文档也都齐全。建议先用豆包或 DeepSeek 把 demo 跑起来，再决定要不要接到自己的业务里。
