# DeepSeek 开源了内部工程规范：11 套质量门禁怎么接进你的项目

如果你正在用 Coding Agent 改真实项目，这套规范最有用的地方，不是让 Agent 多写几段代码，而是让它知道哪些改动该拦、哪些检查该跑、哪些复杂度该删。

DeepSeek Harness 放出了 11 个工程级 Skill，覆盖代码审查、推送前检查、代码精简、文档同步、Agent 笔记归档和界面验收。对已有仓库来说，不必一次接完，我更建议从四个高频门禁开始。

这份配方的目标很具体。选一个小改动，把审查、验证、精简和文档同步串起来，最后得到一套团队能复用、能检查、也能继续修改的仓库规则。

## 选一个能暴露问题的小改动

我不会拿新建项目验证这套规范。空仓库没有历史包袱，很多门禁看不出价值。

更合适的是找一个已经有人维护的仓库，再挑一项范围明确的改动，例如修复边界条件、调整一个接口、删除重复实现，或者修改会影响使用方式的配置。

任务需要同时满足三点。

- 改动范围能在一次 PR 内讲清
- 仓库已经有测试、检查脚本或人工验收方式
- 失败后容易回退，不碰不可逆的数据变更

我会先记录基线，包括改动文件、现有检查命令、需要同步的文档，以及验收人真正关心的风险。没有这层基线，Agent 很容易把门禁执行成一场形式完整却没有重点的表演。

## 把四道门接到现有流程

第一道用 `dsh-code-review`。它强调按仓库自身标准做语义审查，优先检查正确性、安全边界和生命周期，而不是堆积命名、空行之类的细碎意见。

接入时，我会把仓库现有的贡献规范、测试约定和高风险目录交给 Agent，并要求输出阻断项、建议项和对应文件。重点不是意见数量，而是它能否指出会改变行为的具体问题。

第二道用 `dsh-pre-push-checks`。它主张只运行与当前改动相关的最小检查，避免每次机械执行全部测试。

这里不要让 Agent 自由猜命令。把仓库已经存在的 lint、类型检查、单元测试和构建入口列出来，再让它根据改动范围选择。Agent 还应说明为什么选这些检查，以及哪些范围没有覆盖。

第三道用 `dsh-find-simplifications`。它负责寻找过度设计、死代码和重复实现，并把结果整理成正式提案。

我会把它放在功能正确之后。过早追求精简，可能把必要的兼容逻辑当成冗余。提案至少要写清删除对象、行为是否变化、验证方法和回退方式，通过评审后再改代码。

第四道在改动影响使用方式时启用 `dsh-doc-site-sync`。它把文档站视为源文件的投影，避免代码已经变化，文档仍维护另一套说法。

仓库还公开了 `dsh-doc-standards`、`dsh-prose-standard`、`dsh-translate-docs` 和 `dsh-trim-cot-leakage`。它们分别处理文档结构、技术文字约束、双语术语一致性，以及清理推理过程和审查痕迹。文档较重的项目可以继续叠加，但不必在第一次验证时全部启用。

## 用验收结果判断门禁是否有效

四个 Skill 跑完不代表接入成功。真正的验收对象，是这次改动有没有变得更容易判断。

我会检查下面这张验收单。

- 代码审查是否指出具体行为风险，而非只给风格建议
- 推送前检查是否覆盖本次改动，又没有无理由扩大范围
- 精简提案是否区分必要复杂度与过度设计
- 文档是否跟随源文件变化，没有形成第二套事实
- 每条阻断意见是否能定位到文件、规则或可复现结果
- 人工评审是否能否决 Agent 的错误判断，并把原因沉淀回规则

这里有个很重要的提醒。讨论中有人指出，Skill 只是文字提示，仓库本身不会自动让 Agent 变成资深工程师。真正难复制的是数据闭环和人工反馈。

我认同这个判断。成熟团队的规则可以借，但优先级、风险目录和验收口径必须来自你自己的项目。否则 Agent 只是更有条理地执行了一套不适合当前仓库的标准。

## 避开四个常见接入坑

最常见的坑，是把 11 个 Skill 一次全部塞进 Agent。规则过多会增加冲突，也会让你无法判断是哪一道门真正改善了结果。

第二个坑，是把 `dsh-find-simplifications` 当成自动删代码工具。它更适合产出提案，再由测试和人工评审决定是否落地。

第三个坑，是让 Agent 自己定义仓库标准。DeepSeek 提供的是工程纪律的表达方式，不是你项目的业务边界。权限、数据、兼容性和生命周期规则仍要由维护者明确。

第四个坑，是只看 Agent 的文字报告。涉及界面的 PR，仓库还提供了 `record-browser-gif`，要求用真实浏览器录制交互 GIF。它传递的原则很实用，验收行为证据比阅读完成声明更可靠。

把第一次接入控制在一个 PR 内。只启用代码审查、相关检查、精简提案和文档同步，保存 Agent 的错误判断与人工修正。下一轮真正该增加的，不是更多 Skill，而是你们自己的反馈记录。
