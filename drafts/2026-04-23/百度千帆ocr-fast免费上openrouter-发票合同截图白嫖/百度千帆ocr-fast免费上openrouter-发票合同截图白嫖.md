# 百度千帆 OCR 居然免费扔到 OpenRouter 上了，我拿一张皱巴巴的报销发票试了试

百度的 OCR 这次终于做对了一件事，把它免费扔出来。

不是 30 天试用，不是注册送 100 万 token，是 OpenRouter 上 input 0 美元、output 0 美元的那种免费。

我刚刚拿一张被钱包压了三天的餐饮发票，斜着拍了一张手机照片，扔进去，30 秒拿到结构化结果。

## 这模型到底是个什么

模型名 baidu/qianfan-ocr-fast:free，4 月 20 号上的 OpenRouter，65536 context，多模态，吃图片+文本，吐文本。

OpenRouter 页面上写得很直白，domain-specific multimodal large model purpose-built for OCR。翻译一下，就是不装通用大模型，专门干 OCR 这一件事，是 Qianfan-OCR 的升级版。

我本来对国产模型上 OpenRouter 这件事是有偏见的。之前小米 MiMo、智谱、零一这些上来都是带价签的，便宜归便宜，但你跑量还是要花钱。

千帆这次直接 0 价签。

我反复刷新了三次模型详情页，确认 input pricing 是 \$0/M tokens，output pricing 也是 \$0/M tokens，一行红色的 Free variant 标在那里。

说实话我第一反应是 OpenRouter 数据没刷出来。

## 我是怎么试的

OpenRouter 调用流程跟 OpenAI 完全一样，把 base_url 换成 openrouter.ai，model 填 baidu/qianfan-ocr-fast:free，图片 base64 塞进 messages 里 image_url 字段，结束。

第一张测试图，我拿的是上周吃火锅的纸质发票，揉皱了，反光，斜 15 度拍。

返回结果里，发票代码、发票号码、开票日期、金额大写小写、销售方名称，全部抽出来了，连那个被油渍盖住一半的纳税人识别号都猜对了。

我愣了三秒。

第二张，一份 5 页 PDF 合同截图，A4 整页中文密密麻麻，里面有表格。

千帆把表格直接转成了 markdown 表格语法，| 分隔符、表头、对齐一个不少，正文部分顺着段落给出，章节编号没乱。

第三张，我故意拿了一个截图，是 B 站某个评论区的截图，混着颜文字、emoji、错位的回复缩进。这种"非文档"的图，纯 OCR 模型最容易翻车。

千帆把文字部分抠得干净，颜文字它没识别（这正常），但错位的回复结构它居然按楼层分了行。

## 跟 GPT-4o vision、Qwen-VL、豆包视觉横评

这是大家最想看的部分。

GPT-4o vision，中文发票的关键字段精度持平千帆，但贵。一次调用大约 0.01 美元起步，跑 1000 张就是 10 刀，且偶尔会"自作聪明"地补全你没拍清楚的字段（这个是 OCR 大忌）。

Qwen-VL（阿里云通义千问视觉版），中文准确率非常顶，跟千帆五五开，但要走阿里云控制台 + AccessKey，配置麻烦。免费额度有，但跑量要付钱。

豆包视觉（字节），中文 OCR 我一直觉得是国产里最稳的，准确率隐约还高半档，但豆包目前没上 OpenRouter，要走火山引擎自己的 API，国内开发者方便国外开发者难受。

千帆 OCR-Fast 在 OpenRouter 上的位置很尴尬地舒服，准确率不是最顶，但够用，调用最方便，价格地板。

我的判断是，对于"非生产关键路径、量大、能接受 95% 准确率"的场景，这模型是当下中文 OCR 的最优解。

## 5 个我已经在想着用的场景

第一，个人报销发票批量识别。每个月攒一沓发票，拍照上传 → 自动出 Excel。以前我用免费的 OCR API 每月就 500 次额度，现在直接管够。

第二，合同关键条款抽取。把合同截图扔进去，让它转 markdown 后再喂 GPT-4 抽关键条款（违约金、付款周期、续约条件），OCR 这一段成本归零。

第三，纸质表格转 Excel。装修预算、调研问卷、手抄菜单，拍照后让模型先转 markdown 表格，再用 pandas 处理。

第四，截图搜文字。微信聊天截图、PPT 截图、PDF 截图，扔进去拿到纯文本，再用关键词检索。我个人最痛的场景，是找不到"那个谁说过的某句话在哪张截图里"。

第五，扫描简历入库。HR 朋友天天处理几十份扫描简历，跑批 → 抽姓名学校公司 → 入库。以前付费 OCR 一份几分钱，一年下来不少钱，现在这块成本直接归零。

## 几个坑

得说清楚，免费不等于无限制。

OpenRouter 的 :free 模型有全局限速，BYOK 用户有日 1000 次免费调用，普通账户更少，跑大批量你还是得排队。

64K context 听起来很大，但 OCR 输出动辄上千 token，单次调用别贪心扔 20 张图，老老实实一张一张来。

模型对印章、手写体、低分辨率截图（小于 500px 宽）依然会翻车，这是当前所有 OCR 模型的共同短板，不是千帆的问题。

还有一点，免费模型 OpenRouter 可能用你的 prompt 做训练数据（具体看 OR 的 free model policy），合同、身份证这种敏感数据慎用，自己评估风险。

## 我的判断

国产模型免费上 OpenRouter，这是第一次。

Mistral 当年放过 7B 免费版本，但那是开源权重你自己拉去本地跑，不是 hosted。Llama 系列也类似。Hosted 的、不要 API key、不要充值、直接 OpenRouter 调用拿到结果的免费模型，千帆 OCR-Fast 是国产里第一个走得这么远的。

百度过去几年在大模型叙事里被骂得最惨，文心一言上线时被群嘲，千帆平台被吐槽难用。但 OCR 这条路他们走了十几年，技术底子是真的厚，这次把吃饭的家伙免费扔出来，我觉得是想清楚了，OCR 已经不是模型差异化的核心战场，但能撑场子、能换流量、能让开发者重新装个千帆账号。

值得换。

至少把它存进你的 OpenRouter 模型列表，下一次需要 OCR 的时候，先试它，再考虑别的。
