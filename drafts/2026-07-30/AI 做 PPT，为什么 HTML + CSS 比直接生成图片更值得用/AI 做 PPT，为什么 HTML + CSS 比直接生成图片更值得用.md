# AI 做 PPT，为什么 HTML + CSS 比直接生成图片更值得用

如果你做完 PPT 还要改标题、换数据、调版式，决定效率的就不只是第一次生成得多漂亮，而是修改时要不要推倒重来。

看完 @dotey 分享的两个真实方案后，我会把 AI 生成 PPT 的中间格式选成 HTML + CSS。它不一定是最省事的起点，却更能同时照顾视觉效果、可编辑性和原生 PPTX 交付。

这不是图片与代码谁更高级的问题，而是创作者究竟在交付一张定稿，还是一份会反复修改的演示文稿。

## 要做的决策不是选模型，而是选中间格式

@dotey 做过两个受到关注的 PPT Skill。baoyu-slide-deck 走纯图片路线，baoyu-design 则用 HTML 设计，并能转换成原生 PPTX。

两种方案都能得到完整页面，但它们服务的是不同阶段。纯图片更接近一次性成稿，画面确定后，文字、图形和布局已经合成在一起。HTML 则保留了页面结构，标题、段落、图片和装饰仍是可以分别处理的对象。

很多人选方案时先问 Claude Opus 和 GPT 谁做得更漂亮。我更愿意先问另一句，这份 PPT 在交付前还会改多少次。

只要答案不是零，中间格式就比第一次生成速度更重要。

## 用美观度判断自由度够不够

自己设计一套专用中间格式，看起来最可控。问题是，格式里的组件、属性和组合方式通常有限，模型也没有围绕这套私人语法接受过丰富训练。

结果往往是页面很规整，却只能在有限风格里排列组合。你可以继续扩展组件，但维护成本也会跟着增长。

HTML + CSS 的优势来自模型对它足够熟悉。排版层级、留白、色彩、图片位置和装饰关系，都可以通过成熟的表达方式组合。@dotey 的判断是，Claude Opus 生成 HTML 的视觉效果很好，HTML 因而很适合作为中间格式。

在他展示的工作流里，Claude Code 配合 Opus 4.8 负责设计，再由 baoyu-image-gen Skill 调用 Codex 生成画面素材。他还提到，在美观程度上 Opus 的表现更合他的要求，而 GPT 的图像模型适合配合完成配图。

这里真正有用的不是模型排名，而是分工思路。页面设计和画面生成可以由不同能力承担，中间用 HTML 把它们组织起来。

## 用可编辑性判断返工会不会失控

图片成稿适合内容稳定、只需要展示的页面。它的麻烦通常在第二轮修改后出现。

客户改一句标题，演讲者替换一个数字，品牌方要求移动一张图。对图片方案来说，这些看似局部的调整可能需要重新生成整页，还要面对新旧版本在字体、间距和构图上的漂移。

HTML 方案保留了修改入口。文字可以单独改，布局可以重新计算，图片也能替换。对经常改稿的人来说，这种结构化不是附加功能，而是交付能力的一部分。

我会把选择标准压缩成一句话。一次性视觉稿可以优先考虑图片，持续迭代的演示文稿应该优先保留结构。

## 用 PPTX 成本判断约束该加在哪里

自由 HTML 能把设计空间打开，但自由度越高，转换成原生 PPTX 时越难保证每个元素都能对应过去。浏览器能表达的效果，远多于 PPTX 原生对象能够稳定承接的效果。

所以 @dotey 给出的折中不是放弃 HTML，而是使用受约束的 HTML + CSS。设计阶段仍然沿用模型熟悉的语言，同时限制那些难以映射到 PPTX 的写法。

他用 baoyu-design Skill 制作的示例可以接近 1 比 1 转成 PPTX，并表示转换没有问题。这条路径把冲突放在了正确的位置。不是先造一套模型陌生的格式，而是在 HTML 上增加面向交付的边界。

这种约束会牺牲一部分任意表达，却换来原生元素、后续编辑和稳定转换。对于需要把文件交给同事、客户继续修改的人，这笔交换很划算。

## 哪些人适合选不同方案

纯图片更适合内容已经确定、页面数量有限、交付物只需要观看的场景。它追求的是快速得到完整视觉结果，不承担长期编辑任务。

自由 HTML 更适合网页演示、设计探索和视觉提案。它给模型最大的发挥空间，但如果终点必须是原生 PPTX，就要提前评估转换损耗。

受约束的 HTML + CSS 更适合频繁改稿、多人协作和必须交付原生 PPTX 的创作者。它不是三个维度都做到无限，而是在美观、编辑和转换之间取得更实用的平衡。

成本也不该脱离使用频率讨论。@dotey 的判断是，如果不是每天大量制作，不同方案的成本差别不大，效果更值得优先考虑。源材料没有提供具体费用，因此真正可执行的比较方式，是拿同一份内容分别生成一页，再检查修改和转换是否符合自己的交付要求。

## 我的选择是受约束的 HTML + CSS

如果只是做一张发布后不再修改的页面，我会接受图片方案。只要任务叫 PPT，而且后面大概率有人要改，我会选择受约束的 HTML + CSS。

理由很直接。图片把决定封在像素里，自定义格式把能力封在组件里，受约束的 HTML 则把模型熟悉的设计语言和 PPTX 的交付边界接在了一起。

验证时也不需要先做完整套稿。找一页同时包含标题、正文、配图和装饰元素的内容，用 baoyu-design 生成并转成 PPTX，再亲手改一次文字、替换一次图片、移动一次元素。改得动，版式没有明显变化，这条工作流才真正适合你。

AI 做 PPT 的关键选择，不是让第一稿看起来像成品，而是让第七稿仍然改得下去。
