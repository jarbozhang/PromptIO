# 40 个 Marketing Skills 能不能替代增长顾问？独立开发者先用它做一次落地页体检

我最想拿 Marketing Skills 跑的，不是宏大的增长战略，而是一件很小的事，给一个没人负责增长的独立产品做落地页体检。

因为这类产品最尴尬。功能已经做出来了，首页也上线了，但访客看完没感觉，创始人自己又很难判断，是定位没讲清，价格没说服力，还是按钮文案太像临时写的。

Corey Haines 开源的 marketingskills，刚好把这个缺口切得很具体。它不是一个独立 SaaS，而是 40 多个 Markdown skills，可以塞进 Claude Code 或 Cursor，让模型按增长顾问的工作方式处理产品定位、CRO、定价、launch、SEO、onboarding、流失预防、A/B 测试、cold email 等任务。

## 先把产品定位交代清楚

我会把它想成一次低成本的增长顾问预演，而不是直接把顾问这件事替代掉。

它的关键入口是 product-marketing。也就是先把产品、用户、定位、使用场景填进去，再让后面的技能基于这份上下文输出建议。

这一步很重要。很多人用 AI 写营销建议，得到的东西空，是因为一上来就问“帮我优化落地页”。模型不知道你卖给谁，不知道用户为什么犹豫，也不知道你想让访客做什么动作。

marketingskills 的设计更像是先建立一份增长上下文。后面跑 CRO、pricing、launch 或 SEO 技能时，不是每次重新猜，而是围绕同一个产品判断。

这也是它对独立开发者最有价值的地方。你不用先写一份漂亮的品牌手册，只要把产品和用户讲明白，它就能进入具体任务。

## 让它进入一次真实的落地页体检

我会从一个很常见的场景开始。

一个独立开发者做了一个 B2B 小工具，首页有一句主标题、三段功能介绍、一个价格入口和一个注册按钮。问题是访问量不算少，但转化一直上不去。

如果找增长顾问，第一轮通常会问很多基础问题，目标客户是谁，用户现在怎么解决，购买阻力在哪里，首屏有没有说清收益，CTA 是否对准了用户当下的心理状态。

marketingskills 能进入流程的地方，就在这里。

先填 product-marketing，让它知道产品卖给谁。再跑 CRO 审计，让它按转化路径拆页面。接着可以继续跑 pricing，看当前套餐有没有把价值锚点讲清楚。最后再补一个 launch 或 SEO 技能，把页面改动和获客入口接上。

这个链条里，AI 不再只是“帮我改文案”。它更像一个会连续追问的增长实习合伙人，先建立上下文，再进入不同工位。

我认为这比单独找模型写十版标题更接近真实工作流。增长建议最怕散，每个建议看着都对，但放在一起互相打架。统一上下文之后，至少能减少这种漂移。

## 交付物从灵感变成待办

一个好的落地页体检，最后不应该只给你一堆“可以优化”的句子。

它应该变成几类交付物。

产品定位会变成更清楚的目标用户和购买理由。CRO 会变成首屏、社会证明、CTA、异议处理、表单路径的修改建议。定价会变成套餐表达、价值锚点和试用入口的取舍。launch 或 SEO 会变成后续获客页面该补什么内容。

这就是 marketingskills 的现实价值。它不保证你增长变好，但它能把“我感觉页面不对”变成一批可以排优先级的改动。

我会优先看四个交付物。

- 一版更清楚的首屏主张，能让目标用户在几秒内知道产品帮他省什么麻烦
- 一组转化阻力清单，指出用户为什么可能不点注册或不看价格
- 一版价格页表达建议，把功能堆叠改成价值判断
- 一个发布或 SEO 后续动作，让页面修改不只停在页面里

这几项不需要假装成完整咨询报告。对独立开发者来说，够用了。因为真正的瓶颈往往不是缺一份 80 页方案，而是缺一个能推动下周改版的明确输入。

## 别把它当成增长自动驾驶

我对这类工具的判断比较克制。

它适合替代一部分前期诊断、文案发散、页面审计和计划拆解，不适合替代最终业务判断。

原因很简单。它不知道你的真实转化数据，不知道用户访谈里那些细节，也无法替你判断某个渠道的机会成本。源材料里提到它已经被不少 bootstrapped 团队验证，但具体到你的产品，仍然要用自己的页面、价格和用户反馈验证。

所以我不会把它包装成“增长顾问平替”。更准确的用法是，在你还没准备好请顾问、也不想让 AI 继续输出空话时，先让它把增长工作的第一轮拆出来。

这对小团队反而更实际。你可以把 marketingskills 放进 Claude Code 或 Cursor，把产品上下文补齐，然后让它先审一个页面，而不是一次性规划整家公司未来半年的增长。

## 我会这样复用这套流程

如果你也在做独立产品，我建议从一个最小闭环开始。

选一个已经上线的落地页。别选还没定方向的新想法，也别选功能太复杂的整站。只选一个用户能完成明确动作的页面，比如注册、预约、试用、下载或查看价格。

然后按这个顺序跑。

product-marketing 先写清产品、用户、定位和转化目标。CRO 接着审页面，找首屏、CTA、信任感和异议处理的问题。pricing 用来检查套餐表达，不要急着让它直接改价格。launch 或 SEO 放在最后，用来决定页面改完后该从哪里拿第一批流量。

这条路径的好处是，它不会把你拖进一堆概念。你拿到的应该是一份页面改版输入，而不是一篇看完点头、关掉就忘的增长作文。

我的下一步会很具体。找一个正在跑流量但转化一般的页面，先让它产出一版 CRO 审计，再挑 3 个改动上线验证。

如果这 3 个改动都无法落地，问题不一定在工具，可能是你的产品定位还没有写到足够具体。
