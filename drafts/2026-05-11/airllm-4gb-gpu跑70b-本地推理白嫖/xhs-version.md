# 单张 4GB 游戏卡跑 70B 大模型，AirLLM 一夜回到 GitHub Trending

今早刷 GitHub Trending，看到 AirLLM 又冒出来了，单日 +89 stars。

这项目我有印象，2024 年火过一阵，作者 lyogavin 是个中国开发者。当时卖点就一句话，单张 4GB GPU 跑 70B 模型。沉了大半年，今天又被推上首页。

我去翻了 README 又跑了一下，想搞清楚一件事，这玩意儿是真能"白嫖"，还是只是凑合能跑给你看。

## 它是怎么把 70B 塞进 4GB 的

正常加载一个 70B 模型，光权重就要 140GB，4bit 量化也要 35GB 起步。一张 4090 是 24GB，A100 也只有 40GB/80GB 两档。普通人手里的 1650、3060 12G、甚至笔记本集显，从硬件参数看根本不该参与这件事。

AirLLM 的思路是分层加载。把 70B 模型拆成一层一层的 transformer block，每次只把一层搬到 GPU 上算，算完就丢掉，再加载下一层。整个模型权重平时躺在硬盘和 CPU 内存里，GPU 显存只需要装下当前这一层加上中间激活值。

所以 4GB 显存只是瞬时占用，不是持有整个模型。

它还做了几件事，4bit/8bit 分块量化、flash attention 加速、prefetching 把下一层的加载和当前层的计算重叠起来。作者声称结合 4bit 量化能拿到 3x 推理加速。

支持的模型范围很全，Llama2/3/3.1（405B 也覆盖了，官方说 8GB 显存就能跑）、Qwen、ChatGLM、Baichuan、Mistral、InternLM。装一行 `pip install airllm`，调 API 跟 transformers 几乎一样。

## 代价是速度，而且代价很大

这是我必须告诉你的。

分层加载省下的显存不是免费的。每次推理都要把模型从硬盘反复搬到 GPU，70B 模型有 80 层，生成一个 token 就要把 80 层全过一遍。硬盘如果是 SATA SSD 或者机械盘，每 token 的延迟会让你怀疑人生。

社区里零星反馈是，单 4GB 卡 + NVMe 跑 70B，大概是每个 token 几秒到十几秒。对话场景下生成 200 个 token，可能要等十分钟。

所以 AirLLM 的真实定位不是日常对话工具，是"我想在自己破卡上验证一下这个 70B 模型的输出长什么样"。批量跑离线任务勉强能用，实时交互基本告别。

质量上倒没什么损失，分层加载只是改了执行顺序，权重数学上等价，4bit 量化的精度损失是公认的可接受范围。

## 国内本地推理玩家手里其实有一整条路线

把 AirLLM 放回国内本地推理的版图里看，它是这条路线上一个特定生态位的工具。

显卡够好（4090/A100/H100），直接 vLLM，包括蚂蚁开源的 vLLM Ascend 分支，适配国产昇腾卡。

显卡一般（3060 12G、4070、Mac M 系列），llama.cpp 是事实标准，GGUF 量化生态最成熟，Ollama 套了个壳让你 `ollama run qwen2.5:32b` 一行命令搞定。

显卡很差（4GB / 集显 / 老笔记本），这就是 AirLLM 的位置。它接受了速度极慢作为代价，换回硬件门槛归零。

这几条路线没有谁干掉谁的关系，AirLLM 解决的是"我硬件实在不行但就是想本地跑"这个具体场景，跟 vLLM 各自擅长不同的硬件区间。

## 我的判断

AirLLM 不是真的能白嫖，是"用速度换显存"。这两件事不一样。

如果你目标是日常用 70B 跑对话、做 agent、生成代码，AirLLM 不适合你，老老实实本地装 Ollama 跑个 14B/32B 的 Qwen。

但有三种情况 AirLLM 值得装：

一是学习用途，想亲手摸一下 70B 模型内部结构，理解 transformer 分层加载的工程实现，源码不长，是个好的研究对象。

二是离线批处理，你有一批不需要实时的任务（几千篇文档标注、长文本摘要），让它在后台慢慢跑一晚上。

三是验证场景，你手头有个 70B 微调权重，想在自己的卡上跑两个 prompt 看输出对不对，再决定要不要花钱租 A100 部署。

至于这次回归 trending，我的看法是模型权重越发越大（最近一堆 100B+ 开源模型）加上显卡市场没明显变便宜，两件事撞在一起。lyogavin 这个项目踩中了"模型膨胀速度 > 硬件普及速度"的缺口，只要这个缺口还在，AirLLM 就会周期性回到大家视野里。

想试的话，找一个空闲的晚上，`pip install airllm`，下一个 Qwen2.5-72B 的权重，写一行 generate 调用，然后去睡觉。早上起来看输出。这是最适合 AirLLM 的工作流。
