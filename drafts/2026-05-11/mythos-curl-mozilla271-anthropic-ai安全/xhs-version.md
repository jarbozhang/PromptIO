# Anthropic Mythos 在 curl 这边翻车了，但 curl 作者最后一句话才是重点

5 天前 Mozilla 官方说用 Anthropic Mythos 在 Firefox 找到 271 个零日漏洞，几乎无误报。今天 curl 作者 Daniel Stenberg 自己写了一篇 blog 回应同一个工具递过来的 5 条报告。

结果是 5 进 1。4 条要么是误报、要么不是安全问题、要么早就被 curl 现有防御挡掉了。剩下 1 条作为低危 CVE 进入 6 月底的 curl 8.21.0。

Stenberg 的原话是"这次围绕这个模型的炒作主要是营销"。但同一篇 blog 的最后他写了另一句话，对国内开源维护者更重要，我下面会讲。

## 为什么 Firefox 和 curl 给出两份完全不同的答卷

我自己读完两边的材料，结论是 Mythos 的天花板不在模型，在被测代码的成熟度。

Firefox 是浏览器引擎，攻击面巨大、历史代码厚、跨 C++/Rust/JS 边界多，Mythos 一扫就出 271 个，因为可挖的东西本来就堆在那里。Simon Willison 给的数字更直观，Firefox 2025 年月均修 20 到 30 个漏洞，2026 年 4 月单月修了 423 个。

curl 是单一职责的 HTTP 客户端，Stenberg 团队二十年把能想到的 fuzz、静态分析、模糊测试全跑过了，留给 AI 的缝隙窄得多。HTTP/1、TLS、URL 解析这些重点防御过的地方，Mythos 一个问题都没找到。

所以这不是 Mythos 不行，是 curl 自己已经太干净。

## 社区两边的声音差着一个数量级

r/BetterOffline 把 Stenberg 的"营销噱头"原话顶到 197 赞，"看吧 Mythos 也就这样"的情绪很重。

但同一时间 r/technology 上 Mozilla 271 漏洞的帖子有 2416 赞 205 评，普通用户的关注点和 hacker 圈完全不在一个频道。

我个人觉得 Magonia 那篇分析最值得国内安全团队读一遍。核心论点是写过十年检测逻辑的人都知道，漏洞数量从来不是关键指标，可被利用性和爆炸半径才是。271 个 bug 听上去吓人，但绝大多数是 Firefox 多层防御已经能挡住的 attack surface。

另一边 GitHub 上 24 小时内就出现了一个 OpenMythos 复刻仓库，号称用公开研究文献从第一性原理复刻架构。代码质量先放一边，至少说明社区对 Mythos 工作流的兴趣已经溢出。

## 我的判断和那句被忽略的话

Stenberg 在挨完一份营销噱头报告之后，自己在 blog 末尾写了这段。

"不在你的项目里用 AI 代码分析器，就是把时间和机会留给对手和攻击者去发现并利用你没发现的缺陷。"

这是 curl 作者亲口说的。所以国内做开源大项目的团队，OpenSSL/Nginx 镜像维护方、字节阿里腾讯的开源组、华为鸿蒙开源组件，我的判断分两层。

第一层，代码审计不再是要不要做 AI 辅助，是用哪一家。Stenberg 这种被 AI 报告烦透了的人都这么说，还在纯手工 review 的团队再不动差距只会拉大。

第二层，工具链可以国产化。智谱在企业版里上了类似 Codex Sec 的代码安全扫描，阿里通义灵码的安全扫描接入了集团 CVE 库，奇安信和奇虎都有 LLM 驱动的 SAST 产品，豆包代码的扫描虽然偏 lint 但企业内部知识库路径已经跑通。openclaw 生态的 clawhub 上也有几个安全审计相关的 prompt 集合可以直接拿。

这些工具不一定有 Mythos 的强度，但 Mozilla 那份"几乎无误报"已经把门槛立在那里，国产厂商看到目标了。

## 行动建议

如果你在维护开源项目或做企业代码审计，这几件事这周可以动手。

- 升级机器上的 curl 到 8.21.0 之后的版本，6 月底发布。影响所有依赖 libcurl 的 Python requests、PHP cURL、Node http 调用，国内 CDN 厂商的 origin fetch 也几乎都走 libcurl
- 把 Stenberg 的那篇 blog 读完，比任何二手解读都值得，搜 daniel haxx blog mythos 就能找到
- 选一款国产 AI 代码扫描工具跑一次你在维护的中等规模仓库，挑一个 PR 让模型 review，看看 finding 里有几条真的需要修。这是最便宜的 baseline 校准

最后讲清楚那个隐性成本。curl 团队复核 5 条报告要几个小时，Firefox 271 条能跑通是因为 Mozilla 内部有一整套 triage 工具链。国内中小开源团队照搬时第一个要建的不是模型接入，是"AI 报告进来之后谁来确认"的人力流程。没这一环，模型再准也会变成 noise generator。

5 天里 Mozilla 和 curl 给出了 Mythos 的两种答卷，但都指向同一个事实，AI 漏洞挖掘已经从实验性能力变成应该接入的常规工具链。剩下的问题不是用不用，是用哪家、怎么 verify、谁负责 triage。
