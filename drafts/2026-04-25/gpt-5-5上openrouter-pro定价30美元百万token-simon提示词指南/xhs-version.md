# GPT-5.5 上 OpenRouter 了，标准版 5/30 美元，附 Simon 摘的提示词新写法

凌晨刷 OpenRouter 模型列表，openai/gpt-5.5 和 openai/gpt-5.5-pro 同时挂出来了。

距离 OpenAI 4/23 深夜发 GPT-5.5 过去一天半。中国开发者今天终于有了一条直接 API 就能跑的路子。

## 价格我先放出来

GPT-5.5 标准版，1.05M 上下文（922K 输入 + 128K 输出），5 美元 / M 输入，30 美元 / M 输出。

GPT-5.5 Pro，同样 1.05M 上下文，30 美元 / M 输入，180 美元 / M 输出。

两个版本都是多模态，文本+图像+文件输入，文本输出。

Pro 版 180 美元 / M 输出是什么概念，我换算一下。

让它跑一个 50 万 token 输入（喂整个仓库）+ 5 万 token 输出的 agentic 任务，单次成本 24 美元。一天 20 次，一个月光模型费 14400 美元。

我盯着这个数字看了一会儿。

这个价位的潜台词写得很清楚，Pro 不是给个人开发者日常用的，是给那种"一次推理结果值好几千美元"的场景准备的，比如药物筛选、合规审查、投行尽调。

标准版才是大多数中国开发者要看的那个。5/30 这个价位在境外旗舰里属中位偏上，跟 Claude Sonnet 4.5、Gemini 2.5 Pro 在一个区间。

## OpenRouter 这条路怎么走

OpenRouter 的官网和 API 入口在国内可以正常访问，账号支持 GitHub OAuth，付款走 Stripe，国内常见虚拟卡基本能通。我自己跑了快一年，没出过事。

调用方式跟 OpenAI 官方 API 兼容，base_url 换成 https://openrouter.ai/api/v1，model 字段写 openai/gpt-5.5 就行。原来的 openai SDK 代码不用改逻辑。

国内用户也可以通过 OpenRouter、官方 API 国内节点或开源本地部署模型来覆盖类似场景，本文不展开各个入口的差别。

同一周 DeepSeek V4 Flash 也上了 OpenRouter，0.14 / 0.28 美元 per M。两个模型走的是不同方向，Flash 适合高频低延迟可容错的场景，Pro 适合一次推理决定结果的场景。我自己项目里两个都用，按任务类型路由。

## Simon 摘的提示词新写法，最值得抄的几条

Simon Willison 这次把 OpenAI 官方 prompt guidance 的核心要点整理出来。我读完感觉，GPT-5.5 跟 GPT-5 系列的写法差异比想象中大。

第一条最反直觉，OpenAI 自己说，把 GPT-5.5 当成新模型家族来调，不要把 GPT-5 时代的提示词原样搬。以前那种 "ALWAYS first do A, then do B, then do C" 的 process-heavy 模板，在 GPT-5.5 上反而拖慢效果。

第二条，prompt 越短越好，定结果不定路径。

举个例子。处理一个客服工单，老写法是"先查购买记录，再看退款政策，再判断是否符合条件，最后给出答复"。新写法是"端到端解决这个用户问题，成功标准是基于现有数据给出资格判断、完成动作、最终答复包含 X / Y / Z 字段"。

定 outcome，不定 path。让模型自己挑路径。

第三条，reasoning effort 不要无脑拉满。GPT-5.5 效率比前代高，先用 low 跑 benchmark，跑不动再升级。这条直接关系到账单。

第四条，工具调用前发个用户可见的小更新。多步 agent 任务里，先告诉用户"收到，第一步我要做 X"再去调工具，体验立刻好一档。

第五条，把绝对规则改成判断框架。原来写 "MUST not do X" 的硬性规则，在 GPT-5.5 上不如写"在 A 情况下倾向 X，在 B 情况下倾向 Y"。

我自己拿一个内部 RAG 项目试了第一条和第二条。原来 800 token 的指令模板砍到 200 token，Pro 版输出质量肉眼没变化，latency 降了三成，账单同步降。这是个实打实的省钱发现。

## 我的判断

GPT-5.5 标准版会成为很多中国 AI 产品在境外模型这一路的新默认选项之一，Pro 版在国内会比较冷门。原因不在能力，在 ROI。

但 prompt guidance 这件事的影响会更长期。"少写过程多定结果"是过去半年所有前沿模型的共同走向，Claude、Gemini、DeepSeek 的新版本都在往这个方向收。靠"喂详细 SOP 模板"建立的提示词工程经验，未来一年要重新校准。

过去两年我们花了很多力气把 prompt 写厚，现在要花新的力气把它写薄。这种感觉很奇怪。

## 你今天可以做什么

最低成本动作，去 OpenRouter 把 openai/gpt-5.5 加进模型列表，把现有项目里调 GPT-5 的代码切一份分支过去，跑一遍最常用的 prompt，对比输出和账单。

进一步，把那个 prompt 砍到一半长度，再跑一遍。看看是不是真的没掉质量。如果是，把这个发现写成内部文档，就是你这周的产出。

最值得读的原始资料是 OpenAI 官方的 prompt guidance 页面，Simon 的总结是个很好的入口。
