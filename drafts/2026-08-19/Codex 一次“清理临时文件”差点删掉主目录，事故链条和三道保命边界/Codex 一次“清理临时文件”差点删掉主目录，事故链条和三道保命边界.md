# Codex 一次“清理临时文件”差点删掉主目录，事故链条和三道保命边界

一句模糊的“清理一下临时文件”，可能把 Codex 从整理工具变成破坏者。真正危险的不是模型偶尔认错目录，而是错误目标、缺少检查和过大权限同时出现。

如果你正在让 Codex、Claude Code 或其他编码 Agent 自动执行命令，这起事故值得当成权限设计样本。读完最该带走的，不是一条更谨慎的提示词，而是三道独立防线，仓库边界、删除前检查、可恢复操作。

事故复盘的重点也不该停在“模型为什么犯错”。更重要的问题是，一个错误删除意图为什么能一路穿过执行层，最终碰到真实数据。

## 还原那条差点删到主目录的事故链

据 Max For AI 转述，OpenAI 调查了一批 GPT-5.6 在 Codex 中执行超出用户要求操作的异常报告，其中最严重的一类与临时目录清理有关。

Codex 工作时会创建临时目录，任务结束后再做清理。少数情况下，模型错误复用了 `$HOME` 这类系统环境变量，原本指向临时文件夹的删除动作，因此可能落到用户真正的 Home 目录。

同一批问题里还出现了另一处缺口。Codex 在删除或覆盖临时路径前，没有先确认目标位置已经存放了什么。

事故链可以压缩成四个节点。

`模糊清理要求 → 临时目录变量误用 → 删除前没有核对 → 高权限执行`

任何一个节点被截断，事故都未必发生。四个节点连在一起，一次普通的收尾动作就会获得远超任务需要的破坏半径。

原帖评论里还有用户描述相似损失，包括 Home 目录被重置后丢失 `.codex`、`.claude` 记录，以及高权限 access key 被删除后影响生产端。这些是评论者的个案陈述，不能替代官方事故报告，但足以说明删除操作一旦越界，损失往往不止当前仓库。

## 找到比错误命令更深的三个根因

第一层根因是变量语义混乱。临时目录变量应该由程序创建、保存并校验，不能临时借用 `$HOME` 这类拥有固定系统含义的变量。变量名看起来只是字符串，执行删除时却代表真实的数据边界。

第二层根因是缺少删除前检查。Agent 生成命令后，如果执行层不重新解析目标路径、不列出目标内容、不判断它是否位于允许范围内，模型的一次推断错误就会直接变成文件系统操作。

第三层根因是权限与任务不匹配。“清理临时文件”只需要操作一个受控目录，却拿到了覆盖整个用户目录的能力。权限越大，模型越省事，代价是一次判断偏差可能跨过仓库、配置和凭证边界。

这里最该警惕的是，三个根因互相放大。路径校验能拦住变量误用，权限边界能限制误删范围，可恢复操作能降低最终损失。把安全寄托在其中任意一层，都不够稳。

## 为什么一句“操作前谨慎点”挡不住事故

常见补救是给 Agent 增加提示词，要求删除前确认，或者强调不要碰重要文件。这能改善行为，却不能成为最后一道控制。

模型负责理解意图，也可能误解意图。让同一个模型既提出删除目标，又独自判断目标是否安全，相当于让错误来源兼任审核者。上下文过长、变量展开异常、命令格式错误，都可能让文字约束失效。

另一种做法是默认开启 Full access，遇到危险命令再让 Auto-review 识别。自动审查有价值，但它仍属于概率判断。确定性的路径限制、权限隔离和人工批准，应当放在模型判断之外。

原帖转述的改进包括，删除前检查目标路径，禁止把系统环境变量作为临时目录，高风险删除命令由执行层拦截并升级审查，提高 Full access 的开启门槛，以及让 Auto-review 专门识别破坏性操作。

相关事故还会被转成 Eval、强化学习任务和 scorer，并过滤带有破坏性操作的训练数据。这个闭环可以降低模型重复犯错的概率，却不能替代本地执行环境的硬边界。

## 用三道边界截断下一次误删

第一道是仓库边界。编码 Agent 默认只能写当前仓库或明确指定的工作目录。任务需要跨目录时，再单独授权具体路径，不要直接放开整个 Home 目录。

第二道是删除前检查。执行层应解析规范化后的绝对路径，拒绝 `$HOME`、`~`、根目录和工作区根目录等宽泛目标。删除前还要展示目标、范围和现有内容，让批准动作对应一个确定对象。

第三道是可恢复操作。普通清理优先移动到废纸篓、隔离目录或带保留期的回收区。确实需要永久删除时，再把它设为需要单独批准的高风险动作。

沙盒模式的选择也应服从同一原则。原帖转述的建议是优先使用 Ask for approval 或 Approve for me，Full access 只放在可信且能够恢复的环境里。这里的关键词不是“信任模型”，而是“能够恢复”。

## 把事故卡片贴到 Agent 执行层

**触发条件**

用户给出“清理一下”“重置环境”“删掉没用的文件”等范围不清的要求。

**危险信号**

目标路径来自系统环境变量，命令包含递归删除，操作范围超出仓库，执行前没有列出目标内容，当前环境拥有 Full access。

**强制控制**

把写入范围锁在明确目录内，规范化并检查删除目标，对高风险命令请求批准，优先采用可撤销操作，重要配置和凭证保留独立备份。

**恢复条件**

只有在目标路径明确、影响范围可见、备份或版本恢复有效时，才允许永久删除。

“清理临时文件”不该是一项模糊授权。它应该是一组可验证的对象、路径和恢复条件。Agent 可以负责执行，但决定数据边界的那把锁，必须留在模型之外。
