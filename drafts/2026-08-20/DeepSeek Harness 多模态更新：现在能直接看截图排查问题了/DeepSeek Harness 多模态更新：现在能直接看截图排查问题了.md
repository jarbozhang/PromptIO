# DeepSeek Harness 多模态更新：现在能直接看截图排查问题了

如果你经常让 Coding Agent 排查页面问题，这次 DeepSeek Harness 的更新值得关注。以前截图通常停在工作区里，模型拿到的可能只是路径或 OCR 文本，现在图片可以正式进入上下文和工具循环。

最直接的变化，是你能把页面截图、报错画面或设计稿交给 Agent，让它结合代码继续定位问题。对前端开发者、设计工程团队和桌面 Agent 开发者来说，图片不再是流程之外的附件。

我更关注的不是“Agent 有眼睛了”这句宣传，而是图片如何被保存、传递和清理。这里决定了视觉任务能不能跑过一轮演示，真正进入长任务。

## 旧流程为什么经常卡在截图这里

文本 Agent 遇到图片时，常见处理方式是读取文件路径、调用 OCR，或者先用其他工具把画面转成文字。文字能告诉模型按钮上写了什么，却可能丢掉布局、间距、遮挡和视觉层级。

页面诊断尤其依赖这些关系。弹窗有没有盖住按钮，移动端标题是否换行异常，设计稿里的留白是否被压缩，都不是一段 OCR 文本能完整表达的。

另一个麻烦来自工具循环。即使某个工具成功读取了图片，结果也要以模型能理解的形式回到下一轮请求，否则 Agent 仍然无法把视觉信息和代码修改连起来。

## 看懂这次更新改动了哪一层

8 月 19 日披露的更新为 `llm-deepseek` 增加多模态请求支持。`read_image` 可以读取工作区里的 PNG、JPEG、WebP 和 GIF 文件。

图片读取后不会只留下文件路径，也不会被简单压成 OCR 文本。DeepSeek Harness 会把文件放进 Attachment Store，再生成真正的 ImageBlock，作为 Tool Result 的一部分返回。

下一轮模型请求会带上这个 ImageBlock。于是一次完整循环变成了读取截图、把图片加入工具结果、连同上下文再次请求模型、继续检查代码或调用工具。

这次变化发生在 Harness 层，而不只是模型名称旁边多了一个“视觉”标签。Harness 负责管理文件、工具结果和上下文，模型负责消费它收到的内容。最终视觉能力能到什么程度，仍取决于后端模型与处理链路，不能只凭接口接通就推断识图质量。

## 把长任务里的图片负担控制住

截图进入上下文后，新的问题马上出现。Agent 连续排查十几个页面状态，每轮都携带全部旧图，请求体会越来越大。

DeepSeek Harness 为单次请求累计图片载荷设置了 20 MiB 上限。图片继续增加时，系统会优先从请求中移出较早的图片，避免几十轮任务被历史截图拖住。

这里的关键区别是从请求中 offload，并不等于图片从工作区消失。按照源材料描述，这项策略关注的是控制后续请求携带的图片数量，让最近的视觉证据优先留在上下文里。

我的判断很明确。接入图片只是第一步，能管理图片生命周期，才是多模态 Agent 从演示走向工作流的信号。视觉上下文如果没有预算和淘汰策略，很快就会变成新的上下文债务。

## 用三个任务判断它是否适合你的流程

页面截图诊断最容易验证。准备一个存在明确布局问题的测试页面，截取异常状态，让 Agent 指出可见问题并定位可能相关的组件或样式文件。验收重点不是描述得像不像，而是它能否把画面证据连到代码位置。

设计稿检查适合验证空间关系。给出目标图和当前实现图，观察 Agent 能否识别间距、对齐、换行和遮挡差异。涉及精确像素时，仍应保留人工或视觉回归工具复核，不能把自然语言判断直接当成验收结果。

报错画面排查则能测试工具循环。让 Agent 阅读包含错误提示的截图，再检查日志和代码。这个场景可以看出它是在复述画面文字，还是能够把图片信息与后续工具调用串起来。

评论讨论里也出现了一个合理质疑。如果底层模型没有原生视觉能力，Harness 层接入图片究竟是在传递真实视觉输入，还是把 OCR 与像素分析自动化。现有材料能够确认图片进入 Attachment Store、ImageBlock 和请求上下文，但不足以证明所有后端都拥有同等视觉能力。

因此，适合立即验证的人，是已经在工作流中频繁交换截图，并且能明确检查输出对错的开发者。只需要处理纯文本仓库的人，不必因为“多模态”三个字立刻调整流程。

## 把第一次验证压到一张截图

选一张问题足够明确的测试截图，放进独立工作区，让 DeepSeek Harness 读取它，并要求输出可见问题、关联文件和修改建议。全程保留原图、模型响应与代码差异。

如果它只能读出文字，没有识别布局关系，说明当前链路更接近自动化图像解析。如果它能稳定把视觉问题定位到代码，并在修改后复查新截图，这项更新才真正进入你的交付流程。

别急着堆二十张图。一张截图能否完成“看见、定位、修改、复查”的闭环，比多模态标签更有判断价值。
