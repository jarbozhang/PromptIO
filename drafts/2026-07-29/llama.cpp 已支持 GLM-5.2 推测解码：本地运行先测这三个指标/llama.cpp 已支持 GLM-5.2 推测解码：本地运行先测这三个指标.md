# llama.cpp 已支持 GLM-5.2 推测解码：本地运行先测这三个指标

如果你正在本地运行 GLM-5.2，这次 llama.cpp 更新值得关注。它加入了 NextN/MTP 推测解码支持，目标不是改变模型回答什么，而是减少生成过程里的等待。

但我不会只看每秒生成多少 token。一次有用的本地测试，至少要同时记录首字延迟、生成速度和内存占用，否则很容易把局部提速误判成整体体验改善。

下面这套测试不依赖特定显卡，也不要求更换现有部署方案。保留当前可运行的环境，只切换 MTP，就能得到一组适合自己机器的前后对照。

## 把测试压缩成一个固定任务

llama.cpp 这次为 GLM-5.2 的 GLM_DSA 模型加入了 NextN/MTP 推测解码，可以通过 `--spec-type draft-mtp` 使用目标模型中的 NextN 张量。转换环节也新增了 `--mtp` 和 `--no-mtp` 导出控制。

NextN/MTP 可以理解为模型在生成当前 token 时，同时提出后续若干 token 的候选。主模型再验证这些候选，验证通过的部分可以成批接受，从而减少逐个 token 推进带来的等待。

它对两个阶段的影响并不相同。提示词处理仍然要完成，推测解码主要作用于后续生成。因此，我会选择一个生成长度足够、内容又容易重复执行的任务，例如让模型根据固定材料输出一份结构化技术方案。

测试输入需要锁定以下条件。

- 使用同一个 GLM-5.2 模型文件和同一量化版本
- 使用完全相同的提示词
- 固定上下文长度、生成上限和采样配置
- 保持相同的 CPU、GPU 与卸载设置
- 关闭其他明显占用算力或显存的任务
- 每种模式预热一次，再分别运行至少三轮

短到只生成一句话的提示词不适合这次比较。生成阶段太短，进程启动、模型加载和提示词处理产生的波动会盖住 MTP 的效果。

## 只改一个开关跑两组

基准组沿用当前已经能稳定运行的 llama.cpp 启动方式，并确保转换产物没有启用 MTP。实验组保持其余参数不变，在转换时保留 MTP 数据，并使用 `--spec-type draft-mtp` 启动推测解码。

操作路径可以压缩为四步。

1. 保存基准组的完整启动命令、模型文件校验信息和运行日志。
2. 用 `--mtp` 导出支持 MTP 的 GLM-5.2 文件，避免误用 `--no-mtp` 产物。
3. 在相同提示词下分别运行普通生成与 `draft-mtp` 模式。
4. 把每轮首字时间、完成时间、输出 token 数和峰值内存写进同一张记录表。

这里不要同时调整线程数、批处理大小或 GPU 卸载层数。参数一起变化后，即使速度上升，也无法判断收益究竟来自 MTP，还是来自计算资源配置。

我还会保存两组实际输出。推测解码按设计会验证候选，但基准测试仍应检查输出是否完整、是否异常截断，以及固定采样条件下是否出现明显偏离。速度数据不能替代结果检查。

## 用三个指标决定是否保留

首字延迟是从提交提示词到收到第一个输出 token 的时间。它最接近聊天场景里的等待感，但不应被当成 MTP 的唯一成绩，因为提示词处理和首次运行的缓存状态都会影响它。

生成速度用输出 token 数除以生成阶段耗时，记录为 tokens/s。不要把模型加载时间混进来，也不要只抄某一轮的最高值。我更愿意看三轮以上的中位数，它能削弱偶发抖动的影响。

内存占用记录运行期间的峰值。CPU 环境看进程峰值内存，GPU 后端同时看显存峰值。MTP 能否带来值得保留的收益，取决于速度提升有没有挤掉本来就紧张的上下文空间。

建议把验收表保留成下面四列。

| 模式 | 首字延迟 | 生成速度 | 峰值内存 |
| --- | --- | --- | --- |
| 普通生成 | 多轮中位数 | 多轮中位数 | 运行峰值 |
| `draft-mtp` | 多轮中位数 | 多轮中位数 | 运行峰值 |

我的判断很直接。聊天应用优先看首字延迟，长文和代码生成优先看持续生成速度，内存接近上限的机器则把峰值占用设为硬约束。三个指标没有统一权重，真正的验收标准取决于你要交付的场景。

## 排除四种假提速

最常见的误差不是算法，而是测试条件悄悄变了。

- 首轮和热缓存轮混在一起，加载与缓存差异被算成推测解码收益
- 两组生成长度不同，只比较总耗时，没有换算生成速度
- MTP 导出状态不一致，启动参数写了，模型产物却没有对应数据
- 为避免内存不足临时降低上下文或卸载配置，破坏了单变量对照

还要警惕平均值掩盖波动。三轮里一轮特别快、两轮明显变慢时，平均值可能依然好看。把每轮原始数据留下，优先比较中位数，并观察最慢一轮是否影响实际交互。

信息来自 llama.cpp 的 GitHub release。该版本明确提供 GLM-5.2 NextN/MTP 支持及相关导出开关，但没有给出适用于所有硬件的统一性能数字。对本地部署来说，最有价值的结论只能来自同一台机器上的单变量对照。

建一份固定提示词和记录表，先跑普通生成，再只打开 `draft-mtp`。三个数字放在一起，你就能决定这项能力是该进入常用配置，还是继续留在实验配置里。
