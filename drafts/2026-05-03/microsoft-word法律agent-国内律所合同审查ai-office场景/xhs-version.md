# Microsoft Word 把法律 Agent 塞进来了，国内律所等得起吗

5 月 1 日，Microsoft 在 Word 里推出了一个叫 Legal Agent 的新功能。不是对话框，也不是右键"AI 改写"，是专门为法律团队打造的 agent，跑在律师每天都要打开的 Word 文档里。

负责人 Sumit Chauhan 是 Microsoft Office 的 corporate VP，他说这个 agent "不靠通用模型，而是按真实法律实务塑造出来的结构化工作流，去处理那些定义清楚、可重复的任务，比如对照 playbook 一条一条审合同条款"。

翻译成人话，就是不让 AI 给你输出一段"建议修改第 3 条"的散文，而是把审合同拆成一套规则化流程，每一步都对回到法律团队自己定义的标准上。

## 这个 agent 具体能干什么

按 The Verge 拿到的描述，Legal Agent 至少有三个能力。

第一，直接处理带 tracked changes 的 Word 文档。律师都知道这意味着什么，谁删了谁加了谁批注了，是法律工作的基础语言。一个连 tracked changes 都读不了的 AI，在律所根本落不了地。

第二，分析合同往返修改的 negotiation history。谁在哪个版本让了步，对方在哪一轮加回了什么条款，这是谈判阶段最重要的上下文。Legal Agent 能追这条线，意味着它是带历史记忆的工作流参与者，不是单文档处理器。

第三，按 playbook 逐条审查合同条款。这是律师最日常的活，拿到对方草拟的合同，对照事务所或甲方公司的 playbook，一条一条过。哪些条款必须有，哪些绝不能让，哪些可以谈，Microsoft 把这个动作做成了 agent 的标准能力。

## 海外律师怎么看

Reddit 上有一位律师评论说，他们事务所早就在用 AI 审合同了，"但很糟糕"，因为 AI"过度偏向 vendor 一方"。

这个评论揭示了一个事实，海外律所早就把通用 AI 接进合同审查流了，但没人满意。原因很简单，AI 没有 playbook，没有事务所的立场，只能给出一个平均化的"中立"建议，结果就是放过了对自己客户不利的条款。

Microsoft 这次把 playbook 作为一等公民，AI 按事务所的立场去审，才有可能审出真正有价值的红线，而不是一份"你说得对他说得也有道理"的废话。

那位律师还提了一个判断，这个产品对第三方法律软件是"生存威胁"。Ironclad、LinkSquares 这些公司过去几年讲的故事就是合同审查 AI，现在 Microsoft 直接打包进 365 订阅，律所单独买第三方工具的理由就变薄了。

## 国内律所的处境

国内律师每天用的是 WPS 或腾讯文档，国内文档 AI 目前能选的是 WPS AI 和腾讯文档 AI 这类通用助手。我去看了一下两家的功能描述，主要是文档总结、写作辅助、内容润色、智能问答，没有看到合同条款 playbook 比对、tracked changes 分析、negotiation history 这种法律垂直能力。

这是定位差距。Microsoft 把 Legal Agent 单独立项，给出法律垂直功能。国内文档 AI 的定位是"文档生产力提升"，律师拿来用，能用，但要让它按事务所的合同审查标准去跑，需要自己做 prompt 工程。

国内合同审查 AI 赛道并不是空白，幂律智能、法天使这些垂直公司在做。但这些工具是独立产品，不在律师每天打开的那个 WPS 里，律师得切换工具，把合同复制粘贴过去再粘回来。Microsoft 的核心优势就是它在 Word 这个律师不会离开的入口里。

## 法务/律师现在可以做什么

Office 365 在国内有正规渠道，外资所和跨国所里有不少企业客户。如果你的事务所已经是 Office 365 客户，可以联系 Microsoft 国内合作伙伴问 Legal Agent 的可用区域和上线时间，目前原报道没有给出具体 rollout 时间表。

英文合同为主的律师可以优先关注，跨境业务场景大概率是首发支持的。中文合同的处理质量我没看到第一手测试数据，建议谨慎评估。

国内律所更现实的路径是观察 WPS AI 和腾讯文档 AI 的迭代。两家在底层模型能力上不弱，缺的是"为律师建一套结构化工作流"的产品决策。如果你是律所 IT 或法务总监，现在是去和 WPS、腾讯聊垂直定制的好时机，他们大概率愿意做案例。

不管用哪家工具，有一件事现在就可以开始做，把自己事务所的 playbook 数字化。没有 playbook，再好的 agent 也只能给你输出一份没立场的中立稿，这个工作不依赖任何工具。

## 我的判断

Legal Agent 最重要的不是 Microsoft 又发了个 AI 功能，是它把"垂直行业 agent"的产品形态做了一次明确的示范，不是聊天框，不是 copilot 浮窗，是嵌在工作流里、跟着工作流的真实结构走的 agent。

国内文档 AI 厂商一定会跟这条路径，问题是跟得多快。是真的去和律师事务所谈垂类工作流，还是又做一个通用聊天框贴上"行业版"的标签。

律师这行特别值得做垂类，因为工作流足够结构化，playbook 是现成的，tracked changes 是现成的，合同条款是现成的对象，这些都是 AI agent 最容易切入的地方。如果国内文档 AI 一年内还没出律师垂类版本，那不是技术问题，是产品决策问题。

回到那位 Reddit 律师的话，AI 审合同很糟糕，不是 AI 不行，是没有 playbook 的 AI 不行。Microsoft 想清楚了这件事，国内厂商如果还在按通用 AI 的路子做文档助手，就还在解决错的问题。
