# Uber 4 个月把 2026 全年 AI 预算烧完，国内团队怎么管这笔账

Uber 在 4 月底正式承认，原本规划给 2026 全年的 AI 编码工具预算，已经在前 4 个月被 Claude Code 烧完了。

这条消息在 Hacker News 拿到 398 分，Reddit 三个社区合计 2300+ 分。一条企业 IT 财务新闻能同时引爆这么多地方，因为背后是工程组织在 2026 年集体面对的同一道账单题。

## 账单为什么这么难控制

过去十年，企业开发者工具是席位定价。JetBrains、GitHub Copilot、Cursor，每人每月几十美元封顶，可预测可摊销。

Claude Code 的计费逻辑完全不同。它按 token 计费，和模型选择、上下文长度、agent 自主循环深度直接挂钩。一名工程师让 Claude Code 跑一次大型重构，单次调用消耗 200 万 token 不算夸张。Sonnet 4.5 输入价格 3 美元每百万 token、输出 15 美元每百万 token，单次重构动辄数十美元。

Uber 工程团队规模约 6000 人，人均月度费用区间 500 至 2000 美元，按中位数测算月度支出约 600 万美元。

这就是为什么 4 个月能烧完全年预算。组织没法用席位数封顶预算。

社区一条高赞评论说得很准，预算燃尽曲线本身才是有趣的部分。95% 的月活渗透率说明工具被真正用起来了，企业软件铺开极少出现这个数字。

## 国内大厂为什么没有这个问题

国内主要大厂走的是另一条路。

字节跳动内部主推自研 Seed-Coder 和 Doubao 系列，IDE 集成走豆包 MarsCode 和 Trae，预算结构是自研模型加自有算力，账单形态接近资本开支而不是订阅费。阿里通义灵码、腾讯 CodeBuddy 是同一套思路。

根因有两个。一是数据合规，源代码送到境外 API 在审批上走不通。二是自研模型的边际成本对内是算力成本，不是 API 调用成本，规模化后单位成本远低于外采。

## 中小团队的实操路径

Uber 的账单对没有自研大模型选项的中小团队更有参考价值。

**50 人以下团队，OpenRouter 自计费路径。**

OpenRouter 聚合了 Sonnet 4.5、DeepSeek V3.2、Kimi K2、Qwen3-Max 等模型，按 token 实际消耗计费，单模型可切换。DeepSeek V3.2 输入价格 0.27 美元每百万 token，是 Sonnet 4.5 的十一分之一。复杂任务跑 Sonnet，常规补全跑 DeepSeek，单人月度成本可以控在 200 元人民币以内。工具层用 Aider、Continue、Cline 这类开源 agent 接 OpenRouter Key，预算闸门由 OpenRouter 后台的硬上限完成。

**50 至 500 人团队，企业账户加预算闸门。**

这个规模继续走个人计费会失控，需要走火山方舟、阿里百炼、智谱开放平台或 Anthropic 的企业账户。企业账户能拿到组织级 token quota、按部门拆账、超额自动降级到便宜模型。

预算闸门三个动作，给每个工程师设月度软上限触发后自动从 Sonnet 切到 DeepSeek 或 Qwen3-Coder；把 agent 的 max_iterations 在企业网关层限制在 20 步以内防止失控循环；在 IDE 插件层强制开启缓存命中，长上下文复用率不到 50% 的工程师在 review 流程里被点出来。

## 真正的信号

Uber 的账单暴露了一个组织设计漏洞，token 计费的工具被塞进了席位计费时代设计的 IT 预算流程。预算审批走年度，账单按月走，模型升级按季度走，三个时间尺度互不对齐。

国内大厂未来 12 个月的真实问题不是 Uber 式的预算超支，自研路径已经把这个风险关闭。真实问题是工程组织对外采 SaaS 编码工具的边界要不要松一松。某些非核心仓库比如前端组件库、文档站、测试工具链，源代码不出境的硬约束已经在松动，这部分代码用国产 API 跑得起来吗，预算谁出，合规谁担保，这是接下来几个季度国内 CTO 们的真正议题。

Uber 这张账单的最大价值，是把 2026 年 AI 编码工具的财务真相摆到了所有 CFO 的桌面上。
