# 4GB 显卡跑 70B 模型？国产开发者搞了个极限方案

我手里有一台老笔记本，显卡是 GTX 1650 Ti，显存 4GB。

按常理，这种配置连 7B 模型都跑得吃力，更别说 70B。但今天我刷 GitHub Trending 看到一个项目叫 AirLLM，作者直接告诉你，70B 模型，单卡 4GB 显存，就能跑。

我第一反应是不信，于是去翻了源码。

## 它是什么

AirLLM 是国产开发者 lyogavin（Gavin Li）维护的项目，目前 16.9k star，1.8k fork，今天又上了 Trending。核心做的事情就一件，让显存不够的设备也能跑大模型。

国内能搞到 RTX 4090 的玩家不多，更多人手里其实是 3060 12G、3050 8G、甚至我这种 1650 Ti 4G。租 A100 一小时几十块，玩不起。如果 4GB 显卡真的能跑 70B，对国内大量"显卡被卡脖子"的开发者，意义就不只是技术新鲜，而是真能在自己机器上跑 Llama3.1 405B、Qwen2.5、Mixtral 这一档模型。

## 原理拆解

核心一个词，**分层推理 (layered inference)**，或者叫**权重流式加载**。

模型第一次加载的时候，会被代码拆成一层一层的小文件，存到硬盘上。70B 模型大概 80 层 transformer block，每一层一个独立文件。

推理的时候，显存里**永远只放当前在算的那一层**。算完第 1 层，卸载、第 2 层从硬盘读到显存里，再算，再卸载，再读。一直到第 80 层算完，吐出一个 token。

代价是慢。每生成一个 token，都要把 80 层权重从硬盘搬一遍。70B 在 4bit 量化下大概 35GB，NVMe SSD 理论带宽 5GB/s，光 IO 就要 7 秒一个 token。我个人估计实际速度大概率是**分钟级出一段话**。

所以 AirLLM 不是用来做实时聊天的。

## 我自己跑了一遍

70B 我硬盘空间不够，但我在 1650 Ti 上跑了 7B 的 Qwen2.5 测试链路。

安装很无脑，

```
pip install airllm
```

调用代码也极简，from_pretrained 加载，model.generate 出结果，本质是把 transformers 接口包了一层。

踩坑记录三条，

第一，首次加载特别慢。AirLLM 要把权重重新拆成一层一层的 safetensors，7B 都要 5 分钟，70B 估计 30 分钟起步。

第二，硬盘空间。一份 70B 拆完的副本占 140GB+，加上 HuggingFace 缓存，至少预留 300GB SSD。

第三，支持 4bit / 8bit 量化（用 bitsandbytes），开了量化精度会有损失，作者说量化只在 weights 不在 activations，比传统全量化保留更多精度。

支持的模型挺全，Llama2/3/3.1 405B、ChatGLM、Qwen、Qwen2.5、Baichuan、InternLM、Mistral、Mixtral 都能塞。

## 社区怎么说

GitHub issue 区最高频的问题是"我跑 70B 一个 token 要几分钟，正常吗"，作者回答"是的正常，这是分层加载的固有代价"。

第二高频是"能不能用更多显存换更快速度"，作者加了个参数让你一次缓存几层在显存里，4GB 完全跑得动，8GB 12GB 速度会有明显提升。

知乎有人吐槽这就是"用 IO 换显存"的工程 trick，没什么新东西。我承认原理朴素，但工程的价值有时候就在于**有人真的把它做出来了并且开源了**。

## 我的判断

AirLLM 是一个**定位非常窄、但在那个窄场景里几乎没有替代品**的工具。

想流畅本地聊天，去用 Ollama + Qwen2.5 7B 或 14B，体验比 AirLLM 跑 70B 强太多。

想做 RAG 或 Agent 这种对延迟敏感的应用，更别想，几句话就要等几分钟。

但如果你的需求是"我有一个隐私敏感的离线任务，需要 70B 级别的推理质量，不在乎跑一晚上"，比如本地批处理文档摘要、本地跑代码评审、本地分析私密资料，AirLLM 是我目前看到的唯一一个能让你在消费级显卡上做这件事的方案。

它不会成为主流，但它打破了一个心理门槛，**没有 4090 也能玩 70B**。这件事对"我以为我玩不了大模型"的开发者，比对已经有 H100 集群的人重要得多。

国产开发者愿意花精力维护这种小众但极致的工具，挺难得。

## 行动建议

如果你有 4GB 以上的 N 卡，并且至少 200GB 空闲 SSD，可以这样试，

第一步，pip install airllm。

第二步，先用 Qwen2.5-7B-Instruct 验证链路，跑通了再考虑往上加。

第三步，挑战 70B 就用 Llama3.1-70B 或 Qwen2.5-72B，开 4bit 量化 + model compression，准备让它跑一夜。

最后留个开放问题，**当本地推理的瓶颈从"显存"变成"硬盘 IO"，下一代 PCIe 5.0 NVMe 普及后，消费级硬件本地跑大模型这件事，会不会从"能跑"变成"够用"？**

我自己也还在摸。
