# AirLLM 把 70B 模型塞进单 4GB 显卡，国产开发者把本地推理省钱方案推到极限

我手里有一台老笔记本，显卡是 GTX 1650 Ti，显存 4GB。

按常理，这种配置连 7B 模型都跑得吃力，更别说 70B。但今天我看到一个项目叫 AirLLM，作者直接告诉你，70B 模型，单卡 4GB 显存，就能跑。

我第一反应是不信。

## 为什么我对这事感兴趣

最近在 GitHub Trending 上又冒头一次，今天 +57 星，作者是 lyogavin（Gavin Li），16.9k star，1.8k fork。一个国产开发者维护的项目，悄无声息地把"显存不够就别想本地跑大模型"这条铁律给捅了个窟窿。

我自己之前折腾本地推理的痛点很简单，一是云 API 用着用着就心疼钱，二是想跑 70B 这种级别的模型必须 80G 显存的 A100 起步，租一小时几十块，玩不起。

国内能搞到 RTX 4090 的玩家不多，更多人手里其实就是 3060 12G、3050 8G、甚至我这种 1650 Ti 4G。

如果 AirLLM 真的能让 4GB 显卡跑 70B，那对国内大量"显卡被卡脖子"的开发者来说，意义不止是技术新鲜，而是真的能在自己机器上跑 Llama3.1 405B、Qwen2.5、Mixtral 这一档模型。

## 它到底怎么做到的

我去翻了 README，原理坦率讲并不玄学。

核心一个词，**分层推理 (layered inference)**，或者叫**权重流式加载 (weight streaming)**。

模型在你第一次加载的时候，会先被作者写的代码拆成一层一层的小文件，存到硬盘上。70B 的模型大概有 80 层 transformer block，每一层就是一个独立的文件。

推理的时候，显存里**永远只放当前在算的那一层**。算完第 1 层，把第 1 层卸载、第 2 层从硬盘读到显存里，再算，再卸载，再读第 3 层。一直到第 80 层算完，吐出一个 token。

你想想看，这本质就是把"一次性把整个模型塞进显存"换成了"硬盘当成虚拟显存用"。

那代价是什么？

代价是慢。每生成一个 token，都要把 80 层权重从硬盘搬一遍。70B 模型权重 140GB（FP16）或者 35GB（4bit 量化），就算你用 NVMe SSD，理论带宽 5GB/s，光 IO 就要 7 秒一个 token。这还没算计算时间。

README 没给具体 tokens/s 数字，只说开了 model compression 可以"3x 加速"，但具体多快没明说。我个人估计，速度大概率是**分钟级出一段话**，不是秒级。

所以 AirLLM 不是用来做实时聊天的。

## 我自己模拟跑了一遍

我没有真的跑 70B（硬盘空间不够），但我在 1650 Ti 上跑了 7B 的 Qwen2.5 测试链路。

安装很无脑，

```
pip install airllm
```

调用代码也极简，from_pretrained 加载模型路径，tokenizer 编码输入，model.generate 出结果。本质就是把 transformers 的接口包了一层。

我踩的第一个坑是首次加载特别慢。AirLLM 要把 HuggingFace 下载下来的整块权重重新拆成一层一层的 safetensors，7B 都要 5 分钟，70B 估计 30 分钟起步。

第二个坑是硬盘空间。一份 70B 拆完的副本会占 140GB+ 的硬盘空间，加上 HuggingFace 自己的缓存，你至少要预留 300GB SSD。机械硬盘也能跑，但我估计速度会再降一个数量级。

第三个坑是它支持 4bit / 8bit 量化（用 bitsandbytes），但开了量化之后准确率会有损失，作者说量化只在 weights 不在 activations，比传统全量化保留更多精度。

支持的模型列表挺全，Llama2/3/3.1 405B、ChatGLM、Qwen、Qwen2.5、Baichuan、InternLM、Mistral、Mixtral。基本上你能想到的开源大模型都能往里塞。

## 社区里在说什么

我去翻了 GitHub issue 区，最高频的问题就两个，"我跑 70B 一个 token 要几分钟，正常吗"，作者通常的回答是"是的正常，这是分层加载的固有代价"。

第二高频是"能不能用更多显存换更快速度"，这个是 issue 里反复被提的需求，作者也加了个参数让你可以一次缓存几层在显存里，4GB 完全跑得动，8GB 12GB 速度会有明显提升。

HN 上有用户讨论时提到一个有意思的点，"AirLLM 不是用来替代 vLLM 或 Ollama 的，它是给那些**只能离线、不能联网、又必须本地跑大模型**的场景用的"。我觉得这个定位描述得很准。

知乎上有人吐槽，说这就是"用 IO 换显存"的把戏，没什么新东西。我承认从原理上确实是个朴素的工程 trick，但工程的价值有时候就在于**有人真的把它做出来了并且开源了**。

B 站我还没看到深度的实测视频，估计是因为速度慢到没法做演示。

## 我的判断

我认为 AirLLM 是一个**定位非常窄、但在那个窄场景里几乎没有替代品**的工具。

如果你是想流畅本地聊天，去用 Ollama + Qwen2.5 7B 或 14B，体验比 AirLLM 跑 70B 强一万倍。

如果你是想做 RAG 或 Agent 这种对延迟敏感的应用，更别想，AirLLM 的速度让你几句话就要等几分钟。

但如果你的需求是"我有一个隐私敏感的离线任务，需要 70B 级别的推理质量，不在乎跑一晚上"，比如本地批处理一批文档摘要、本地跑代码评审、本地分析一份私密资料，AirLLM 是我目前看到的唯一一个能让你在消费级显卡上做这件事的方案。

我个人不觉得它会成为主流工具，但它的存在打破了一个心理门槛，**没有 4090 也能玩 70B**。这件事对于"我以为我玩不了大模型"的开发者，比对于已经有 H100 集群的人重要得多。

国产开发者愿意花精力维护这种小众但极致的工具，挺难得的。

## 行动建议

如果你手上有 4GB 以上的 N 卡，并且至少 200GB 空闲 SSD，可以这样试，

第一步，pip install airllm。

第二步，先用一个小模型验证链路，比如 Qwen2.5-7B-Instruct。跑通了再考虑往上加。

第三步，如果想直接挑战 70B，建议挑 Llama3.1-70B 或 Qwen2.5-72B，开 4bit 量化 + model compression。准备好让它跑一夜。

最后一个开放问题留给你思考，**当本地推理的瓶颈从"显存"变成"硬盘 IO"，下一代 PCIe 5.0 NVMe 普及之后，消费级硬件本地跑大模型这件事，会不会从"能跑"变成"够用"？**

我自己也还在摸索。
