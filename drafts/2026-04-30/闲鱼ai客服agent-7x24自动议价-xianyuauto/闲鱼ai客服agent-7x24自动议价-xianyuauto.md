# 一个开源的闲鱼 AI 客服 agent 一夜涨星，7×24 自动议价上下文记忆，副业党要薅羊毛了

我昨晚刷 GitHub Trending，看到一个叫 XianyuAutoAgent 的项目挂在 Python 榜，今天 +48 stars，累计涨到 7.3k。

它就一句话简介，专为闲鱼平台打造的 AI 值守解决方案，7×24 自动化值守，多专家协同，智能议价，上下文感知对话。

我点进去看了五分钟，立刻觉得这事得马上写出来。

因为闲鱼这个生态，是中国 AI 副业党最大的"私域议价场"。一个挂二手手机、二手键盘、原单球鞋的卖家，每天最痛的就是凌晨一点钟有人砍价 80，他不回复就掉权重，回复了就睡不着。这个项目把这个痛点直接接管了。

而且它是国内 LLM 跑国内电商场景，默认通义千问，连 OpenRouter 和翻墙都不需要。落地门槛低到离谱。

## 这个 agent 到底干了什么

我把 README 整个读了一遍，骨架其实就三层。

**第一层是意图分类。** 用户发来一句话，先过一个 classify prompt，判断是议价、技术咨询、无效消息还是一般问询。作者把分类规则写得很细，价格相关词（元、优惠、便宜）走议价 agent，规格相关词（型号、Type-C）走技术 agent，识别到 prompt injection 直接进 no_reply 不回。

**第二层是专家路由。** 议价单独一个 agent，技术问题单独一个 agent，闲聊和物流走 default。每个 agent 有自己的 prompt 文件，互不干扰。

**第三层是上下文记忆。** 一个 context_manager.py 把历史对话拼进 LLM 输入，所以买家半小时前说"能 80 包邮吗"，agent 现在还记得这个底牌。这点在闲鱼场景里特别要命，因为闲鱼买家最爱的就是隔几个小时回来再砍一刀。

我自己在脑子里模拟跑了一次。

挂一个 Kindle，标价 300，底价 240。买家凌晨一点发"老板还在吗？250 出不"。agent 走议价路径，回复"全新少用，最低 270，可小刀"。买家两小时后再来"260 拿"，agent 调出上下文，知道自己已经退到 270，回"可以的，价妥下单立即发"。

这一来一回，按以前我得醒着。

## 议价 prompt 是怎么写的，我读完最佩服的一段

我去翻了它的 prompts 目录，里面四个文件，classify、default、price、tech 各一个。

最值得学的是它对回复风格的硬约束。

**句子控制在 10 字以内，总回复不超 40 字。** 这一句直接把 LLM 那种"您好亲爱的顾客"的客服腔给掐死了。闲鱼买家最反感长句，看到 100 字回复直接拉黑。

**用"全新""可小刀"这种行业黑话。** 不是"价格可商量"，是"小刀"。这是闲鱼老炮儿才知道的词，AI 一开口说"小刀"，对面买家会下意识觉得"这卖家是个老手，砍不动"。

**议价节奏是阶梯降价，不是一次砍到底。** 比如标 300，第一轮报 285，第二轮 275，第三轮触底 270。让买家觉得"砍到了"，又不让卖家亏到底价以下。

**价格已敲定后立刻引导下单。** 一句"价妥可下单，立即发出"，把对话从砍价模式切换到成交模式。这一句话是整个 agent 最值钱的设计，因为大量人工卖家在买家点头之后还在自我感动地多说两句，结果买家又跑去看下一家了。

坦率讲，这套东西比很多花钱买的"闲鱼话术 SOP"训练营还实在。

## 社区里在讨论什么

我翻了 GitHub issue 区，吵得最凶的是两类问题。

**一类是 cookies 怎么稳定。** 这个项目目前还是网页端登录，复制 cookies 字符串到 .env。GitHub issue 区里有人提到大概一周左右要重新登一次，遇到风控会更频繁。这是这套方案目前最大的脆弱点，没有官方 API 就只能这么走。

**另一类是模型选型。** 默认通义千问，但有人在 issue 里反馈说自己换成 DeepSeek-V3 后议价效果反而更狠，因为 DeepSeek 的中文情绪识别更贴近"闲鱼这个语境"。我没亲自验证，但这个方向值得试。配置就是改一行 MODEL_BASE_URL 和 MODEL_NAME 的事。

知乎上闲鱼老玩家提到一个隐忧，AI 客服回得太"标准"，反而会被买家识破。一个真实卖家偶尔会打错字、会半夜不回、会撂一句"睡了明天聊"。AI 永远在线、永远礼貌、永远 10 字以内，这本身就是一种"机器味"。

这个项目作者也注意到了，README 里有个 SIMULATE_HUMAN_TYPING 的开关，模拟人类打字延迟。但我觉得这远远不够。

## 我的判断，可能会得罪一批人

**第一个判断，闲鱼自动议价 agent 普及之后，"人工客服外包"这个副业品类会被打回原形。**

过去半年我在小红书看到过不少帖子，"帮你打理闲鱼店铺，月费 199，24 小时回复"。这种生意的护城河就是"我比你勤快"。当一个开源项目让任何人 30 分钟搭起一个比人工更快、更便宜、更稳定的 agent，这个外包品类的定价权就崩了。这不是危言耸听，是已经发生的事。

**第二个判断，议价 agent 的天花板就是"被算法判定为黄牛号"。**

闲鱼平台不是傻子。一个号 7×24 在线、回复速度永远 2 秒、每条话术都精准卡 40 字以内、底价从来不破，平台风控模型扫一眼就知道这是机器人。轻则限流，重则封号。这个项目目前在 issue 里还没有人深入讨论这个，但它一定会发生。所以我的建议是，把它当"辅助"用，不要全量托管。深夜挂上、白天关掉，留一些"人味儿"的破绽给算法。

**第三个判断，这套架构的真正价值不在闲鱼，在更广的私域议价场景。** 把 prompts 目录里的几个文件改一改，它就是淘宝客服 agent、小红书私信 agent、甚至微信社群里的报价 agent。意图分类、专家路由、上下文记忆这三件套，是国产 LLM 在中文电商场景里第一次被组装得这么干净。

可能有些想法还不成熟，但我看到这个项目时的第一反应是，这事一年内会出十个仿品，五个 SaaS 包装，三个跑路。

## 行动建议

如果你真在闲鱼做副业，今晚就 git clone 一份本地跑起来，先观察它怎么处理你最常被砍的那五个商品。

把 prompts/price_prompt_example.txt 改成你自己的底价和话术风格（仅供学习参考），让 agent 替你跑三天，每天人工 review 一次对话日志。

不要全托管。AI 是助手，不是替身。

如果你不做闲鱼，但做任何"私域聊天 + 报价"的生意，把它的 classify_prompt 那套意图分类思路抄走。这是这个项目里最不显眼、但复用性最强的部分。

回到我开头那个画面。凌晨一点的砍价消息，从此不会再吵醒你。

但你也得问自己一个问题，当连"和买家磨价"这件事都被外包给 AI 之后，你这个卖家，到底还在卖什么。
