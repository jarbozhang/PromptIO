# Codex 操控电脑的三种方式，什么时候用 Computer Use、Chrome 扩展和内置浏览器

给 Codex 分配任务前，最容易浪费时间的一步不是写 prompt，而是选错操控入口。让它处理桌面 App、已登录网页、前端调试，看起来都是操作电脑，实际成本完全不同。

这份决策表只解决一个问题，什么任务该交给 Computer Use、Chrome 扩展或内置浏览器。读完可以直接把自动化任务放到合适入口，减少等待、误点和返工。

结论先放前面，需要账号状态用 Chrome 扩展，需要控制本机 App 用 Computer Use，做开发调试用内置浏览器。有插件或 MCP 能直接完成时，优先走结构化工具。

## 先把任务归到正确入口

| 你要做的事 | 优先入口 | 适合放手到什么程度 |
| --- | --- | --- |
| 操作本机 App | Computer Use | 等待、重复点击、图形界面流程，关键确认留给人 |
| 使用已登录网页 | Chrome 扩展 | 浏览、对比、起草、收集反馈、写入本地文件 |
| 调试本地页面 | 内置浏览器 | 改代码、点页面、截图、复查视觉问题 |

这张表背后的原则很简单，越结构化越优先。插件、MCP、API 能处理的事，别急着让 Codex 看屏幕点按钮。视觉控制适合补缺口，尤其是那些没有可调用接口的界面。

## 操作本机 App，接受慢一点换覆盖面

Computer Use 的优势是覆盖面。它让 Codex 像人一样看屏幕、点鼠标、敲键盘，Spotify、Xcode、系统设置、iOS 模拟器、iPhone Mirroring 这类图形界面都能碰到。

它的短板也清楚，慢。结构化插件能直接调接口，Computer Use 要找按钮、等响应、检查结果，一步步推进。

设备差异也要提前算进去。Mac 上 Codex 可以在后台操作，你继续用电脑；Windows 上它要占前台，任务运行时那台机器基本要让出来。

Jason 的例子很典型。有次他的快递被偷，Amazon 提示客服要等 25 分钟接通，他让 Codex 每五分钟检查一次聊天窗口，客服出现后改成每分钟一次，后面自动完成退款流程。

这个场景适合 Computer Use，不是因为它能替代所有入口，而是因为客服窗口这类流程常常只有图形界面。它适合长等待、低频操作、没有 API 的 App。

## 处理已登录网页，把账号状态交给 Chrome 扩展

Chrome 扩展适合那些离开登录状态就没法做的任务。Gmail、LinkedIn、Salesforce、公司内部后台，关键不是页面长什么样，而是 Codex 能沿用你的 cookies、账号状态和已有标签页。

它还适合跨标签页任务。在一个标签页读信息，到另一个标签页对比，再到第三个标签页整理结果，Chrome 扩展理解的是浏览器上下文，不只是屏幕坐标。

Jason 曾用它跑长期任务，每天检查 X 消息收件箱、浏览新闻、收集反馈，把有价值内容写到本地文件，但不发送任何消息。这个边界很重要。

网页会把 Codex 的点击和表单提交当成你本人操作。研究、浏览、起草可以自动化，发送、发布、付款要留给自己确认。

## 做开发调试，用内置浏览器缩短反馈循环

内置浏览器住在 Codex 对话线程里，你和 Codex 看到同一个渲染页面。它不带登录状态和 cookies，是隔离环境，这反而适合开发。

本地开发服务器、文件预览、公共页面、响应式布局检查、视觉 bug 复现，都更适合在这里跑。Codex 可以改代码、操作页面、截图，再按截图继续修。

Jason 提到的标注功能很关键。你直接在页面元素上点一下，留下“这个层级反了”或“这个按钮间距不够”，Codex 拿着截图和元素上下文去改，再打开同一个页面等下一轮反馈。

它不适合处理账号后台，也不适合需要 cookies 的任务。它适合把开发反馈循环压短。

## 把最后一步留给人确认

这里最容易踩坑的是，把能自动化的任务和该确认的任务混在一起。Codex 能操作界面，不代表所有动作都该让它执行到底。

可收藏的分层清单可以这样记。

- 可以放手，浏览、研究、读取页面、等待窗口状态、收集反馈、写入本地文件。
- 先让它起草，回复内容、表单内容、跨标签页对比结果。
- 必须人工确认，发送、发布、付款。

我的判断是，Computer Use 和 Chrome 扩展越像真人在操作，越要把责任边界写清楚。让它做到确认页之前停下，比事后追查一次误提交便宜得多。

## 用一个最小路径开始验证

不要一上来把整套日常工作都交给它。先选一个低风险任务，让 Codex 证明它能稳定读到状态、保存结果、在关键动作前停住。

- 本机 App，选一个需要等待但不涉及付款或发布的流程，用 Computer Use 跑到确认前。
- 已登录网页，选一个只读任务，用 Chrome 扩展跨标签页收集信息，结果写到本地文件。
- 开发调试，打开本地页面，用内置浏览器标注一个视觉问题，让 Codex 改代码并截图复查。

如果这三个最小任务都跑通，再把频率提高。入口选对了，Codex 才像助手；入口选错了，它只是一个很努力的远程鼠标。
