# Kimi K2.5 重做 Transformer 三块地基：开源团队能学到什么

如果你在做开源模型或 Agent 应用，Kimi K2.5 最值得看的，并不是参数规模，而是它开始改动那些多年没怎么变过的底层组件。

我把杨植麟在 GTC 2026 的分享拆开后，看到三条很清楚的路线。MuonClip 想提高每个 Token 的产出，Kimi Linear 想让长上下文真正参与任务，多 Agent 协作则试图突破单模型串行工作的时间上限。

这三条路线共同指向一个变化。模型竞争正从堆参数，转向重新设计训练效率、记忆方式和任务组织。对开源团队来说，可追赶的入口也因此从算力规模下沉到了代码、消融实验和任务编排。

## 把有限数据变成更高的训练产出

高质量数据很难持续翻倍，但现有优化器未必已经把每个 Token 用到了极致。

月之暗面给出的替代方案是 MuonClip。它基于 Muon 优化器，在参数更新时尽量保持不同方向的信息独立，减少重复更新。演讲披露的实验结果是，在相同数据量下，MuonClip 的训练效果接近把数据量增加一倍。

这条路线真正吸引我的地方，不只是节省训练成本。数据效率一旦提高，原本受数据规模限制的能力上限也可能继续向前移动。

Muon 扩展到万亿参数时并不稳定。注意力层的最大 logit 曾突然升到 1000 以上，而正常范围通常在 50 到 100。月之暗面为此加入 QK-Clip，在前向计算中检查每个注意力头，超过安全范围就同步缩放 Q 和 K 的投影。

按照演讲数据，这套方法支撑了超过 15 万亿 Token 的训练，没有出现一次 loss spike。

开源团队最值得验证的，不是直接复刻超大训练，而是检查三个问题。相同 Token 预算下，MuonClip 能否更快降低验证损失，QK-Clip 在什么阈值开始介入，以及稳定性收益会不会随模型规模变化。

## 让长上下文从容量变成可用记忆

上下文窗口变长，不等于模型真的会使用前面的信息。Agent 连续工作数天时，需要保留已经尝试过的方向、工具返回结果和失败记录。只提供更大的窗口，却不能有效选择和遗忘，任务链依然会断。

标准全注意力的计算量随上下文长度平方增长。上下文扩大十倍，注意力计算可能增加一百倍。百万 Token 级任务很难长期承担这种成本。

Kimi Linear 使用 Kimi Delta Attention，也就是 KDA，让不同信息通道拥有不同的遗忘速度。有些通道负责保存长距离信息，有些通道快速释放空间，吸收新内容。

它也没有彻底放弃全注意力，而是按 3 比 1 混合线性注意力层和全注意力层。杨植麟称，这套架构在短上下文、长输入和长输出任务上都超过了全注意力，长度继续扩展时，效率优势会更加明显。

我认为这里最关键的变化，是模型开始学习如何管理记忆，而不是被动装下更多文本。开源团队验证 Kimi Linear 时，应把重点放在信息利用率上，例如早期约束能否影响很晚出现的决策、无关内容增加后答案是否稳定、长输出是否持续遵守前文要求。

只测模型能否接收百万 Token，很容易把容量误当成能力。

## 把复杂任务的瓶颈移出单模型

MuonClip 和 Kimi Linear 都在增强单个模型，Agent Swarm 则改变了任务的组织方式。

一个主 Agent 负责理解目标和拆分工作，多个子 Agent 并行承担研究、编程、数据分析与事实核查，最终再由主 Agent 汇总。过去需要顺序执行的工作，由此可以同时推进。

难点并不是多开几个 Agent，而是防止协作机制退化。月之暗面设计了实例化奖励、完成奖励和最终结果奖励。前者鼓励拆出可并行任务，中间一项防止生成大量空任务，后一项确保团队真正解决问题。训练前期偏重拆解和完成率，后期逐步提高最终结果的权重。

Kimi K2.5 发布时最多支持 100 个 Agent 并行、执行 1500 个步骤，K2.6 又把并行上限提高到 300 个。数字很醒目，但我更关心并行带来的新成本，包括任务重叠、结果冲突、上下文污染和汇总失真。

开源团队不必从上百个 Agent 起步。更有价值的实验是固定同一个复杂任务，比较单 Agent 串行、少量 Agent 并行和更大规模协作的完成时间、调用成本、重复劳动与最终质量。只有质量没有下降，并行才算真正创造了收益。

## 从一次架构改动看清下一轮竞争

月之暗面还公布了 Attention Residue。标准残差连接主要把上一层输出传给当前层，Attention Residue 则允许当前层从多个前序层中选择信息。为控制成本，实际方案按块组织，例如每 16 层组成一块，块内保留标准残差，块间使用注意力残差。

演讲给出的结果是，大约 8 个块便能获得大部分收益，Token 效率提升约 24%，在 GPQA、MATH 和 HumanEval 等任务上尤其明显。

把这些变化放在一起看，方向已经很明确。Adam、全注意力和残差连接并非不可移动的标准答案，Agent 的串行工作方式同样不是终点。开源模型接下来能否继续逼近前沿水平，很大程度上取决于团队是否愿意重新检查这些默认选项。

我的判断是，开源团队最现实的机会，不在复制一整套庞大系统，而在做出可证伪的小实验。固定数据量比较优化器，固定任务比较上下文利用率，固定预算比较 Agent 并行收益。任何一项跑出稳定增益，都比单纯增加模型规模更有工程价值。
