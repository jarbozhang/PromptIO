# DeepSeek Harness rc.7 值得升级吗：Bash 卡顿修复，插件和任务面板也补齐了

如果你正在用 DeepSeek Harness 跑持续 Bash、长会话或带图片的 Agent 任务，rc.7 是一个值得进入测试环境的版本。

我关心的不是更新项有多少，而是三个会直接打断工作的故障有没有被处理。极简模式每次 Bash 调用约卡 3.5 秒，长历史消息可能触发栈溢出，max-tokens 截断后会话还可能无法继续。

我的升级决定很明确。会升级验证，但不会直接替换正在交付任务的稳定环境。读完这份版本解读，你可以判断自己的痛点是否命中，并把验证范围压到三个真实场景。

## 判断这次更新有没有击中你的旧问题

持续 Bash 的延迟，是 rc.7 最值得关注的修复。

一次调用多等 3.5 秒看起来不算严重，但 Agent 连续执行查看目录、读取文件、运行测试和检查状态时，延迟会不断累加。人等的是一次命令，Agent 等的是整条工具调用链。

原帖给出的变化是，极简模式下的持久 Bash 调用从约 3.5 秒延迟降到几乎可以忽略。这个数字很诱人，但我会把它当作待复现的升级信号，而不是已经适用于所有环境的性能结论。

另外两处修复更偏稳定性。大历史消息分页不再因栈溢出而中断，max-tokens 截断导致会话无法继续的问题也得到处理。对于会持续数十轮、不断追加工具结果的编码 Agent，这两项比新增一个按钮更重要。

## 看懂 rc.7 补齐了哪些工作环节

| 原来的阻塞点 | rc.7 的变化 | 对 Agent 工作流的影响 |
| --- | --- | --- |
| 极简模式持续调用 Bash 时卡顿 | 修复持久 Bash 调用延迟 | 连续命令链有机会变得更顺畅 |
| 长历史消息分页可能栈溢出 | 修复大历史消息分页问题 | 长会话不容易在翻页阶段中断 |
| max-tokens 截断后无法继续 | 修复截断后的续接问题 | 长任务有机会从截断位置继续推进 |
| 子代理任务分散在不同入口 | Codex 与 Claude Code 子代理任务接入 Job Panel | 多任务状态可以集中查看 |
| 图片附件在跨协议或嵌套任务中丢失 | MCP、ACP 支持持久化图片附件，PTC Mode 可转发嵌套图片 | 图像上下文更适合进入多阶段任务 |
| 插件设置入口受限 | 插件可自行注册设置卡片 | 插件配置更容易融入统一界面 |

这次新增的 Job Panel 接入也很实用。Codex 和 Claude Code 子代理任务进入同一个任务面板后，DeepSeek Harness 不再只是聊天与命令入口，也开始承担任务调度视图的角色。

插件可自行注册设置卡片，Cordis 动态插件面板也得到优化。对插件作者来说，配置不必全部挤进通用设置区，插件可以拥有更贴合自身能力的控制入口。

图片附件的变化同样不能忽略。MCP 和 ACP 支持持久化图片附件，PTC Mode 可以继续转发嵌套图片。截图分析、视觉检查和带图子任务最怕上下文经过一层转发就丢失，这次更新正面处理了这条链路。

## 把升级验证压到三个真实场景

我会用同一台机器、同一个测试仓库和相同任务分别跑升级前后版本，重点记录可观察结果，而不是只凭界面手感判断。

第一个场景是持续 Bash。让 Agent 连续执行多次短命令，观察每次调用前的停顿，并记录整条任务链耗时。这里要验证的是高频调用能否保持连贯，不只是第一条命令是否变快。

第二个场景是长会话恢复。准备一段包含大量历史消息和工具结果的会话，让它触发分页与 max-tokens 截断，再检查能否继续提交指令、调用工具和生成结果。能续写文本不等于任务恢复，工具链也要继续工作。

第三个场景是图片跨层传递。通过 MCP 或 ACP 附加图片，再让嵌套任务读取并转发它。验收标准很具体，图片没有丢失、子任务能拿到正确附件、返回主会话后仍能追溯原始上下文。

## 决定谁该升级，谁可以再等等

经常使用极简模式和持续 Bash 的开发者，最适合优先验证 rc.7。你受到的影响频率最高，修复一旦成立，每条 Agent 任务都会受益。

依赖长会话、子代理编排或图片附件的团队也值得跟进。Job Panel、会话续接和图片持久化组合在一起，改善的不是某个孤立功能，而是任务能否从开始走到交付。

如果当前工作主要是短对话和单次命令，没有遇到 Bash 延迟、历史消息中断或附件丢失，可以等待更多验证结果。rc 版本仍适合保留回退路径，尤其不要让正在运行的重要任务承担首次验证成本。

我的判断是，rc.7 的价值不在功能数量，而在它开始修补 Agent 工具最消耗耐心的断点。速度、续接和上下文完整性都不显眼，却共同决定一个 Agent 能不能被持续使用。

我会先复制一个日常任务，在测试环境跑完持续 Bash、长会话恢复和图片传递，再决定是否迁移主工作区。升级决策不需要靠期待，三个场景跑通就够了。
