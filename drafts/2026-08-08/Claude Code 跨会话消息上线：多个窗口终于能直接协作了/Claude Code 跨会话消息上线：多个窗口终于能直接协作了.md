# Claude Code 跨会话消息上线：多个窗口终于能直接协作了

同时开几个 Claude Code 会话并不难，难的是让它们知道彼此正在做什么。一个窗口改接口，另一个窗口补测试，第三个窗口处理文档，任务虽然并行了，上下文却还得靠人来回搬。

Claude Code v2.1.224 加入跨会话消息后，这段搬运工作终于可以交给 Claude。会话可以命名，也能通过自然语言找到其他会话并发送消息，多个终端窗口不再只是各自运行的孤岛。

如果你经常用多个 Git 工作树拆任务，这次更新最直接的收益不是少复制一次内容，而是减少重复解释背景、当前进度和交付边界的成本。

## 结束用长串 ID 找窗口

过去同时跑多个会话，最别扭的地方不是模型能力，而是会话缺少清晰身份。窗口一多，只看一串 session ID，很难立即判断哪个在改后端，哪个在跑测试。

v2.1.224 提供的跨会话协作路径，把这件事拆成了三个动作。

| 原来的阻力 | 新版本的处理方式 | 对并行开发的作用 |
| --- | --- | --- |
| 会话只能靠 ID 区分 | 用 `/rename` 设置易读名称 | 人和 Agent 都能识别任务归属 |
| 不清楚哪些会话可联系 | 通过 `/list-agents` 或 `/peers` 查找 | 减少来回切换终端确认 |
| 任务摘要靠手动复制 | 直接用自然语言要求 Claude 发送 | 把上下文交接留在工作流里 |

这里最关键的是命名。评论里有人提到，session 一多，如果使用者自己都分不清窗口，再聪明的 Agent 也很难准确协作。这个判断很实际，跨会话消息能否好用，取决于会话是否拥有稳定、明确的职责名称。

## 给每个工作树一个任务身份

我更愿意把这项更新理解成并行开发的命名层，而不只是一个聊天功能。

例如，一个仓库可以拆成三个 Git 工作树，分别处理接口、测试和文档。对应的 Claude Code 会话可以命名为 `api-change`、`regression-test` 和 `docs-sync`。名字应该表达任务，而不是使用 `窗口1`、`窗口2` 这种很快就会失去含义的编号。

当接口会话完成字段调整后，可以让 Claude 把下面几类信息发给测试会话。

- 改动涉及哪些文件和接口
- 哪些字段或行为已经变化
- 哪些测试尚未执行
- 当前存在什么不确定项
- 接收方需要完成什么交付

这不是多加一份汇报，而是把交接压缩成一条可追踪的任务摘要。接收会话拿到的不是一句“我改完了”，而是一段能继续工作的上下文。

## 让 Claude 负责寻找和发送

新功能更顺手的地方，在于使用者不一定要亲自查找目标 ID。按照原帖展示的流程，可以直接用自然语言告诉 Claude，把当前任务摘要发给指定会话。

Claude 会查找可到达的会话，识别目标，再组织消息内容并发送。原来由人完成的查 ID、切窗口、复制内容和补充说明，被收进了一次指令里。

我的判断是，跨会话通信真正改善的不是发送速度，而是并行任务的闭环。过去多个会话只是同时工作，现在它们开始具备主动交接的条件。对 Agent 应用也有一个直接启发，多 Agent 协作不只需要任务拆分，还需要可识别的角色、结构化的交接内容和明确的接收对象。

不过，消息能发出去不等于协作一定正确。任务名称含糊、摘要缺少验收条件，仍然会让接收会话走偏。通信层解决的是信息送达，任务边界依旧需要人来设计。

## 判断谁该升级验证

这次更新更适合已经在使用多个 Claude Code 会话的人，尤其是下面几类场景。

同时维护多个 Git 工作树，需要让不同任务及时同步接口变化。一个会话负责实现，另一个会话专门审查或补测试。长任务被拆到多个终端执行，人工转述已经成为明显负担。

如果你通常只开一个会话，这项能力暂时不会改变太多。反过来，如果你每天都在几个窗口之间复制进度，v2.1.224 已经值得进入验证范围。

目前来源信息显示，跨会话消息需要 Claude Code 版本不低于 v2.1.224，支持 macOS、Linux 和 WSL 2，原生 Windows 暂未支持。功能和平台状态可能继续调整，使用前应核对官方文档与当前版本说明。

最合适的验证方式，是选一个可回退的测试仓库，创建两个职责明确的工作树，为会话命名，再让其中一个会话向另一个发送包含改动文件、完成状态和待办事项的任务摘要。只要接收会话能据此继续工作，这次升级就已经替你省下了一轮上下文复述。
