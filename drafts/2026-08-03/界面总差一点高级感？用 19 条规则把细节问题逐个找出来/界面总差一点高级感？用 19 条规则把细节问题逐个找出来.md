# 界面总差一点高级感？用 19 条规则把细节问题逐个找出来

页面功能都能用，配色也没有明显问题，可成品总像差了一口气。这种差距往往不在某个醒目的设计亮点，而在圆角、图标、热区、动效和状态反馈同时偏了一点。

这套来自 Make Interfaces Feel Better 的审查方法，适合正在打磨产品页面的设计师和独立开发者。它把模糊的“高级感”拆成 19 条可以定位、修改和验收的规则。

最实用的地方，不是照着清单做一次美化，而是把它变成固定审查流程。每次只检查一个真实页面，留下位置、改法和验证结果，细节问题才不会在下一版重新出现。

## 选一个状态足够多的真实页面

不要拿静态展示页开工。选择一个同时包含卡片、按钮、图片、动态数字和加载状态的页面，例如控制台首页、文件列表或内容编辑器。

审查范围也要锁住。只处理这个页面及其直接组件，并继续使用项目原有的样式方案。Tailwind 项目就用 Tailwind，CSS Modules 项目就沿用 CSS Modules，不为一次润色引入第二套体系。

准备阶段保留四份材料。

- 页面正常状态截图
- hover、focus、active 状态截图
- loading、empty 和内容加载完成后的截图
- 浏览器动画面板中的慢速回放记录

这一步决定审查能否落地。没有状态截图，后面的判断很容易退化成“看起来应该改一点”。

## 沿着五个区域逐项排查

第一轮看表面与布局，这里最容易产生“哪里不对，但说不清”的感觉。

- 检查同心圆角，外层圆角应等于内层圆角加内边距
- 检查视觉对齐，图标侧内边距可按观感减少约 2px，播放三角形可以略向右移
- 区分层级与结构，阴影负责深度，边框留给分割、选中和聚焦
- 给图片增加 1px 低透明度内缩描边，亮色模式用纯黑，暗色模式用纯白，避免带色调的近黑污染底色
- 测量点击区域，触屏至少 44×44px，密集桌面界面至少 40×40px，扩展后的热区不能互相覆盖

第二轮把动画降到 10% 速度。全速播放时只是隐约别扭的地方，慢下来后通常会暴露为突然跳动、方向不连贯或反馈缺失。

- 交互动画使用可中断的 CSS transition，一次性序列再用 keyframes
- 低频入场按语义分块，并以约 100ms 交错，高频悬停和键入不加动画
- 退场比入场更弱，可采用较短的 150ms 和小幅固定偏移，并使用 ease-out
- 情境图标可从 scale 0.25、opacity 0、blur 4px 过渡到正常状态，spring 的 bounce 设为 0
- 按压反馈使用 scale(0.96)，不要低于 0.95，并提供关闭动效的 static prop
- 页面加载时可用 initial={false} 跳过无意义入场，但要确认没有破坏原本需要的出现过程
- 动效不能成为唯一反馈，颜色、图标或文字至少保留一种静态提示

第三轮检查文字和数字。标题不超过 6 行时可以使用 text-wrap: balance，正文可用 pretty 减少孤词，长文本不要强行套用。macOS 根布局统一使用 antialiased，动态数字则使用 tabular-nums，避免数值变化带动布局抖动。

第四轮盯住图标。常规文字附近的描边可用 1.5px，半粗文字附近用 2px。状态图标尽量复用单一 SVG 和 currentColor，默认采用描边，填充只标记激活态。图标按实际渲染尺寸设计，RTL 布局只翻转具有方向含义的图标。

第五轮清理性能隐患。删除 transition: all，明确写出需要过渡的属性。will-change 只考虑 transform、opacity 和 filter，而且应在观察到首帧卡顿后再加，尤其要验证 Safari 的表现。

## 把发现写成能执行的审查单

口头说“按钮有点飘”无法进入开发流程。每条发现至少写清严重度、文件与行号、修改前后、违反的规则和用户影响。

系统性问题应合并记录。例如同一种错误圆角出现在六张卡片上，只建一条发现，再列出全部位置。这样既能看出影响范围，也不会把报告写成重复问题的堆积。

严重度可以这样判断。

- HIGH，影响点击、状态识别或关键任务完成
- MEDIUM，造成明显错位、抖动或交互不连贯
- LOW，不阻断使用，但持续削弱视觉一致性

报告还要保留一小段“已否决候选”。列出考虑过却没有采用的修改及理由，例如没有替换字体，因为规则只要求改善数字稳定性。这个动作能防止审查变成无边界的重新设计。

## 用四个结果判断是否可以交付

验收不能停在“改完看着不错”。重新遍历正常、悬停、聚焦、按下、加载和空状态，再以 10% 速度检查关键动效，同时运行项目已有的格式检查、类型检查和测试命令。

最终结果只看这些证据。

- 圆角关系一致，图标在视觉上居中
- 所有点击区域达到尺寸要求且没有重叠
- 动态数字不再推动相邻内容
- 动画可以被打断，退场弱于入场
- 关闭动画后，用户仍能识别状态变化
- transition 和 will-change 都限定在必要属性
- 报告明确写出未审查的类别，不用模糊措辞暗示完整覆盖

只要还有 HIGH 问题，裁决就是 Block。只剩中低优先级问题时标记 Needs changes，全部完成并通过验证后才是 Approve。

## 避开四种越改越乱的做法

最常见的错误，是看到不够精致就增加阴影、动画和装饰。动效是一笔预算，边框也有明确职责，多加一层不等于多一层质感。

另外三类问题同样常见。

- 为了统一而强改字体族，扩大了改动范围
- 用几何居中覆盖视觉偏差，图标数值正确却仍显得歪
- 只检查默认状态，遗漏 focus、loading 和 empty
- 把 will-change 当成通用性能开关，没有卡顿也提前添加

我的判断是，界面质感很少靠一次大改突然出现。更可靠的方式，是把 19 条规则压进一次有边界的页面审查，让每个修改都有位置、理由和验收结果。

现在就选一个状态最多的页面，截齐六类状态，再从同心圆角和点击热区开始。第一轮只处理能明确定位的问题，完成后用慢速动画复查一次。
