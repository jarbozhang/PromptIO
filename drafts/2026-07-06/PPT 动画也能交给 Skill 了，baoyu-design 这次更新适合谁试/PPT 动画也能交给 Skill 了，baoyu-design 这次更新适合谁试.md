# PPT 动画也能交给 Skill 了，baoyu-design 这次更新适合谁试

如果你经常做课件、方案页、路演稿，baoyu-design 这次更新值得看一眼。

它现在开始支持 PPT 动画了。不是那种只把静态页面导成 PPTX 的流程，而是让常用动画能进到最终演示文件里。

我最关心的不是“能不能炫”，而是它能不能把一类重复劳动往前推一步，先生成可讲的页面，再补上最基本的演示节奏。

## 选一个真会用到动画的页面

我不会一上来拿整套路演稿去试。PPT 动画最容易翻车的地方，不是功能有没有，而是页面太复杂，最后你不知道问题出在内容、布局、导出，还是播放器差异。

更适合先试这三类页面。

- 课程讲解页，一步步露出概念、公式、案例
- 方案汇报页，按顺序出现问题、方案、结果
- 路演故事页，让时间线、增长路径、产品结构逐段展开

这次更新的关键信息是，baoyu-design Skill 原来生成的是 HTML 格式的 PPT，再借助 PptxGenJS 导出 PPTX。这个链路之前卡在一个地方，PptxGenJS 本身不支持 PPT 动画。

这也是我觉得这个更新有价值的原因。它不是又加了一个模板，而是补了一个演示文件里很现实的缺口。

## 按“讲稿节奏”写动画需求

如果你只是告诉 Skill“加点动画”，大概率得不到好结果。

做 PPT 的动画，真正要描述的是讲述顺序。比如一页课件里，我会把需求写成这样。

- 标题和主图先出现
- 三个要点按讲解顺序依次进入
- 关键数字最后出现
- 不要给每个小图标都加动画
- 每页只保留一种主要动画节奏

这个写法比“做得高级一点”有用得多。

源材料里提到，之前借助 Opus 4.8 没有搞定，现在用 Fable 5 迭代了几轮才处理好。这里最值得注意的不是模型名字，而是它处理的是 PPTX 的 XML 格式。

也就是说，这个能力更像是直接碰到了 PPTX 内部结构，而不是只在 HTML 页面里做一个看起来会动的效果。

## 用两端预览做验收

源材料里给了一个很关键的验证方式，视频前半部分看 HTML 页面动画，后半部分在 Keynote 里预览播放。

我建议也照这个思路验收，不要只看生成页面。

一个合格的最小验证可以这样做。

- 生成一页带 3 到 5 个元素的演示页
- 在 HTML 预览里检查动画顺序
- 导出 PPTX 后用 Keynote 或常用播放器打开
- 对比进入顺序、停留时间、元素位置
- 保留一个静态版本，防止演示场合临时兼容性出问题

这里不用追求第一次就替代人工修稿。更现实的目标是，让 Skill 先生成 70 分的动画草稿，你再把最关键的 2 到 3 页人工调整到可交付。

对做课件的人，这能省的是重复设置出现顺序的时间。对做方案的人，它能让页面天然带一点讲述层次。对做路演稿的人，它至少能把“这页该怎么讲”提前嵌进页面结构里。

## 常用动画可以先试，复杂转场别急

源材料里也说得很克制，动画细节上还有一点小出入，但常用的几个动画应该没什么问题。

这句话很重要。

我会把第一轮测试范围压得很窄，只试常用动画，不碰复杂转场和精细时间轴。比如元素依次出现、简单强调、分组进入，这些才是绝大多数课件和方案真正高频的部分。

不建议一开始就试这些场景。

- 多对象交错运动
- 很精细的路径动画
- 一页里塞十几个动画节点
- 依赖特殊字体和复杂遮罩的效果
- 需要严格对齐音频节奏的演示

PPT 动画不是越多越好。很多演示变乱，恰恰是因为每个元素都想动一下。

我的判断是，baoyu-design 这次更新最适合做“讲述顺序型动画”，不适合直接拿来做重动画视觉片。课件、方案、路演稿里的大多数动画，本来就是为了让听众跟上，而不是为了证明页面会动。

## 把第一次测试压成一页

如果我要开始试，会拿一页真实内容做最小闭环。

比如一页产品方案页，内容结构是痛点、方案、效果。给 Skill 的需求可以写成，先生成一页适合汇报的 PPT，页面需要包含痛点、方案、效果三段，动画按讲述顺序依次出现，导出后用于 Keynote 预览。

验收标准也很简单。

- 静态页面不乱
- 动画顺序符合讲稿
- 导出 PPTX 后能播放
- 细节偏差不影响讲解
- 人工修改时间少于从零设置动画

如果这五条过了，它就值得进入你的工作流。没过，也不要急着否定，先把页面元素减半，再试一次。

这类 Skill 的价值，不是让你永远不打开 PPT 软件。它更像一个会先搭结构的助理，把空白页、基础排版和常用动画先处理掉。

真正的交付判断还是在你手里，哪一页需要停顿，哪一页要删动画，哪一页要保留静态，都要按演示场景决定。
