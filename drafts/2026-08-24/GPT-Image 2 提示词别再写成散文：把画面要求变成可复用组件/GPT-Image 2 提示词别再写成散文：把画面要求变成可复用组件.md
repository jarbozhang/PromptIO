# GPT-Image 2 提示词别再写成散文：把画面要求变成可复用组件

如果你经常用 GPT-Image 2 做封面、海报或系列配图，这套方法能解决一个很实际的问题，同样的视觉风格，为什么每次都要重新描述一遍。

我看到 Berryxia 分享的案例后，最感兴趣的不是某条提示词能生成多漂亮的图，而是另一件事，把主体、光影、材质、文字和空间坐标拆成组件，交给人和 Agent 重复调用。

但有个判断需要纠正。结构化提示词能减少变量混乱，提高复用和排版控制，却不能让生成过程接近零幻觉。它管住的是输入，不是模型的全部输出。

## 别把提示词长度当成控制力

常见误解是，画面描述得越细，模型越能准确还原。于是提示词越写越长，从主体一路写到情绪、镜头、材质和字体，最后像一篇视觉散文。

这种写法用于单张探索图没有问题。创作者可以边写边联想，偶然得到意料之外的效果。

麻烦出现在第二张图。你想保留上一张的灯光，只替换主体，却很难确定该复制哪几句。Agent 接手时更棘手，因为它需要从自然语言中猜出哪些词属于固定风格，哪些词是当前任务的变量。

我更愿意把长提示词看成一次性成品，而不是可维护资产。它可能有效，却很难复用、比较和批量修改。

## 把五类变量拆成可替换部件

组件化的关键不是把散文塞进 JSON 或 YAML，而是让每个字段只承担一种职责。

- 主体组件，描述人物、物体、动作、数量和视觉焦点
- 光影组件，描述光源方向、软硬程度、明暗关系和色温
- 材质组件，描述纸张、金属、玻璃、织物等表面特征
- 文字组件，描述需要呈现的文字内容、层级、字重和对齐方式
- 空间坐标组件，描述主体、留白和文字分别占据画面的哪个区域

例如做一组科技媒体封面，我可以固定光影与材质，只替换主体组件。换到竖版内容时，再调整空间坐标，而不用重写整段视觉语言。

这才是 Prompt-as-Code 真正有用的地方。字段可以被保存、复用、做版本比较，也能让 Agent 明确修改目标。一次只换一个变量，失败后也更容易判断问题出在哪里。

## 空间坐标提高排版控制，但不是像素承诺

原帖里最值得关注的是空间坐标约束。文字位置一直是生成图片里较难控制的部分，而左上、右侧、中下区域或百分比范围，比一句“把标题放在合适的位置”清楚得多。

更准确的做法，是把画面理解成一个坐标系统。主体占据左侧主要区域，右侧保留连续留白，文字限定在安全区内，同时注明各元素不能互相遮挡。

它能提高模型理解布局关系的概率，也方便在横版、竖版和方图之间转换。但坐标不是前端 CSS，不能保证每次都落在同一个像素点。涉及品牌字、价格、日期或长段文字时，仍然需要检查错字、缺字、遮挡和裁切。

我的判断是，空间约束适合控制构图意图，不适合代替最终排版。要求越精确，越应该把生成画面与后期文字排版分成两个环节。

## 组件化减少混乱，不会消除随机性

“结构化之后几乎零幻觉”这个说法过满。JSON 和 YAML 可以固定字段、减少遗漏，也能阻止 Agent 随意改写不相关变量，但模型仍可能忽略约束、误画数量、改变材质或生成错误文字。

组件化真正解决的是工程问题。

同一套风格能不能重复调用，某次修改影响了哪些部分，多种尺寸如何共享视觉规则，失败结果能不能沿着字段定位原因。这些事情靠一段长提示词很难管理，靠组件就清楚得多。

它不能消除的，则是模型对空间关系、细节数量和文字生成的误差。输入变得可控，不等于输出已经确定。

## 用一组系列图验证这套方法

我建议不要拿单张图判断组件化是否有效。选三张需要保持统一风格的系列封面，固定光影、材质和色彩，只替换主体，再观察风格是否稳定。

第二轮只修改空间坐标，把同一内容分别适配横版和竖版。验收时关注四件事，主体有没有漂移，留白是否连续，文字安全区有没有被侵占，字段修改是否只影响预期区域。

如果每次仍要重写全部字段，说明组件边界拆得不对。如果结构已经稳定，但文字依然出错，就不要继续堆提示词，转入独立排版环节。

散文式提示词适合寻找灵感，组件式提示词适合交付。真正值得保存的不是某句神奇描述，而是一套能替换、能检查、也允许失败的画面变量。
