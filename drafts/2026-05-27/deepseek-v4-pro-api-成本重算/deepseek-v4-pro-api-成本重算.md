# DeepSeek 旗舰模型永久降价 75%，国内开发者该重新算一遍 API 成本了

DeepSeek 这次真正影响开发者预算的，不是又多了一个模型名字，而是 V4-Pro 的 API 价格不再按临时促销来算。

Bloomberg 在 2026 年 5 月 23 日报道，DeepSeek 会把旗舰 V4-Pro 的 75% 降价变成长期价格。DeepSeek 官方价格页也写明，优惠在 2026 年 5 月 31 日 15:59 UTC 结束后，V4-Pro API 定价会正式调整为原价的 1/4。

这件事最直接的动作不是感叹价格战，而是把你现在的 token 账单拆开，重新算一遍哪些请求值得迁。

## 先把价格摊开

官方文档按 1M tokens 计价。V4-Pro 的 75% 降价后价格已经可以用作后续预算基线。

| 计费项 | V4-Pro 原价 | V4-Pro 调整后 | V4-Flash |
|---|---|---|---|
| 1M 输入 tokens, cache hit | $0.0145 | $0.003625 | $0.0028 |
| 1M 输入 tokens, cache miss | $1.74 | $0.435 | $0.14 |
| 1M 输出 tokens | $3.48 | $0.87 | $0.28 |
| 并发限制 | 500 | 500 | 2500 |

有两个数字最该被单独拎出来。V4-Pro 的 cache miss 输入是 $0.435/M，cache hit 输入是 $0.003625/M，两者相差 120 倍。也就是说，真正便宜的不是所有请求，而是重复上下文能稳定命中缓存的请求。

用官方价格可以直接算几笔账。

| 请求形态 | V4-Pro 调整后成本 | 适合怎么理解 |
|---|---|---|
| 1M 新输入加 1M 输出 | $1.305 | 普通单轮大请求 |
| 1M 缓存输入加 1M 输出 | 约 $0.874 | 固定系统提示词和重复资料多的任务 |
| 10M 缓存输入加 1M 输出 | 约 $0.906 | 长上下文复用明显的任务 |
| 10M 新输入加 1M 输出 | $5.22 | 长文首次进入模型时仍然不便宜 |

这张表给国内开发者的提醒很具体。不要只问 V4-Pro 单价是多少，要问你的业务里 cache hit 占多少，输出 tokens 占多少，峰值并发有没有撞到 500。

## 哪些任务可以优先迁

第一类是高频、低风险、可回放的文本任务。摘要、信息抽取、标签分类、去重、长文初筛，都可以先拿历史样本做离线评测。它们的共同点是错误容易被发现，也容易用规则或人工复核兜底。

第二类是系统提示词很长、用户输入相对短的 agent 子步骤。很多团队的 agent 成本不在用户一句话，而在一大段固定的角色说明、工具说明、输出格式要求。只要这些固定上下文能命中缓存，V4-Pro 的 cache hit 价格会把成本结构改掉。

第三类是内部研发提效任务。比如代码解释、PR 摘要、日志归因初稿、测试失败原因归纳。这些任务对单次输出的稳定性有要求，但通常不是直接面向最终用户。先迁内部链路，风险比一次性迁生产问答低。

第四类是长文档反复分析。合同条款提取、知识库批处理、客服工单归因、研报摘要这类任务，如果同一批资料会被多轮调用，缓存命中率比模型名更影响账单。

## 哪些任务先别急着动

已经围绕某个模型调过大量提示词、评测集和安全边界的核心链路，不要因为价格直接全量切换。便宜 75% 只解决计费问题，不自动解决输出风格、失败模式和边界条件。

强依赖某家供应商专有能力的链路，也要谨慎。DeepSeek 官方价格页列了 JSON Output、Tool Calls、Chat Prefix Completion、FIM Completion 等能力，但如果你当前链路依赖价格页没有列出的能力，迁移前必须单独验证。

对并发敏感的任务要看限制。官方表里 V4-Pro 并发限制是 500，V4-Flash 是 2500。便宜模型不等于无限吞吐，批处理、排队、降级路由都要提前设计。

还有一类是业务关键输出。用户看得见、出错成本高、没有人工复核的请求，适合先做灰度路由，而不是把 provider 一次换干净。

## 一张迁移检查表

迁移前先从网关或日志里导出最近一段真实请求，至少拆出四列，输入 cache hit tokens、输入 cache miss tokens、输出 tokens、失败重试次数。只看总 tokens 没用，因为 Pro 的 cache hit 和 cache miss 不是一个价格层级。

可以用这条公式做第一版预算。

`月成本 = cache_hit_input_M * 0.003625 + cache_miss_input_M * 0.435 + output_M * 0.87`

然后给每类任务加四个标记，可回放、可复核、可降级、可缓存。四个都满足，优先迁。只满足一两个，先放进实验队列。

评测也不要只看平均分。更实用的是固定 50 到 200 条代表性样本，记录格式错误率、拒答率、幻觉率、P95 延迟、重试率。价格便宜以后，失败重试反而会被忽略，但重试会吃掉一部分节省出来的空间。

上线策略建议从路由开始，而不是从替换开始。把 DeepSeek-V4-Pro 放进一个可配置 provider 层，按任务类型、缓存命中率和失败率分流。这样价格变动、模型升级、供应商限流都不会把业务绑死在一次选择上。

## 这次降价真正改变的是预算口径

HN 上这个 Bloomberg 链接本身只有 2 条评论，而且被标为 dupe，所以本文不拿社区口碑当证据。现在能确认的事实已经够用，V4-Pro 的 75% 降价会变成官方定价，官方价格表已经给出 cache hit、cache miss、output 三个关键价格。

我认为这次最该做的不是讨论谁替代谁，而是重写团队内部的模型路由表。低风险、高频、可缓存的任务迁到更低成本路径，关键链路继续保留已经验证过的模型和 fallback。

开发者真正要省下来的，不是某一次 API 调用的钱，而是把模型当成可路由基础设施以后，每个月少交的无效 token 税。
