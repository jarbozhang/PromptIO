# Chip Huyen 新书配套 repo 一天冲榜，AI 工程师该读什么她写了 600 页答案

今天 GitHub Trending 冒出来一个没什么代码的 repo，一天涨了两百多星，叫 chiphuyen/aie-book。

没错，就是 Chip Huyen。那个写《Designing Machine Learning Systems》卖穿 AI 圈的 Chip Huyen，她 2025 年在 O'Reilly 出的新书叫《AI Engineering》，这个 repo 是它的配套资源。

repo 里 README 有句话挺刺眼，"This is NOT a tutorial book"。翻译过来就是，别指望抄代码跑，我是来给你建心智模型的。

坦率讲我看到这句话的时候愣了一下。因为过去一年国内太多 AI 工程师，包括我自己，都是项目驱动学下来的，哪个需求卡住学哪个，RAG 卡住补 RAG，Agent 卡住补 Agent。结果就是一身补丁，没有地图。

## 她凭什么能出这本书

先说人。Chip Huyen 这个名字在海外 ML 圈的分量，大概类似国内的沈向洋加上一个写字好看的版本。

履历上 NVIDIA NeMo 核心开发、Snorkel、Netflix ML 系统，Stanford 教过 CS329S（机器学习系统设计），后来还创办并卖掉了一家 AI 基础设施创业公司。真正跑过 production 系统的人，不是只会讲 PPT。

上一本《Designing Machine Learning Systems》是亚马逊 AI 类目卖到断货的书，翻译成了十几种语言。我身边做 ML 平台的工程师，书架上基本都有一本，封面那只猫头鹰很眼熟。

这本《AI Engineering》根据 O'Reilly 自己公布的数据，是他们平台上线以来最多人读的书。注意是最多人读，不是最多人买，这个指标更硬。

所以这个人写 AI 工程方法论，是"她上台"，不是"她出书"。

## 这个 repo 到底有什么

我把 repo 扒了一遍，先打预防针，它现在还挂着 [WIP] 的标签，作者说后面几周会陆续补资源。目前能看到的主要是几类东西。

一类是书的目录和章节摘要。这东西看着普通，但对想决定要不要啃英文原版的人来说非常有用，先看目录判断对自己有没有用，比直接买书靠谱。

一类是学习笔记和资源清单。比如针对 hallucination 缓解、RAG 策略、Agent 开发、finetuning 决策、数据质量验证、production 性能 cost security 优化这些话题，有额外的延伸阅读。

还有一类是 case studies 和 prompt engineering 的例子。这个 repo 不是在教你写 prompt，是在展示真实项目里 prompt 是怎么迭代出来的。

代码少得可怜。脚本目录里有个好玩的工具，可以把你的 ChatGPT 或 Claude 对话记录生成热力图，看看自己一年都在问 AI 什么。其他没什么可跑的。

这一点我觉得反而是优点。市面上 AI 工程的 repo 太多了，clone 下来跑通就算学会了，三个月后工具升级完全废掉。她这本书刻意去掉了工具细节，讲的是哪怕三年后 LangChain 没了，你还能用得上的思考框架。

## 中国 AI 工程师的真实痛点

说真的，我们这波人学 AI 是最赶时间的。

从 2023 年 ChatGPT 爆火到现在，三年不到，所有人都是一边上线一边学。结果就是每个人都会用 LangChain、会调 embedding、会搭 RAG，但问一个稍微深一点的问题，比如"你这个 RAG 为什么选 top-k 等于 5 不是 10"，大部分人答不上来。

因为没人系统教过，都是看 YouTube 和公众号拼的。

我观察下来有个反常识的事，国内做 AI 应用的同学，论动手能力一点不比海外差，甚至更猛。但论"系统性理解"差一截。你让他列一个 AI 系统评估的完整框架，他列不出来，因为他的知识都是事件触发的，不是结构化组织的。

这也是为什么我觉得 Chip Huyen 这本书对中国工程师特别重要。她的写作风格是"先给框架再给案例"，和我们习惯的"先上代码再解释"正好反过来。读起来会痛苦，但读完脑子里会有地图。

## 英文技术书的性价比

有人肯定要问，英文书啊，读不动怎么办。

我的判断是这样。第一，O'Reilly 电子版含免费更新，比买国内翻译版划算，翻译版出来至少晚半年，而 AI 领域半年等于上古时代。第二，现在 Claude、Kimi、元宝翻译英文技术书的水平已经够用，整章丢进去让它做中文摘要再对照读，效率比纯中文版还高。

而且《AI Engineering》这本书的词汇难度不高，主要难的是概念密度。概念密度高的书翻译反而失真严重，不如原版配 AI 辅助读。

我认识的几个国内大厂 AI Infra 工程师已经在读了，有个在美团做推理优化的朋友说，"看完第一反应是，原来我这两年做的事有专业名词"。这句话我觉得很典型。

## 我的判断

如果你是做 AI 应用的工程师，现在有两条路。

第一条，继续项目驱动。哪里不会补哪里，这样走三年你会变成一个很能干活的人，但永远是"某个具体工具的老手"。

第二条，花一个月把这本书啃完，补齐框架。短期看没收益，长期看你和周围人的差距会拉开。

我自己选第二条。因为我越来越觉得，工具会过时，方法论不会。三年前大家都在卷 LoRA 微调，今天大家都在卷 Agent，再过一年卷什么没人知道。但如何评估一个 AI 系统、如何权衡 finetuning 和 RAG、如何做 production 的可靠性，这些问题永远在。

可能有些想法还不成熟，但我是真的觉得，国内 AI 工程师缺的不是算力也不是数据，是一本像样的地图。Chip Huyen 画了一张，我们至少应该先看看。

## 行动建议

先 star 这个 repo 占个位，她后面还会加资源。

然后去 O'Reilly 开个试读，前两章通常免费，判断一下风格对不对胃口。

最后如果你是团队 lead，可以在团队里搞个读书会，每周一章，大家讨论对应到自己项目里该怎么落地。这种读法比一个人闷头啃收益大十倍。

顺便问一句，你上一本从头读到尾的 AI 技术书是哪本，什么时候读的。我猜很多人答不上来。
