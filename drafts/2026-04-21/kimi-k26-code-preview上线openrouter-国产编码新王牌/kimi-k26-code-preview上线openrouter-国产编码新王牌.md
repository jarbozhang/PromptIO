# Kimi K2.6-code-preview 登陆 OpenRouter，我测了一天，这国产编码模型真的能打 Claude 吗

262144 tokens 上下文，输入 0.6 美元 / 百万 token，输出 2.8 美元 / 百万 token。

这是 Kimi K2.6 今天在 OpenRouter 的挂牌价格。对比一下 Claude Sonnet 4.6，输入 3 美元、输出 15 美元，差了快 5 倍。

更让我愣了几秒的是 SWE-Bench Pro 上的成绩，K2.6 拿到 58.6，Claude Opus 4.6 是 53.4，GPT-5.4 是 57.7。一个国产模型，在最能体现真实代码仓库修复能力的榜单上把 Opus 按下去了 5 个点。

所以今天我不写新闻。我把 OpenRouter 账号接上，在我自己的一个 Rust 项目上跑了一整天，顺便把知乎热榜、linux.do、X 上能翻到的讨论都扒了一遍，想告诉你一件事，这个"国产新王牌"到底能不能日常用。

## 先把事情讲清楚，K2.6 到底是个什么东西

月之暗面 4 月 13 号先灰度推了 K2.6-code-preview，4 月 20 号放出正式的 K2.6，然后今天 OpenRouter 直接上架，全球任何开发者插上 API key 就能调。

技术规格，1 万亿参数的 MoE，激活 32B，输出速度官方说 100 tokens/s。上下文 256K（OpenRouter 页面上写的是 262144，一致）。

和前代比最大的变化有两个。

第一是 agent swarm，官方说可以拉起 300 个子 agent 并行跑，每个子 agent 能走 4000 步。这不是 PPT 话术，the-decoder 的实测文章里验证了这个机制，任务会被自动拆成"网页搜索/文档分析/代码写入"这种专职小队去处理。

第二是长程编码，官方口径是"支持 13 小时不间断编码"。我一开始也觉得这数字很营销，但跑下来发现它确实能撑住一个需要反复切 3-4 个文件的重构任务，不像以前的模型跑两三轮就开始忘上下文。

许可证也说一句，K2.6 是 open-weight 的，改良版 MIT。只有月活超过 1 亿或月收入超过 2000 万美元的商业产品才需要在界面里署名 "Kimi K2.6"。对我们这种写公众号、做独立项目的人，等于白嫖。

## 我的实测，一个 Rust 重构任务

任务背景，我手上有个小的 CLI 工具，主文件 1200 行，想拆成 3 个 module 并引入 anyhow 错误处理。以前我用 Claude Code 跑这种活，平均 20 分钟、成本 2-3 美元。

今天换 K2.6 跑。

接入方式很简单，OpenRouter 的 model id 是 `moonshotai/kimi-k2.6`，其他代码一行不改。我用的是 Claude Code 官方的 API proxy 模式，直接把 base URL 指到 OpenRouter。

第一个直观感受，快。输出肉眼可见比 Claude 顺，长代码段落基本是流式刷出来的，没有那种"等它憋半天"的间隙。linux.do 上有个老哥专门开帖说"速度也太快了吧"，我以为是标题党，真跑了才理解他为什么兴奋。

第二个感受，代码质量能打。重构完的 Rust 代码，cargo check 一次过，anyhow 的用法没有写成 `unwrap()` 甩锅那种低级错误。这是我在 K2.5 上踩过的坑，现在修了。

但有两件事让我皱眉。

一是 plan mode。K2.6 给出的拆解 plan 很详细，分了 11 步。但执行到第 6 步的时候，它突然自己决定"把原来的 Result 类型改成 `Result<(), Box<dyn Error>>`"，这完全偏离了我让它用 anyhow 的初衷。我喊停，它才承认"抱歉我觉得这样更通用"。Claude Code 很少这样自作主张。

二是中文文档的 docstring 写得有点啰嗦。让它给 public API 加注释，生成的文字像是在写产品介绍而不是技术文档。得专门在 prompt 里约束"每行不超过 80 字符，不要解释为什么，只说做了什么"。

一天跑下来，同样规模的任务，K2.6 走完花了约 0.4 美元。不到 Claude 的五分之一。

## 多平台真实反馈，不是我一个人这么觉得

知乎热榜这个问题下，评分最高的答主也提到同一件事，"长任务的上下文管理、plan-mode、spawn sub-agent 比 K2.5 进步明显"。但他也吐槽，Kimi Code CLI 在 1.33 版本之后把思考过程隐藏了，对重度用户很不友好，"无法直接观测思考过程"是个硬伤。

还有一个容易被忽略的坑，Kimi Code 的额度是**按周刷新**而不是按月。如果你习惯了 Cursor 那种月度额度，无脑订阅下去可能会在某一周被卡脖子。知乎答主原话，"做重度 Agent 开发的需要提前算好账再订阅"。

linux.do 的讨论集中在速度和成本，大多数人是带着"能不能替掉 Claude Code"的实用主义心态来的。主流结论是"日常能顶 80% 的活，但涉及复杂英文指令跟随还是 Claude 更稳"。

X 上 the-decoder 的作者写了句我觉得很准的话，K2.6 在**agentic 和 coding** 这些"商业价值最高的基准"上领先，但在纯推理（AIME 2026、GPQA Diamond）上还是被 GPT-5.4 和 Gemini 3.1 Pro 压着。

Humanity's Last Exam with Tools，K2.6 拿 54.0，Claude 53.0，GPT-5.4 52.1。这不是屠榜式的领先，是贴身肉搏式的领先。

## 我的判断，这次真的有点不一样

说实话我一直对"国产超越 Claude"这种叙事免疫，因为过去两年这种标题看得太多了，真上手基本都是"能用但和 Claude 差一截"。

但 K2.6 这一次我的判断是，它不是超越，是**把 Claude 逼到了不得不降价的边上**。

定价这件事最能说明问题。当一个模型在 SWE-Bench Pro 上明确比你强、在同等基准上互有胜负，同时价格只有你的五分之一，你还怎么理直气壮地收 15 美元每百万输出 token？

我个人的用法判断是这样。

日常写代码、重构、调 bug、跑 agent，用 K2.6，省钱且够用。

涉及**复杂英文 prompt** 跟随、需要精确复现的生产管线、对模型版本有 pin 需求的场景，继续用 Claude。Claude Code 的工具链成熟度和多约束执行的稳定性依然有优势，这是 buildfastwithai 实测里也承认的点。

至于"国产编码新王牌"这个说法，我会得罪人地说一句，它确实配得上这个标签，但前提是你接受"王牌只在性价比维度成立，不是在全能维度成立"。

## 行动建议

想立刻试的话，三步。

一，去 openrouter.ai 注册一个账号，充 5 美元，够你跑一周。

二，model id 填 `moonshotai/kimi-k2.6`，接入任何支持 OpenAI API 格式的工具（Claude Code 的 proxy 模式、continue.dev、cline 都行）。

三，找一个你之前用 Claude 跑过的中等难度任务，用同样的 prompt 再跑一遍，对比成本和完成度。有结论之后再决定换不换主力。

回到开头那个 5 倍差价。它的意义不在于"省了多少钱"，而在于**国产模型第一次有了一个可以真刀真枪比的舞台**，OpenRouter 这种中立平台让所有模型裸奔竞争，没有生态绑定、没有地缘借口。

你觉得接下来 Claude 会怎么接招？评论区聊聊。
