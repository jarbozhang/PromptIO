# 港大开源 AI-Trader 一夜 646 星，开源 agent 交易框架到底在做什么

5 月 10 日 GitHub Trending 第一名是 HKUDS/AI-Trader，单日 +646 星，仓库总星数 15.1k，fork 2.5k。HKUDS 团队之前做过 RAG-Anything 和 ViMax，开源履历不算新人。这次的项目方向比较新，讨论度也最高，国内交流群里第一波问题就是"这玩意国内能用吗"。

我把它读了一遍，简单聊聊这个项目到底在做什么、值不值得国内 AI 用户去了解。**注意：本文仅作为开源项目介绍，不构成任何投资建议，也不教大家做实盘交易。**

## 这套系统到底是什么

AI-Trader 不是一个本地跑的回测框架，也不是一个命令行交易机器人，它本质上是一个 agent-native 的开源框架，由两层组成。

服务端是 FastAPI + React，对应仓库里的 `service/server/` 和 `service/frontend/`，仓库整体 60.9% Python、32.5% TypeScript，负责账户、信号、结算等逻辑。

agent 层不在仓库里，而是任意 AI 客户端通过 `SKILL.md` 协议接入。README 里举的例子包含 OpenClaw、nanobot、Claude Code、Codex、Cursor，覆盖大部分主流 agent 运行时。SKILL 文件分三种，`ai4trade` 是主接入、`copytrade` 是策略复制、`tradesync` 是数据同步。

平台还有一个 \$100K 的 paper trading 沙盘，相当于把所有 agent 放在同一组虚拟资金下跑模拟，排名靠前的策略可以被一键复制。这是一个"集体智能"的设计形态，不是论文里那种 multi-agent debate，而是公开模拟 + 排行榜 + 策略复用的工程实践。

## 跟 dexter / TradingAgents 的差异

我们之前覆盖过两条同类开源线，5 月 5 日的 dexter 和 5 月 1 日的 TradingAgents。三个项目设计取向其实差得很远。

TradingAgents 是清华那条线，多 agent 角色扮演（基本面、技术面、风险研究员），跑完一轮在本地输出一份分析报告，定位偏研究框架。dexter 走的是工具集路线，把 yfinance、TA-Lib、回测引擎打包成一组 LLM 工具，agent 自己组合调用，强项是灵活。

AI-Trader 走的是第三条路，它把"agent 协作"标准化为一组信号协议（strategy / operation / discussion），上链到服务端，再由服务端做编排。它把前两个项目"agent 帮你想"的部分，往"agent 之间互相配合 + 排行榜激励"这个方向推进了一步。这在工程上是更进一步，也意味着系统复杂度和风险面积都更大。

## 国内 AI 用户怎么看这件事

我自己的判断是，这个项目值得了解，但不建议国内散户拿去跑实盘，原因有三点。

第一，资产侧。AI-Trader 对接的经纪商是境外的，A 股的常用通道（券商 PTrade/QMT、迅投、掘金、聚宽）一个都没接，Tushare、akshare 这种国内数据源在 README 里也完全没有出现。

第二，数据侧。要让 AI-Trader 跑 A 股，至少需要替换三件事：行情源、合约标准化（A 股 6 位代码 vs 美股 ticker）、交易日历（沪深休市规则）。这三件改完，相当于 fork 一个新项目。

第三，合规侧。这是最关键的一条。**个人投资者用 AI 自动下单 A 股，目前监管口径很严**。证监会对"程序化交易"在 2024 年已经发过监管要求，对报单频率、撤单率都有阈值限制；如果被认定为"异常交易"，账户会被限制。AI-Trader 默认带的"策略复制"功能在 A 股语境下，更可能被定义为投顾或代客理财，需要持牌经营，普通用户照搬有合规风险。

所以从国内 AI 用户的视角，这个项目最合理的姿态是把它当**学习资料**：读一读它的 agent 协议设计，看 SKILL.md 怎么把 agent 行为标准化，理解一下 agent-native 的工程思路。它是一份很好的开源教材。

## 我的判断

AI-Trader 这次火，火在它把 agent-native 这件事做出了**完整的平台形态**。在这之前，TradingAgents 是研究框架、dexter 是工具集，没人敢真的做"集体智能 + 排行榜 + 协议化"这一套。HKUDS 敢做出来，工程能力是认可的。

但对中国大陆用户来说，它的实操价值非常有限：境外接入路径不在合规范围内，A 股集成技术上要重写大半个项目，"策略复制"在国内法规下属于持牌业务。

它真正值得跟踪的，不是"能不能用"，而是它把 agent 接业务系统的协议层（SKILL.md）做成了一个开放标准。以后国内做 agent 应用的厂商，不论做的是金融、办公还是物流，agent 之间互相协作的协议格式，可能都会参考这套样板。**这是 agent 工程方法论上的进步，跟实盘交易的关系没有大家想的那么大。**

如果你是 agent 开发者，建议把仓库 clone 下来读 `SKILL.md` 部分的协议设计；如果你只是想在 paper trading 模式下试一下 agent 写策略的体感，平台本身有沙盘可以玩，但请明确：**这是认知投资，不是实盘交易**。
