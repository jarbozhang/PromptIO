# 让 Codex 和 Claude Code 审计陌生仓库，为什么反而可能触发远程代码执行

你把一个陌生仓库交给 Codex 或 Claude Code，希望它找出恶意代码。结果，仓库里的恶意内容反过来影响审计代理，让代理亲手执行了攻击者准备的文件。

这不是安装恶意插件，也不依赖 MCP 服务器或额外配置。AI Now Institute 公布的概念验证显示，在特定版本和自动审批配置下，仅让编码代理检查一份被篡改的第三方代码，就可能把防御任务推进到远程代码执行。

对经常审查依赖、接手陌生项目或把安全扫描接入流水线的团队，真正需要重新检查的不是提示词怎么写，而是陌生仓库能否同时影响代理的判断，并获得命令执行机会。

## 还原这次审计失控的现场

研究人员修改了一份 `geopy` 代码库，在其中加入看似正常的安全检查材料。仓库里有一个 `security.sh` 脚本、一个名为 `code_policies` 的恶意二进制文件，以及一份看起来与该二进制对应的 Go 源文件。

脚本提到 `semgrep`、`black` 和 `mypy` 等常见工具，外观符合代码质量检查的语境。伪装用的 Go 文件则提供了一份正常的静态检查程序，让代理更容易把恶意二进制理解成可信的编译产物。

第二层诱导藏在 `README.md`。文档没有直接要求代理运行恶意载荷，而是把 `security.sh` 描述成项目自带的安全检查入口。

当用户只提交执行安全测试的任务时，代理会阅读文档、检查脚本和相关文件，再判断运行该脚本符合原始目标。脚本随后启动恶意二进制，攻击者的载荷便进入宿主环境。

研究覆盖 Claude Code CLI 2.1.116、2.1.196、2.1.198、2.1.199，以及 Codex CLI 0.142.4。论文中的配置分别使用 Claude Code 的 `auto-mode` 和 Codex 的 `auto-review`，模型包括 Sonnet 4.6、Sonnet 5、Opus 4.8 与 GPT-5.5。

## 拆开从文档到执行权限的事故链

这次失败不是单一过滤规则漏掉了一句恶意指令，而是四个条件连在了一起。

`不可信内容进入上下文` → `文档把执行包装成审计步骤` → `相互呼应的文件制造可信证据` → `自动审批允许命令落地`

代码仓库在传统工具眼中主要是待扫描的数据。在编码代理眼中，`README.md`、项目说明和源文件还可能成为任务上下文。只要代理不能稳定区分事实材料与操作指令，攻击者就能借仓库内容参与决策。

自动审批又缩短了最后一道距离。它原本用于减少长任务频繁中断，但审批分类器与执行代理仍会参考同一批可疑材料。攻击者不必直接击穿权限系统，只需让一次危险执行看起来像完成安全审计所必需的动作。

研究人员还专门询问模型仓库中是否存在提示词注入。在其实验里，Sonnet 4.6 和 GPT-5.5 都没有识别出来。研究同时强调，模型输出具有非确定性，实际结果会受模型、上下文、提示和服务端变化影响，因此这不是每次必然成功的固定漏洞链。

## 解释为什么常见防线仍然不够

只检查 `.mcp`、`.json` 或工具配置文件，挡不住这类路径。研究使用的是普通 `README.md`，它不需要承担机器配置功能，也可能推动代理执行仓库中的脚本。

只让模型再判断一次是否安全，同样存在结构性问题。攻击材料可以把文档、源码、文件名和二进制外观组织成互相支持的证据，而负责识别风险的仍是容易受到这些内容影响的模型。

沙箱能限制后果，却不能被当成绝对边界。此次概念验证没有继续演示沙箱逃逸，但研究指出，代理一旦在沙箱内获得代码执行，仍可能寻找沙箱实现缺陷、可写配置或其他宿主入口。

人工确认也不是万能补丁。高频弹窗会造成提示疲劳，操作者可能逐渐把批准当成流程动作。若审批界面只显示一条看似正常的安全脚本命令，而不呈现脚本来源、调用链和文件差异，人仍然很难作出有效判断。

## 把修复落到权限和环境边界

处理陌生仓库时，应把它视为主动对抗输入，而不是普通项目资料。安全审计代理不能同时拥有广泛读取、任意执行、敏感凭据和宿主写入能力。

更稳妥的修复动作可以压成三层。

**隔离环境**

为每次陌生仓库审计创建一次性环境，与日常开发机和关键流水线分开。环境中不放 SSH 密钥、云凭据、包发布令牌、生产配置和可复用登录状态，任务结束后直接销毁。

**权限收缩**

默认禁止执行仓库自带脚本、二进制文件和安装钩子。文件系统尽量只读，网络访问按任务关闭或收窄，宿主目录、容器控制接口和配置目录不要映射进去。

**人工确认**

把确认点放在行为边界，而不是依赖模型判断某条命令是否安全。任何来自待审仓库的可执行文件、构建脚本、测试入口或下载动作，都应暂停并显示来源文件、完整调用链、文件哈希及即将获得的权限。

对自动化流水线，还要把静态阅读与动态执行拆成两个阶段。第一阶段只生成发现和待验证项，第二阶段由独立环境处理经过确认的最小命令，避免审计代理从读取仓库一路无阻地走到执行载荷。

## 留下一张陌生仓库事故卡

**触发条件**　不可信仓库内容进入代理上下文，代理还能执行命令。

**危险信号**　文档推荐运行仓库自带安全脚本，二进制与源码仅凭名称对应，审计任务要求自动完成，审批由模型代替人工。

**立即处置**　停止在当前宿主继续分析，撤销该环境可接触的凭据，保留执行日志与文件哈希，在一次性环境中重新检查调用链。

**恢复标准**　审计环境不含敏感凭据，仓库默认只读，未知程序无法直接执行，网络与宿主写入受到限制，高风险动作必须由人确认。

这次事故最值得记住的，不是某个恶意文件名，而是权限设计原则。用于发现危险的 Agent，本身也必须被当成可能受不可信输入操纵的执行主体。
