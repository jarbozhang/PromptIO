# The Verge，vibe coding 革命，软件作者的意志不再垄断用户体验

The Verge 在 5 月 14 日发了一篇长文，标题叫《You can make an app for that》，开篇第一句就立了一个判断，"软件的暴政几乎结束了"。

作者的意思很直接。从第一个程序员写下第一行代码开始，软件用户就一直生活在程序员设计好的世界里，按钮放在哪里、流程怎么走、有什么功能、缺什么功能，这些都由"做软件的那群人"决定，而做软件的人和用软件的人通常不是同一批人。律师用律师事务所软件，医生用医疗系统，老师用学校系统，教堂用教会系统，但这些系统都不是律师、医生、老师、牧师自己造的。

vibe coding 改变了这件事。这是 The Verge 这篇评论真正的命题，不是"AI 能写代码"这件已经被讲烂的事，而是"软件作者的意志不再垄断用户体验"。

## 什么叫"软件的暴政"

这个词听起来挺重，但描述的是一个所有人都默认接受的现实。

你用钉钉，钉钉的产品经理决定你打开 app 看到什么。你用微信，张小龙团队决定哪些功能存在哪些不存在。你用 Notion，Notion 的设计师决定页面长什么样。如果你想要一个稍微不一样的版本，比如"我希望日历视图能直接显示我的待办权重排序"，你能做的事只有两件，要么发工单等三年，要么"去学编程吧"。

The Verge 这篇文章引用了 Raycast 联合创始人 Thomas Paul Mann 的话，他在描述自家 vibe coding 产品 Glaze 时说，这是"我们对个人计算的理解"，让用户为自己造小工具，或者为团队造极度具体的 app。

关键词是"极度具体"。

过去的软件商业模式天然反对"极度具体"。一款 SaaS 必须服务尽量多的人才能活下去，所以每个产品都在做最大公约数，每个团队都被迫去适配那个最大公约数。而当造软件的边际成本被 AI 压到接近零，每个人都能为自己量身造一个，"最大公约数"这件事就没意义了。

## 国产路线，可以立刻试的几条

Verge 这篇是评论，没怎么讲怎么动手。但对中国 AI 用户来说，更重要的问题是，国内能直接用什么。

国产 vibe coding 路径已经成型，且不需要任何境外服务。

**Trae**，字节做的 AI 原生 IDE，国内可直接下载，自带 Claude、GPT、Doubao 多模型切换，免费额度足够日常用。它的 Builder 模式就是典型 vibe coding 形态，描述需求直接出可运行 app，对前端项目尤其顺手。

**通义灵码的 AI 程序员模式**，阿里在 2026 年初把通义灵码从代码补全工具升级成了 agent 模式，支持多文件改动、自主调试。国内开发者用阿里云账号直接登录就能用，免费版日额度可观，适合习惯 JetBrains 全家桶或 VS Code 生态的人。

**腾讯 CodeBuddy**，腾讯的同类产品，定位偏团队协作，深度集成腾讯文档、腾讯会议、企业微信，适合在腾讯生态里办公的团队造小工具。

**DeepSeek + Cline 组合**，给愿意折腾的用户。Cline 是开源 VS Code 插件，可以接任何 OpenAI 协议兼容的模型，DeepSeek 官方 API 价格只是 Claude 的几十分之一，跑日常 vibe coding 任务完全够用。这条路线的好处是完全可控，不依赖任何厂商的"免费额度"政策。

值得说一句的是，国内这几款工具的设计取向并不一样。Trae 更像 Cursor 的国产对应，强调一体化开箱即用，通义灵码更接近"加在你现有 IDE 上的 agent"，CodeBuddy 偏向团队工具链整合。选哪个，看你已经在哪个生态里。

## 不只是"会写代码"这件事

vibe coding 这个词容易被误解成"AI 帮我写代码"，但 The Verge 文章里真正想讲的不是这个。

代码生成 2023 年就有了。Copilot 卷了三年，结果是程序员效率提升，门槛并没有变。vibe coding 和它的区别在于，目标用户不是程序员。

The Verge 文章里举的例子是律师想要一个"自动按照我习惯排版的合同生成器"，医生想要一个"我每天问诊都问同样几个问题的自动记录工具"，老师想要一个"按我自己的逻辑给学生分组的随机点名器"。这些需求过去都不会被任何 SaaS 公司满足，因为单个用户群体太小，但单个用户的痛点又真实存在。

vibe coding 把"造一个只服务你自己的软件"这件事的成本压到了一个咖啡的钱。国产工具里这条路径已经走通了，Trae 用户群里能看到大量这类"我只是想要一个小工具"的案例，从给孩子做的英语单词卡，到给自己卤味店做的进销存。

## 社区在担心什么

不是所有人都买单这个叙事。

最近 r/technology 上一个 2693 赞的帖子标题就很尖锐，《数千个 vibe-coded app 在公网上暴露公司和个人数据》。热门评论里最直接的一条说，软件工程师和 vibe coder 的区别是什么，答案是软件工程师"真的会写安全且高效的代码"。

r/south_africa 有人专门写了技术分析帖，呼吁版主禁止在板块里推广 vibe-coded app，理由是这类 app 的开发者通常根本不知道 SQL 注入、CSRF、密钥管理是什么概念。

r/vibecoding 自己社区里也有清醒的声音，2026 年 5 月 10 日的一个帖子说，vibe-coded app 已经不是 demo 了，它们有真实用户、真实文件、真实支付、真实客户数据，"AI 能帮你造得快，但 AI 不会替你承担你 ship 出去的东西"。

另一面，r/vibecoding 上也有大量正反馈。有用户晒了从 audio plugin 到 illustrator 脚本到完整 SaaS 的一长串自造工具列表，标题就叫《我对 vibe coding 完全上瘾了》。另一个 case 是用 vibe coding 做了一个 iOS 照片清理工具，跑到 100 美元月经常性收入。

这两边都不假。vibe coding 真的让普通人能造软件，也真的让一批不懂安全的人在公网上跑着满是漏洞的服务。

## 我的判断

The Verge 这篇评论赌的是个人软件会重演 1980 年代 PC 革命的剧本。我认为它说对了一半。

说对的那一半是，"软件最大公约数"这件事的合理性正在被瓦解。当造一个只服务 100 个人的 app 比改一个服务 1 亿人的 app 还便宜，那些被主流 SaaS 忽略的长尾需求会被填满。这件事在国产工具圈已经在发生，Trae 和通义灵码上每天都在出新的小工具，绝大多数都不会变成"产品"，但它们解决了具体的人的具体问题。

我不同意的那一半是 Verge 隐含的乐观，"暴政几乎结束"。vibe-coded app 的安全问题是真的，r/technology 那个帖子讲的不是个例。当造软件的门槛被打到地板上，伴随而来的是"造出来不知道自己在干嘛"的人变多。这不是技术问题，是认知问题，AI 不能替你理解你在 ship 什么。

我认为更准确的描述是这样的，vibe coding 解决了"我能不能造"的问题，但没解决"我该不该造"以及"我造的东西安不安全"的问题。后两个问题在可见的未来还是要由人自己承担。

如果你想现在就开始动手试，最低成本的路径是这样的，下载 Trae 或者打开通义灵码，从一个你每天都做、但市面上没有完美工具的小麻烦开始，比如自动整理周报、按你的逻辑归档微信收藏。先造出来，再考虑要不要给别人用。

如果是后一步，把安全这件事请回到桌面上。
