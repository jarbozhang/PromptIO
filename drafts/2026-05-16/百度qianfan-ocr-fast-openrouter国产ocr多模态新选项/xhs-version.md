# 百度 Qianfan-OCR-Fast 上 OpenRouter，国产 OCR 多模态又多一个选项

5 月 16 日，百度的 Qianfan-OCR-Fast 静悄悄出现在 OpenRouter 模型列表里 📝

没有发布会，没有官方推文，模型卡只有短短两行描述，周用量也才 4.27M tokens。但对中文 RAG 和文档解析的人来说，这是个值得记下来的时间点。

## 模型卡上写了什么

Qianfan-OCR-Fast 的 model id 是 `baidu/qianfan-ocr-fast`，上下文 65,536 tokens，输入支持文本和图像，输出文本。定价 $0.68/M 输入 + $2.81/M 输出，按当前汇率折算大致是 4.9 元/M 输入 + 20 元/M 输出。

官方描述只有一句话，「一个专为 OCR 构建的领域专精多模态大模型，在保留多模态通用智能的同时，用 OCR 专门训练数据带来了相对 Qianfan-OCR 的性能升级」。

换成实操语言，百度千帆把云端跑了一段时间的 OCR 专精模型，挂上了 OpenRouter 的统一计费通道。开发者不用单独申请百度智能云账号、不用走鉴权 SDK，一行 OpenAI 兼容的 HTTP 请求就能调起来。

## 国产 OCR 多模态阵营的四条路

把 Qianfan-OCR-Fast 放回国产 OCR 模型的版图里，更容易看清它的位置。

**PaddleOCR**，百度自家的开源 OCR 工具链，本地部署，免费，企业内网友好。复杂场景需要堆 pipeline、调参数，工程量不小。

**GLM-OCR / Qwen-VL Plus**，智谱和阿里通义的视觉语言模型路线。通用多模态附带强 OCR 能力，全能型路线，对图文混排、图表理解都能接。

**OmniOCR**（OmniParser 类），OCR + 文档结构理解的开源项目，强在版面分析，把 PDF 拆成有语义的块，配合 RAG 流水线效果好。

**Qianfan-OCR-Fast**，OCR 专精的多模态大模型。训练语料围绕 OCR，对古籍、合同、票据、手写笔记这类「读不清楚」的场景压力测试更充分。

这四条路不是替代关系。本地大批量处理用 PaddleOCR，需要图文混合推理用 Qwen-VL Plus，需要结构化拆 PDF 用 OmniOCR，需要把模糊扫描件读准用 Qianfan-OCR-Fast。各自擅长不同场景。

## 价格的真实位置

$0.68/M 输入 + $2.81/M 输出 💰

参照系，Qwen-VL Plus 在 OpenRouter 上的定价是 $0.40/M 输入 + $1.20/M 输出。Qianfan-OCR-Fast 比它略贵一些。两者走的方向不一样，一个是通用全能、一个是 OCR 专精，各自在不同场景里有自己的优势区间。

跑一个量化估算。一份 100 页中文合同扫描件，每页大约 800 tokens 文字 + 一张图，总输入估计 200K tokens，输出结构化文本 80K tokens，单次调用成本大约 $0.36（约 2.6 元人民币）。对法律文书数字化、票据批处理这种典型 B 端场景，这个单价能进决策视野。

## OpenRouter 这层中间件的意义

为什么百度把模型挂到 OpenRouter 上值得拿出来说？

国内开发者要调用百度千帆原生 API，走的是百度智能云的鉴权体系，需要 access token 轮换、AK/SK 管理。如果一个项目要同时调通义、智谱、千帆做能力对比，光是 SDK 适配就要写一层适配器。

OpenRouter 把这层差异抹平了。所有模型走 OpenAI 兼容协议，HTTP 请求格式统一，model id 一改就能切换底层 ✨

更微妙的是，OpenRouter 在国内可以直连，不需要任何额外网络配置。

## 实际能用在哪里

按目前模型卡的描述和 OCR 专精模型的常规能力，几个典型场景值得验证 🎯

**中文合同 OCR + 结构化抽取**。甲方乙方、金额、生效日期、违约条款，多模态大模型可以直接 prompt 出结构化 JSON。

**票据批处理**。发票、火车票、餐饮小票这类排版混乱但字段固定的文档，是国产 OCR 模型训练数据相对充足的场景。

**古籍 / 手写笔记**。繁体竖排、行草、墨色模糊，专精模型的训练数据密度通常更高。

**RAG 文档预处理**。65K 上下文意味着单次能塞下一份完整中等长度文档，不用切片。

## 怎么开始测

打开 OpenRouter 文档页 `openrouter.ai/models/baidu/qianfan-ocr-fast`，注册账号，充 5 美元够跑很多次测试。

准备 5-10 张真实业务样本，覆盖最难的场景（最模糊的扫描件、最复杂的表格、最潦草的手写）。同一组样本同时跑 Qwen-VL Plus 和 Qianfan-OCR-Fast，做一次盲评。

判断维度，识别准确率（字符级 + 字段级）、结构保留度（表格行列对齐情况）、单次调用延迟、单页综合成本。两到三小时能跑完一轮，比看任何测评文章都更接近你自己业务的真实表现。

## 收尾的判断

国产 OCR 模型的格局正在从「PaddleOCR 一家独大的开源工具链」变成「开源工具 + 通用多模态 + OCR 专精」的多层供给。每一层有自己最适合的场景。

下次做 RAG 文档预处理选型时，多一个模型可以放进对比矩阵，就是这件事的意义。
