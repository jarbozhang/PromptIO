# OpenAI 企业收入首次超过个人业务：团队采购 AI 该换一套算法了

如果你正在替团队采购 AI，真正该问的已经不是“要买多少聊天账号”，而是“哪些工作能稳定交给 AI，并产出可验收的结果”。

OpenAI 企业收入首次超过个人业务，是一个很强的采购信号。企业付费的重心，正在从聊天订阅转向代码、数据连接和任务执行。

对团队负责人来说，眼下最有用的动作不是追逐更多产品，而是重写采购标准。我会用三个维度做判断，真实使用率、可验证产出、接入成本。

## 决定买账号，还是买执行能力

据来源帖援引的公开信息，OpenAI 年初的收入结构大约是个人业务占 60%，企业业务占 40%。半年多后，两条曲线完成反转，企业业务成为更大的收入来源。

帖中还提到，OpenAI 年化收入运行率达到 400 亿美元，拥有超过 10 亿周活跃用户，并服务超过 200 万家企业。截至 6 月，Codex 占企业客户 Codex 与 ChatGPT 合计输出 Token 的 64%。

这里要区分一个容易误读的数字。年化收入运行率是按近期收入速度折算，并不等于已经确认了一整年的实际收入。相比单个大数字，我更在意 Codex 的 Token 占比，因为它指向了企业使用方式的变化。

员工不只是打开 ChatGPT 问问题了。AI 开始进入代码编写、资料检索、数据处理和工作流执行，离交付物越来越近。

这会直接改变我的采购问题。聊天订阅解决的是“员工能不能用”，执行型产品解决的是“工作能不能完成”。前者看席位，后者要看流程。

## 用真实使用率识别伪需求

第一个判断维度是使用率，但我不会只看登录人数。

企业软件很容易出现一种假繁荣，账号都分下去了，员工偶尔润色邮件、总结文档，月活数据不难看，业务流程却没有变化。这类使用可以提升局部效率，却很难支撑持续扩大的采购预算。

我更关心三个信号。使用是否集中在高频任务，能否连续进入同一条工作流，以及停用之后团队是否会明显变慢。

例如，开发团队每天让 Codex 参与代码修改、测试和审查，比全员每周问几次零散问题更接近稳定需求。客服、运营或数据团队也是同样的逻辑，重复发生的任务比偶发灵感更值得付费。

我的判断很直接。如果一个产品只能靠培训和提醒维持活跃，它还没有进入团队的真实工作面。

## 用可验证产出替代使用时长

第二个维度是产出能不能验收。

聊天产品常用消息量、活跃人数和使用时长证明价值，但 Agent 进入企业后，这些指标不够。模型生成了一万行代码，不等于合并了一项功能。处理了大量文档，也不等于给出了可靠结论。

采购负责人需要把价值落到业务对象上。代码是否通过测试和审查，数据任务是否能复现，知识库回答是否能追溯来源，工作流失败后是否留下记录并允许人工接管。

这也是代码、数据和任务执行更容易进入企业预算的原因。它们能和已有交付标准连接，成功与失败更容易被看见。

我不会用“节省了多少小时”作为唯一依据。这个数字经常依赖估算，也容易忽略复核成本。更稳妥的做法，是比较采用前后的交付周期、返工率、通过率和人工接管次数。

AI 采购不该奖励模型忙碌，而该奖励团队完成工作。

## 把接入成本算进每一次调用

第三个维度是接入成本，这部分最容易在演示阶段被忽略。

一个 Agent 能回答问题，和它能进入公司的代码库、权限系统、数据源及审批流程，是两种完全不同的产品状态。连接器越多，权限边界、数据治理、日志审计和故障处理就越重要。

便宜的单次调用，可能对应昂贵的工程维护。功能丰富的平台，也可能因为接入周期过长，迟迟无法形成可用流程。

所以我会把成本拆成四块，订阅或调用费用、集成投入、复核时间、失败后的恢复成本。采购价只是其中最显眼的一项。

对于高频、标准明确、允许逐步接入的任务，集成投入通常更容易摊薄。对于低频、责任模糊、错误代价高的任务，再强的模型也可能不是当前阶段的好采购。

## 哪些团队适合调整采购方向

已经有稳定数字化流程、任务可以验收、数据权限相对清晰的团队，适合把一部分预算从通用聊天席位转向代码、数据和执行能力。软件研发、内部知识检索、结构化数据处理，以及规则明确的重复工作，通常更容易建立评估闭环。

还在寻找使用场景、主要需求是偶发问答、缺少流程负责人，或者无法定义正确结果的团队，不适合急着扩大 Agent 采购。此时保留少量通用席位做需求发现，往往更合理。

个人订阅也不会因此失去价值。来源帖明确提到，个人业务仍在增长，只是企业端增长更快。通用聊天入口适合探索和个人效率，执行型能力适合进入流程，两者承担的任务不同。

## 我的选择是先改采购表

如果由我做下一轮预算，我不会按部门人数直接增加席位，也不会因为收入结构反转就押注单一厂商。

我会先挑一个每周反复发生、结果可以验收的任务，记录当前交付周期、返工和人工投入，再让候选产品接入这条流程。采购评审只看三件事，是否持续被使用，是否交付了可验证结果，接入与复核成本是否可接受。

只有这三项同时成立，我才会扩大预算。

OpenAI 的收入变化提醒我的，不是企业应该买更多 AI，而是企业终于开始为“完成工作”付费。下一张采购表里，席位数可以保留，但它不该继续排在第一列。
