Claude Code 创始人 Boris Cherny 在 Sequoia AI Ascent 2026 上的访谈，信息量极大，整理一下核心内容。

起点：2024 年底 Boris 加入 Anthropic 内部一个叫 Anthropic Labs 的孵化器，只有几个人，产出了三样东西——Claude Code、MCP、Desktop App。做完团队就解散了，2026 年初由 Instagram 联合创始人 Mike Krieger 牵头重组。Claude Code 现在年化营收超过十亿美元，被 Anthropic 称为"史上从研究预览到十亿美元产品最快的一次"。

但前六个月它几乎没人用。Boris 说当时连他自己也只用它写 10% 的代码，"基本不能用"。他们是故意的——从一开始就知道前六个月不会有 PMF，因为是在为下一代模型提前做产品。真正的爆发点是 2025 年 5 月 Opus 4 发布，之后每一代模型（4.5→4.6→4.7）都让增长曲线再拐一次。这套逻辑和典型 SaaS 的"先验证需求再做产品"完全是反着来的。

选 TypeScript + React 不是因为技术偏好，是因为这两个在模型训练数据里极其常见（on-distribution）。2024 年底模型还不够聪明，语言和框架的选择直接决定模型能写多少。正因为选了模型最熟的栈，他们在 2025 年 10-11 月就过了临界点：模型开始写 100% 的代码。

Boris 2026 年至今没写过一行代码。每天合并几十个 PR，上周单日峰值 150 个——他说"就是想看看能推多远"。他在台上做了现场调查，全场观众大致是"50% 解决"，但对他个人是 100%。他也承认这不普世：还有大型复杂代码库、模型不擅长的小众语言。解决方案？"通常答案就是等下一代模型。"

他的日常工作流：大部分工作在手机上完成。Claude App 里常驻 5-10 个 session，每个 session 开一堆 Agent，加起来几百个在跑。晚上再起几千个做深度任务。最常用的模式叫 Loop——让 Claude 用 cron 起定时任务。他有几十个 Loop 同时跑：一个盯 PR 自动修 CI 和 rebase，一个保持 CI 健康（修 flaky test），一个每 30 分钟从 Twitter 拉用户反馈做聚类。Anthropic 刚发布的 Routines 把 Loop 搬到服务器端，关掉笔记本也照跑。他说"Loop 是未来"。

关于团队变化：Claude Code 团队里工程经理、产品经理、设计师、数据科学家、财务、用户研究员——每个人都在写代码。他认为未来会出现大量跨学科通才，不是"一个工程师同时写 iOS 和服务端"这种，而是一个人同时懂产品、设计和数据科学。

SaaS 终结的判断他借用了 Hamilton Helmer 的七种护城河框架。会被 AI 抹平的两种：切换成本（模型帮你一夜迁完所有工作流）和流程效力（4.7 能 hill-climb 任何目标，你设定方向让它自己迭代就行，"这是第一个能做到这件事的模型"）。不会变的：网络效应、规模经济、独占资源。他预测未来十年颠覆性创业公司的数量是过去十年的 10 倍——因为小公司从白纸开始 AI 原生构建，大公司要改流程、重新培训、面对内部阻力。

产品 vs 模型的归因，他说一年前大概 50/50，六个月前也是 50/50，两年后？"不知道，我们一次只做一周的计划。"但他强调产品永远重要——"不管模型多强，你最终得做出一个用户真的爱用的东西。"同时他也说，随着模型变强，外面那层 harness 会变得没那么重要。一年后 prompt injection 防御、权限模式、human-in-the-loop 这些安全机制可能都不需要了，"因为模型自己就会做对的事"。

Anthropic 内部的状态：整个公司已经没有手写代码，所有 SQL 由模型生成。员工的 Claude 之间通过 Slack 互相沟通——你的 Claude 遇到不确定的问题，会自己去 ping 别人的 Claude 问。Boris 说模型层面内外基本没差距（内部用 Mythos 试一点，Opus 4.7 是 dogfooding 主力），真正的领先在组织流程的改造。"技术大家都能拿到，但把整个公司从手写代码切到模型生成代码，让 Claude 之间互相问问题，这是组织行为的改造，比追技术慢得多。"

关于本地 vs 云端 AI，他说"这件事不重要"。一两年后模型自己会决定用什么来执行任务，不再需要工程师做这个决策。关于知识工作怎么走 Claude Code 这条路，答案是 MCP——同一个连接器 Claude[dot]ai、Cowork、CLI 都能用。没有 MCP 的系统用 Computer Use 兜底，"慢，但 4.7 之后做得很好"。他说模型不在乎是 MCP、CLI 还是 API，"对模型来说都只是 token"。

他给的历史类比是印刷术。1400 年代欧洲大约 10% 的人识字，印刷术之后 50 年出版的文献比之前 1000 年的总和还多，书的成本下降 100 倍。他说软件构建会经历同样的过程，而且会更快。最尖锐的一句：写会计软件最合适的人不是工程师，是真正懂业务的会计师——编程是简单部分，懂领域才是难的部分。

下一个 product overhang 在哪？他点名了 Claude Design，"现在已经挺好用了，未来会好得多。"
