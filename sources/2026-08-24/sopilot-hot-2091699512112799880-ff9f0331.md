## 原帖详情

李博杰 @bojie_li 这里提到把《深入理解 AI Agent》当成 Coding Agent 的「指导书」，这个用法跟我平时的习惯几乎一样。

这本书本身已经写得很细，而且内容更新得很快。DeepSeek Harness、Agent Memory、Multi-Agent 这些最近大家讨论很多的东西，里面都有比较系统的梳理。

不过我现在不会想着从头到尾把它啃完。

平时用 Claude Code、Codex，或者自己搭 Agent 时，哪里没想明白、效果不对，我会直接找到书里对应章节，把链接扔给 Agent，让它先把这一部分真正读懂，再结合当前项目分析问题、给方案。

有时候甚至可以直接告诉它：

「先读这一章，理解这里的设计原则，再回来检查我们现在的 Agent 哪些地方没做好。」

这种感觉挺有意思的。

以前技术书主要是写给人看的，现在一些足够系统、足够高质量的资料，开始可以直接变成 Agent 的外部知识和工程手册。

很多书可能没必要逐页读完，但需要的时候，你得知道该把哪一章交给 Agent。

- **Nash | Second Mind (@Secondmindsys)**：This changes what technical writing is for.

A chapter can now participate directly in engineering work, but the agent still needs to know what authority that chapter carries.

The book may explain a design principle correctly while the current repository, project decision, or newer source establishes a different constraint. Reading the right chapter is only the first step.

The agent should preserve which source informed the work, where the principle applies, what current evidence it was checked against, and what happened when the sources disagreed.

Otherwise a useful guide can quietly become authority over a project it was only meant to inform.
