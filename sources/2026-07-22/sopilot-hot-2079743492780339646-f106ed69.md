硬性要求：

1. 禁止删除任何文件，也不要运行 ocx uninstall。
2. 不得覆盖、重建或破坏我现有的 ~/.codex/config.toml、MCP、插件、模型和登录状态。
3. 修改前分别备份：
   - ~/.codex/config.toml
   - 如果存在，再备份 ~/.opencodex/config.json
   备份名必须带当前时间，权限设为 600。
4. 不要打印、复制或记录 OAuth token、Cookie、邮箱、API Key；不要读取输出 ~/.opencodex/auth.json 的正文。
5. 不要使用 sudo。若 npm 全局目录权限异常，先定位原因。
6. 不要使用 ocx init。它可能先写入只有 xAI 的配置，造成 GPT 请求被 OpenCodex 接管后返回：
   404 No enabled canonical OpenAI provider
7. 必须先同时配置 OpenAI 和 xAI，确认两条路由都存在以后，才能把 OpenCodex 注入 Codex。
8. OpenAI 必须使用 Codex App/CLI 已有登录态的 forward 模式，不要向我要 OpenAI API Key，也不要配置 openai-apikey。
9. 保留当前原生 GPT 模型作为默认模型；Grok 使用 xai/grok-4.5。
10. 不要在最后执行会卸载后台服务的 ocx restart。最后必须用 ocx service 安装、更新并启动常驻服务。

执行顺序：

A. 检查环境：
- macOS 架构
- node -v，要求 Node >= 18
- npm -v
- codex --version
- 当前 Codex 是否已经登录
- 当前 ~/.codex/config.toml 的 model、openai_base_url 和 model_catalog_json
- 当前是否已安装 ocx

B. 安装经过验证的版本：

npm install -g @bitkyc08/opencodex@2.7.30

然后验证：

command -v ocx
ocx --version

C. 如果提示 bundled Bun runtime missing：

先定位：

OCX_PACKAGE_ROOT="$(npm root -g)/@bitkyc08/opencodex"
OCX_BUN_DIR="$OCX_PACKAGE_ROOT/node_modules/bun/bin"

只有同时满足以下条件时，才执行兼容修复：
- 系统是 macOS
- "$OCX_BUN_DIR/bun.exe" 不存在或小于 1MB
- "$OCX_BUN_DIR/bunx.exe" 存在且大于 1MB
- 执行 "$OCX_BUN_DIR/bunx.exe" --version 能正常返回 Bun 版本

满足后：

cp -p "$OCX_BUN_DIR/bunx.exe" "$OCX_BUN_DIR/bun.exe"
chmod 755 "$OCX_BUN_DIR/bun.exe"

然后再次验证 ocx --version。条件不满足时不要盲目复制，先报告实际错误并继续安全诊断。

D. 在注入 Codex 之前配置两个 provider：

ocx provider add openai --force
ocx provider add xai --force
ocx provider set-default openai

随后检查：

ocx provider list
ocx provider show openai
ocx provider show xai

必须确认：

- openai：
  - adapter=openai-responses
  - authMode=forward
  - 使用 Codex 现有登录态
- xai：
  - adapter=openai-chat
  - authMode=oauth
  - defaultModel=grok-4.5

如果此时只有 xai，禁止继续注入。

E. 执行 xAI OAuth：

ocx login xai

打开 xAI 官方登录页面后暂停，让我本人完成浏览器授权；授权成功后自动继续。不得要求我粘贴 token。

F. 同步模型并安装常驻服务：

ocx sync
ocx service

不要在这之后执行 ocx restart。

G. 最终验证：

ocx provider list
ocx account list openai
ocx status
ocx service status
curl --noproxy '*' --max-time 10 -fsS http://127.0.0.1:10100/healthz

必须同时满足：

- Proxy: running
- openai 与 xai 都存在
- OpenAI 账号类型是 codex/main 或同等的 Codex 登录态
- xAI 显示 OAuth 已登录
- Service 已安装且处于 loaded/running 状态
- 不能出现 “installed, not loaded”
- ~/.codex/config.toml 中存在：
  openai_base_url = "http://127.0.0.1:10100/v1"
- 模型目录中同时存在原生 GPT 和 xai/grok-4.5

H. 发起两个最小真实请求：

- 使用配置文件原有的 GPT 模型，只回复 GPT_OK
- 使用 xai/grok-4.5，只回复 GROK_OK

如果 Codex CLI 输出被插件警告干扰，再检查 ~/.opencodex/usage.jsonl 的安全字段，确认：

- GPT 请求 provider=openai、status=200
- Grok 请求 provider=xai、status=200

不得输出 usage 日志中的提示词正文或任何凭证。

I. 完成后告诉我：

- OpenCodex 版本
- 两个 provider 是否正常
- GPT 与 Grok 的真实测试结果
- 后台服务是否 loaded/running
- 配置备份的准确路径
- 如何在同一个 Codex 对话中通过模型选择器切换 GPT 和 Grok
- 如果以后需要回退，只告诉我使用 ocx stop 或 ocx restore；不要现在执行

若模型选择器没有立即刷新，只提醒我完整退出并重开 Codex/ChatGPT App，不要强制结束我的应用。
