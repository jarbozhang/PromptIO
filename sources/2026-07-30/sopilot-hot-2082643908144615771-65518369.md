## 原帖详情

AI 生成 PPT 这事我有发言权，我做过两个还颇受欢迎的 PPT Skill 版本，一个是纯图片的（baoyu-slide-deck skill），一个是 HTML 但是能转原生 PPTX（baoyu-design）。

我的结论是要设计效果好并且方便编辑，一定还要是 HTML + CSS，因为你要自己设计一套中间格式，大概率是 AI 不友好的，那么设计出来的不会多好看，或者说只能组合出有限的风格样式，毕竟 AI 没丰富训练过。但现在 Claude Opus 这样的模型做 HTML 很漂亮。

或者说 HTML 就是最佳中间格式。

如果要转原生 PPTX，那么就需要是有约束的 HTML + CSS，这样就能兼顾美观和原生。

这是我前不久用 baoyu-design skill 做的一个 PPT：
https://t.co/yxvhbb3bGp

基本上是 1:1 还原成 PPTX 没有任何问题。

从美观程度来说 Opus 模型效果最好，比 GPT 5.6 要好，但是 GPT 的画图模型很好，可以配合着用来画图。

比如我这个 Slides 就是用 Claude Code + Opus 4.8 设计，用 baoyu-image-gen Skill 调用 Codex 画图。

至于成本，不是每天大量做，差别不大，重点是效果要好。

推荐试试看：https://t.co/d2EaYV6q7j

## 评论与对话线索

- **fine (@finee405)**：代码生成和图片生成还是有本质区别的，就拿审美来说，光靠对前端代码的理解还不够，还是得靠截图之类的视觉输入让 LLM 去打磨，这就又回到了生图流程上。

代码生成：编辑友好，且可以通过 skills，claude design 等设计流程去提升，但效果有限（毕竟靠的是视觉，目前看 llm 输入/输出在 vision 上的审美是远大于 code 的）。

图片生成：效果佳，但支持编辑需要一套打磨完善的图片处理 pipeline（ocr/sam/inpainting...），把图片转为结构化数据，相对于第一条路线会难很多，很多边界问题要处理。

另外，为啥一定要转 pptx？简单理解就是向下兼容（别跟我讲“不 care pptx 用户”，那路会越走越窄的 🤪）。
针对个人或 AI 友好的环境，迁移到 html 当然可以 0 成本，甚至都不需要 deck 形式。
但 pptx 毕竟是个流行 20 来年的标准格式，对于很多专业人群/公司/平台，要交付的/要上传的/要分享的不都还是 pptx 嘛，而且这部分群体的数量按主观理解应该也是远大于用 html 这波人的。
