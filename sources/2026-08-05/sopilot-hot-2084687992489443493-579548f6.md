## 原帖详情

Cursor 官方今天（2026-08-04）刚发重磅开源：
Mixture-of-Kittens（MoK）这个东西，名字很可爱，但本质上是解决大模型训练中最痛的一个系统瓶颈。

1. 先讲背景：MoE 为什么训练很慢？
现在主流的大模型（DeepSeek、Kimi、Qwen、GLM 等）很多都是 Mixture-of-Experts（混合专家） 架构。
简单理解：

模型不是所有参数都一起干活，而是分成很多个「专家」（比如几百个）。
每个 token 只激活其中几个专家（比如 top-8）。
这样能把模型总参数做得很大（几千亿甚至上万亿），但实际计算量没那么夸张。

问题来了： 训练的时候，这些专家会被分散到不同的 GPU 上（这叫 Expert Parallelism）。 于是就出现了两个必须同时干的活：
通信：把 token 正确路由到对应专家所在的 GPU，算完再传回来。
计算：专家内部做矩阵乘法（GEMM）。

传统做法是「通信一段 → 计算一段 → 再通信」，中间还要不停地同步。 在 NVL72（NVIDIA 最新的大规模机柜，72 张 Blackwell GPU 通过超高速 NVLink 连在一起）这种系统上，通信和同步的开销经常能占到一半甚至更多时间。 MoE 层成了训练的最大瓶颈。

## 评论与对话线索

- **lifcc (@mylifcc)**：2. MoK 干了什么？
Cursor 做了一个叫 Mixture-of-Kittens 的 megakernel（超级大核）。
核心思想一句话： 
把「通信 + 计算」全部焊进同一个 CUDA kernel 里，并且做到完全确定性。
具体可以理解成：
不再分阶段执行，而是让通信和计算深度重叠。

用一个固定大小的环形缓冲区（ring buffer）管理 token，避免 CPU 和 GPU 之间反复同步。
前向和反向都支持，精度覆盖 BF16 和 MXFP8。
整个过程是完全确定性的（同样输入、同样结果），这对做消融实验和强化学习很重要。
他们还给这个 kernel 起了个很 Cursor 风格的名字：Mixture-of-Kittens（小猫混合）。
