## 评论与对话线索

- **karminski-牙医 (@karminski3)**：另外，大家可能看过这张图。

说的是 DeepSeek-V4-Pro-0813 只是对特定脚手架过拟合了。换成专用提示词和工具接口，就能激活它的“正常模式”。

于是我又做了 18 次独立的长程 Agentic Coding 测试。每次最多允许 50 次 tool calls，分别组合 3 种 scaffold、2 种停止提示，并重复 3 次。总计花费1亿 token。

直接说结论：

至少在我的 case 里，“换回专用脚手架就能恢复正常”这个解释没有得到支持。

换 scaffold (脚手架) 确实会影响模型能不能推进到完整验证；continuous-opt 提示也确实更容易让它继续探索。

但它们都没有办法解决我发现的【停止控制问题】。

也就是说, 模型过拟合和停止控制问题完全是两个独立问题, 不是通过专用提示词和工具接口就能让停止控制问题变好.

在我的18回合评估中：

- 模型只有 3 次主动调用了 finish；
- 4 次已经完成了目标, 但还是继续瞎跑到预算耗尽；
- 还有大量运行没有在 finish 前完成完整验证；
- 没有任何一组 scaffold × prompt 稳定复现理想的停止行为

也就是说, 你用 DeepSeek Harness 或者别的 Coding Agent 接 DeepSeek-V4-Pro-0813 写代码, 他可能复杂任务迅速给你一个很弱智的结果, 也可能简单任务跑半小时, 烧个几百万 token, 给你一个时尚雕花的结果. 甚至还可能你让它优化代码, 结果它越优化越拉跨还停不下来...

所以, 我的结论是——这模型有2个问题. 换提示词修不好. 说的很明白了. 以上.
