## 原帖详情

Codex 负责人 Tibo 刚刚表示，他们最近专门调查了一批 GPT-5.6 在 Codex 中「自作主张」的案例。

几周前， @OpenAI   开始调查少数 Codex 的异常报告，发现 GPT-5.6 偶尔会执行超出用户要求的破坏性操作。

最严重的一类事故，居然发生在「清理临时文件」的时候。

Codex 工作过程中会创建临时目录，结束后再自动清理。但在极少数情况下，模型会错误复用 $HOME 这类系统环境变量。

结果就是：

本来想删临时文件夹，格式错误的清理命令却可能直接指向用户真正的 Home 目录。

除此之外，OpenAI 还发现过 Codex 在删除或者覆盖临时路径之前，没有先检查里面到底已经存在什么文件。

现在 OpenAI 已经紧急加了好几层防护。

包括要求 Codex 删除前必须检查目标路径，不允许拿系统环境变量当临时目录；
高风险删除命令会被执行层直接拦截并升级审查；
Full access 变得更难开启，并增加了更明显的风险提示；
Auto-review 也开始专门识别破坏性操作。

更有意思的是，这些真实事故现在还被做成了专门的 Eval、强化学习任务和 scorer，相关破坏性操作也会从训练数据里过滤掉。

OpenAI 最后还专门提醒用户尽量使用 Ask for approval 或 Approve for me 沙盒模式。

Full access 只应该在「你信任，而且出事了能恢复」的环境里使用。

而是 OpenAI 现在已经开始把这些真实线上事故，直接做成 Eval、强化学习任务和 scorer。

也就是说，Codex 现在正在形成一套很有意思的训练闭环：

线上 Agent 闯祸 → 重放事故 → 做成测试 → 做成 RL 训练题 → 下一版模型学会别再这么干。

以前软件出了事故，是工程师修 Bug。

现在 Agent 出了事故，事故本身也会变成训练数据。

某种意义上，Codex 的用户正在免费给下一代 Codex 出题。
