# 小红书来源风险与生成规则改造需求

日期，2026-06-16

## 背景

6 月 15 日的文章生成已经完成了两个结构变化：小红书内容作为默认主稿、每个文章目录只保留一个确认后的 markdown 文件。但新一轮复盘发现，选题和写作规则仍会把 Reddit、Hacker News、OpenRouter 作为可见信息源或替代入口写进文章。这类内容对当前小红书账号有较高审核风险。

本次改造目标不是再生成一份“小红书版”，而是让唯一主稿从选题、写作到保存前都满足小红书发布要求。

## 需求

- R1. Reddit、Hacker News/HN、OpenRouter 不能作为每日选题来源进入生成链路；GitHub 仍可作为公开可验证来源。
- R2. 任何最终发布面，包括 markdown 正文、frontmatter、标题、链接、slug、topics JSON，都不能出现 Reddit、Hacker News/HN、OpenRouter。
- R3. 不再使用“外网/国内/国外/境外”等二分表达来包装文章价值，统一改成“读者/中文读者/公开来源/官方文档/本地运行/可验证入口”等中性表达。
- R4. openclaw 和 Hermes 相关选题需要采用“新版本优先”视角，重点回答新版本解决了什么问题、新增了什么能力、对读者有什么启发、怎么开始使用。
- R5. 写作链路增加去 AI 味终审，删除模板化开头、总结腔、清单堆叠、假装亲测和重复动作描写。
- R6. daily skill 必须同步更新，不能再指导 agent 拉取 Reddit/HN 社区反馈，也不能再把 OpenRouter 写成安全替代入口。
- R7. 维持现有文件契约，每个文章目录只保留一个 `{中文目录名}.md`，不恢复 publish 文件夹、meta.yaml 或 xhs-version.md。

## 约束

- 不删除历史旧文档，只新增 2026-06-16 的规则覆盖当前流程。
- 不把可修复风险交给人工兜底；保存前要有程序化扫描。
- 不引入新的第三方合规服务。
- 不把“敏感源”解释写进最终文章，相关限制只存在于内部 prompt、skill 和代码。

## 验收

- daily 选题 prompt 不泄漏被过滤来源。
- selector 即便返回被过滤来源，也会在 normalize 阶段丢弃。
- single 生成的最终 markdown 在写入前经过发布面扫描，命中敏感源或二分表达时直接失败。
- prompt 与 skill 中不再建议使用 Reddit/HN/OpenRouter，也不再要求产出独立小红书版本。
- 重新生成 2026-06-15 文章后，`drafts/2026-06-15` 下每个目录只有一个 markdown 文件，且目录名为中文可读标题。
