Grounding Context

current failure

当前 2026-06-15 选题已经暴露了规则缺口，topics/2026-06-15.json 选入了 OpenRouter、Reddit r/LocalLLaMA、Hacker News 三类来源，对应草稿正文和 frontmatter 也保留了这些平台名、链接和来源说明。仅靠写作模型“尽量不要提”已经不够，风险必须前移到选题门和保存前扫描。

代码与 prompt 现状

  • scripts/daily.js 的 sourcePriority() 仍给 hacker-news 加分，也没有在 normalizeSelection() 或 prompt 前过滤 Reddit/HN/OpenRouter。
  • config/prompts/scoring.md 仍允许通过 OpenRouter/镜像讲 API 路径；qa-check.md 和 xhs-compliant.md 也把 OpenRouter 列为可替代入口。
  • .claude/skills/daily-content-pipeline/SKILL.md 的 Step 3.5 仍设计为用 last30days 拉 Reddit/HN/GitHub，且会写 community-research.md，这和“只保留一个确认过的 md 文件”以及新的敏感源限制都冲突。
  • config/prompts/wechat.md 已经有 L4 活人感终审，但缺少一个保存前的“去 AI 味终修”步骤，导致模型会用边界说明、套路化分节和“本文为 AI 辅助整理”来显得安全，读感仍偏机器。

平台样本给出的正向信号

data/xhs-note-manager-sample.json 的 55 条样本里，高浏览和高收藏集中在“中文场景 + 明确收益 + 可收藏路线”。例如 17,729 浏览的 Claude Code 交易 bot，5,303 浏览的不联网 AI 听写 App，4,937 浏览的 Gemma 本地跑，1,138 浏览的大模型中文教程路线。相反，“一行 curl 查模型价格”“Dify 论文”“Clawdmeter 桌面小工具”等偏英文工具目录或摘要式标题，浏览明显低。

这说明之前的“英文项目名 + 技术摘要”不是主航道。新规则不只是为了避险，也应该把选题推向“今晚能做什么、怎么避坑、适合谁、版本变化解决什么问题”。

openclaw / Hermes 最新可用事实

已在 2026-06-16 核对 GitHub API 和 README。openclaw 最新 release 为 v2026.6.8-beta.1，发布时间为 2026-06-14T22:45:33Z，重点不是“冲上 Trending”，而是 Telegram/WhatsApp 渠道投递更稳定、Agent/Gateway 恢复更强、消息工具和会话身份等故障被修复。README 还确认它是可运行在自有设备上的个人 AI 助手，支持多渠道、onboard CLI、Windows Hub、local-first gateway 和 security defaults。

Hermes Agent 最新 release 为 v2026.6.5，发布时间为 2026-06-06T00:55:58Z，标题为 The Surface Release。关键变化是原生桌面 App、Web 管理面板、首次设置体验、完整简体中文翻译、远程 gateway 登录等。README 说明它的核心卖点是 learning loop、skills、memory、session search、cron、messaging gateway 和多 backend 运行。写 Hermes 时应优先讲这些版本变化，而不是停留在“会成长的 Agent”口号。

1

建立 Source Eligibility Firewall，把敏感源挡在选题前

把 Reddit、HN、OpenRouter 从“可降权来源”升级为“不可进入发布选题的来源”。GitHub 保留，因为用户明确说 GitHub 可访问，且平台样本也显示 GitHub 中文指南、本地运行、开源教程能带来收藏。

Axis
来源准入
Basis
direct: 当前 topics/2026-06-15.json 已选入 openrouter-new-model-ac0fd8fa.md、reddit-r-localllama-a3573e04.md、hacker-news-algolia-ai-filter-146c08ec.md；scripts/daily.js 仍给 hacker-news 加分。
Rationale
敏感源如果进入 topics，后续标题、frontmatter、链接、正文都会自然泄漏。前置过滤比生成后改写更稳。
Downsides
会减少候选池，尤其是 local LLM 和 HN 工具发现；需要用 GitHub releases、GitHub issues、中文平台补信号。

2

为 openclaw / Hermes 单独建立 Release-first 写作镜头

这两个品牌不应继续写“项目火了、值得关注”这种泛稿。选题命中 openclaw 或 Hermes 时，写作 prompt 应强制补充 release / README / docs 事实，并围绕“解决了什么问题、新增了什么功能、给我们什么启发、今晚怎么试”组织。

Axis
品牌叙事深度
Basis
external: openclaw 最新 v2026.6.8-beta.1 明确有渠道投递与 Agent/Gateway recovery 变化；Hermes v2026.6.5 是 Surface Release，新增桌面 App、Web 管理、中文翻译等。
Rationale
用户点名 openclaw / Hermes 要关注新版本。版本 lens 能把热度稿转成可交付的更新解读，也更符合小红书收藏型结构。
Downsides
需要在生成前多抓一次 GitHub release/README；如果 release 信息太长，需要摘要，否则 prompt 会膨胀。
Confidence
88%
Complexity
Medium

把“国内/外网”改成中性读者语言规则

不要再把读者分成“国内用户”与“外网/国外工具”。在 skill 和 prompt 里改成“中文读者、读者、小团队、开发者、本地部署、官方文档、公开来源、可验证入口”。这不是文字洁癖，而是降低平台审核联想。

Axis
文本风险面
Basis
direct: 当前 skill 和 prompt 多处出现“国内可访问入口”“国外工具”“国内无法直接访问”“国内用户”等表达；用户明确要求不要区分外网/国内。
Rationale
正常中文科技文章不需要解释访问边界。中性语言既能保留行动价值，又不会主动触发敏感语义。
Downsides
需要重写一批既有规则，避免把“可操作”误写成“可访问”。
Confidence
91%
Complexity
Low
4

增加保存前 Humanizer 终修，而不是只靠 QA 打分

现在 L4 会判断“像不像同一个 AI 套出来”，但没有一个稳定的“保存前改写动作”。建议在写作后、frontmatter 写入前增加终修 pass，专门删除模板化边界说明、机械分节、泛泛“适合谁/坑点/今晚能做什么”小标题堆叠，并把必要免责声明融入自然句。

Axis
读感与平台表现
Basis
direct: 今日 openclaw/Hermes 草稿有明显“先把边界说清楚”“适合谁先看”“最小试用清单”“今晚能做什么”等重复骨架；QA 规则已承认具体技法清单会反向制造 AI 味。
Rationale
去 AI 味不能只列禁用词，否则模型会换一组套话。终修应该以整篇节奏和姿态为单位，删掉解释腔，把文章改成自然分享。
Downsides
会增加一次 LLM 调用；如果没有约束，可能删掉事实边界。因此需要“只删/替换，不扩写事实”的约束。
Confidence
82%
Complexity
Medium

把社区反馈改成 GitHub-first 和中文平台信号

last30days 原本用 Reddit/HN/GitHub 补“社区声音”，但现在 Reddit/HN 要移出发布素材链。替代方案不是放弃真实反馈，而是用 GitHub releases、issues、PR、discussions、README、官方 docs，以及已有中文平台样本做反馈来源。

Axis
来源准入
Basis
direct: .claude/skills/daily-content-pipeline/SKILL.md Step 3.5 明确调用 --search reddit,hn,github 并保存 Reddit thread、HN story；用户明确 GitHub 可访问但 Reddit/HN 不应进入规则。
Rationale
GitHub 足够支撑开源项目的版本事实、问题反馈和使用边界。中文平台数据可以支撑标题与结构，不需要把不可访问社区搬进正文。
Downsides
缺少 Reddit/HN 后，部分“开发者口碑”会变少；需要更依赖 release note 和 issues 的信息密度。

加发布面扫描和回归测试，防止敏感词从 frontmatter 泄漏

风险不只在正文。今天 OpenRouter/Reddit/HN 同时出现在 title、source_file、source_url、tags、reach_note 和相关链接里。保存前扫描必须覆盖完整 md 文件，包括 frontmatter。

Axis
文本风险面
Basis
direct: 当前草稿 markdown frontmatter 保留 source_url 和 source_title，而同步到 Obsidian/发布平台时仍可能被读取或复制。
Rationale
只扫正文会漏掉最容易被忽略的来源字段。测试用例可以固定防止未来 prompt 或 fetcher 改动回退。
Downsides
需要区分内部调试文件和最终文章文件；内部 ideation 文档可保留这些词，发布草稿不可保留。

84%

Rejection Summary

#IdeaReason Rejected
1只提示 LLM 不要提 Reddit/HN/OpenRouter太晚也太弱，当前草稿已经证明来源会泄漏到 frontmatter、标题和链接。
2保留 OpenRouter，但换成“统一模型路由服务”本质仍是敏感源规避写法，且容易变成不透明表述。
3把所有英文平台名都加入禁用词过宽，会误伤 GitHub、OpenAI、Google、Ollama 等可讲的品牌。
4每个来源都人工确认违背每日管线自动化目标；应该用规则自动判定，再把边缘样本报出。
5所有 openclaw/Hermes 都写安装教程用户要的是新版本解决了什么和启发，不是每次都硬写安装教程；没有实测时教程化会编造。
6继续用“国内可访问入口”作为安全壳用户已明确不要区分外网/国内，这个安全壳本身会触发不必要联想。

Recommended Sequence

implementation order
  1. 先更新 scoring.md、daily-content-pipeline/SKILL.md 和 daily.js，让 Reddit/HN/OpenRouter 不再进入 topics。
  2. 再更新 wechat.md、xhs-compliant.md、qa-check.md，移除 OpenRouter 替代入口和“国内/外网”表达。
  3. 为 openclaw/Hermes 增加 release-first 生成规则，生成前抓 GitHub release/README 摘要。
  4. 增加 humanizer 终修和发布面扫描测试。
  5. 最后删除今天已生成目录，按新规则重新生成，预期会去掉 OpenRouter、Reddit、HN 这 3 篇，补入 GitHub/中文平台安全选题。
